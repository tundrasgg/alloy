## Who and why

A cloud admin who ran `alloy init` and wants to see the cluster at a glance:
which nodes are healthy, how they reach each other, what runs where, and what is
still fragile. A user inside an organization who wants to create, watch, and
remove instances and VPCs without memorizing flags, and to keep their hands on
the keyboard. Both expect the console to do what the CLI does, in the same
words, and to show them the command when they want to script it.

## Behavior

**Reaching the console**

- The console is static files built into `alloyd` and served by every control
  node at its API address (ARFC 0019 section 2). The browser talks only to the
  public API (ARFC 0019 clause 3.2.2), in the browser wire form requested below.
- A cluster with a public name has an ACME certificate (ARFC 0008 clause 3.8).
  The console is then at `https://api.<cluster-domain>/` and works from any
  browser. The login screen takes a login code.
- A cluster without a public name presents a certificate from its own API CA,
  which no browser trusts. The console never asks the user to click through a
  certificate warning. Instead, `alloy console` runs the **console bridge**: it
  listens on `127.0.0.1` on a free port, connects to the API with the context's
  pinned certificate authority (ARFC 0019 section 8), forwards the browser's
  requests, and opens the default browser. A request whose `Host` header is not
  the bridge's own address is refused. Forwarded requests carry the browser
  session only, never the context's access key.
- `alloy console` signs the browser in. It obtains a session token for the
  context's user, derived from the context's access key (ARFC 0007 section 2.3),
  and opens the browser at a launch path that works once, only on this bridge,
  sets up the browser session, and redirects to the landing screen. The address
  printed on standard output is the bridge's plain address. Stopping the bridge
  revokes the session token.
- `alloy console <link>` opens a link that another member copied, through this
  computer's bridge. `alloy console --no-browser` prints the address and opens
  nothing.
- The console is served by the release of the node that serves it. When it
  finds the API on a release it was not built for, it says so (see Errors).

**Layout**

- One window: a top bar, a left navigation column, and the screen. Nothing else.
- Top bar: the organization and project (a switcher, `p` to open), the palette
  field showing `Ctrl+K`, the stale marker when the data is stale, and the user
  menu (issue a login code, theme, shortcuts, log out).
- Navigation: `Overview`, `Nodes`, `Mesh` under **Cluster**, shown only to a
  cloud admin. `Instances`, `VPCs` under **Project**. `Operations` last. Each
  entry shows its count and, when a standing warning concerns it, a yellow or
  red word, never color alone (T10, C13).
- At 1280 by 800 pixels a list shows at least 20 rows of at most 36 pixels
  (C6). The navigation column collapses with `[` to give a list more width.

**Screens, in build priority**

The first four are the screens the M11 rungs make real. Every action is one
CLI command (principle 7). Commands marked *provisional* follow the CLI nouns
of ARFC 0019 clause 3.1.1 but are not yet specified; the console takes whatever
ARFC 0019 fixes for them.

1. **Nodes** (`/nodes`, cloud admin). Rung 2.
   - List: the columns of `alloy node list` in its order (ARFC 0019 clause
     3.1.15): `NAME`, `STATE`, `ROLES`, `ZONE` when there is more than one zone,
     `MESH`, `RELEASE`, `ADDRESS`. `unreachable` red, `pending` yellow, both
     with the word. Standing warnings that concern nodes sit under the table,
     each with its command.
   - Detail (`/nodes/<name>`): the fields of `alloy node get` in its order:
     name and state first, then the `Node` fields of ARFC 0006 section 2.6, then
     the node's standing warnings and its paths (from Mesh).
   - Actions: `Approve node` (`alloy node approve <name>`), `Reject node`
     (`alloy node reject <name>`), `Update node` with roles and advertise
     addresses (`alloy node update <name> --roles ... --advertise ...`),
     `Create join token` (`alloy token create`), which shows the join command
     once in a dialog with a copy button, and the token list and `Revoke join
     token` (`alloy token list`, `alloy token revoke <id>`). `alloy node leave`
     runs on the node itself, so the detail screen shows it as a command to
     copy, not a button.
2. **Instances** (`/orgs/<org>/projects/<project>/instances`). Rung 4.
   - List: `NAME`, `STATE`, `SHAPE`, `IMAGE`, `VPC`, `ADDRESS` (primary IPv4),
     and `NODE` for a cloud admin only. States are the guest states of ARFC 0011
     section 2; `failed` is red, `pending`, `starting`, `stopping`, and
     `migrating` are plain words with a progress mark.
   - Detail: name, state, uid, shape, image, node (cloud admin), VPC, subnet,
     each ENI with its MAC, IPv4, and IPv6 addresses, volumes, key pair, labels,
     create time. Tabs: `Overview`, `Network`, `Serial output`, `Operations`.
   - Actions (provisional): `Create instance` (`alloy instance create`), `Start
     instance`, `Stop instance`, `Restart instance`, `Resize instance` (while
     stopped), `Delete instance`, `Update labels`. The create form opened and
     submitted unchanged creates a running instance in the default VPC (C8, ARFC
     0019 clause 3.1.3).
3. **VPCs** (`/orgs/<org>/projects/<project>/vpcs`). Rung 5.
   - List: `NAME`, `IPV4 RANGE`, `IPV6 RANGE`, `SUBNETS`, `INSTANCES`, `MTU`.
   - Detail tabs: `Subnets`, `Security groups`, `Instances` (each ENI in the
     VPC with its instance and addresses).
   - Actions (provisional): `Create VPC`, `Update VPC`, `Delete VPC`, `Create
     subnet`, `Delete subnet`, `Create security group`, `Update security group`
     (its rules), `Delete security group`, each `alloy <noun> <verb>`.
4. **Mesh** (`/mesh`, cloud admin). Rungs 3 and 6.
   - List, one row per open session between two nodes: `FROM`, `TO`, `PATH`
     (`direct` or `relayed`), `VIA` (the relaying anchor, else `-`), `RTT`,
     `SINCE`. Lazy sessions (ARFC 0004 section 3.8) mean a pair with no traffic
     has no row; the screen says so above the table.
   - Under it, each `relay-only` node with its relay's measured throughput (ARFC
     0004 section 3.7).
   - No mutating actions. CLI equivalent (provisional): `alloy mesh path list`.
   - Until the API reports paths (Requested design changes), the screen shows
     only the `MESH` column of nodes, and Nodes covers rung 3.
5. **Overview** (`/overview`, cloud admin, their landing screen). Every standing
   warning (ARFC 0019 clause 3.2.5), then counts of nodes, instances, and VPCs
   by state. Each warning shows its command with `Copy` and, when the command is
   an API call the user may make, `Run`, which opens that action's dialog.
6. **Operations** (`/operations`, `/operations/<name>`). Every operation the
   user may see, newest first, with its stages as the CLI prints them (T17,
   C12). CLI equivalent (provisional): `alloy operation list`, `get`, `wait`.
7. **Login** (`/login`) and **Settings** (`/settings`: theme, single-character
   shortcuts on or off, issue a login code, log out).

A user who is not a cloud admin lands on Instances in their default project.

**Command palette**

- Opens with `Ctrl+K`, or `Cmd+K` on macOS, from every screen (C2). It takes
  the first keystroke within 100 ms with no network request.
- Entries, in this order, filtered by what is typed:
  1. Actions of the current screen and its focused row: `Create instance`,
     `Stop instance web-1`, `Approve node linux-3`.
  2. Go to: `Go to overview`, `Go to nodes`, `Go to mesh`, `Go to instances`,
     `Go to VPCs`, `Go to operations`, `Go to settings`.
  3. Resources in the current project, and nodes for a cloud admin, by name,
     from the lists already loaded and kept current by Watch.
  4. `Switch project`, `Switch theme`, `Show shortcuts`, `Copy link`, `Copy
     CLI command`, `Issue login code`, `Log out`.
- Each action entry shows its shortcut, if any, and its CLI command (C3).
- Enter runs the entry. An action with inputs opens its dialog; one without
  inputs runs at once unless it is destructive, which asks for the name (C18).

**URLs**

The path is the resource's full name (rule A2), so a link and a name are the
same thing. Filters, order, and tab are query parameters (C5).

| Screen | Path |
|---|---|
| Overview | `/overview` |
| Nodes, a node | `/nodes`, `/nodes/<name>` |
| Join tokens | `/join-tokens` |
| Mesh | `/mesh` |
| Instances, an instance | `/orgs/<org>/projects/<project>/instances`, `.../instances/<name>` |
| VPCs, a VPC, a subnet | `.../vpcs`, `.../vpcs/<name>`, `.../vpcs/<name>/subnets/<name>` |
| Operations, an operation | `/operations`, `/operations/<name>` |
| Login, Settings | `/login`, `/settings` |
| Query | `?filter=<A9 expression>&order_by=<field>&tab=<name>` |

`Copy link` copies the address the API is reached at directly (for example
`https://192.168.1.20/orgs/default/projects/default/instances/web-1`), not the
bridge's, so the link works for another member, through their own `alloy
console <link>` when the cluster has no public name.

**Live updates**

- Each visible list and detail screen keeps one `Watch` open. Rows change in
  place. A new row appears and a deleted row leaves with motion of at most 150
  ms, none with reduced motion (C16). No refresh button (C10).
- A change the user makes shows `pending` beside the field until the Watch
  delivers the resource with the new generation (C12). A change that returns an
  operation shows its stages in place until it is done.
- When a Watch stops, the console reconnects with backoff from 1 to 30 seconds
  and resumes from the last version it saw. While it is down, the top bar shows
  `Stale, 42 s` in yellow, and the affected screens keep their data under the
  same marker (ARFC 0019 section 6). If the API says the version is too old
  (`Compacted`), the console lists again and replaces the screen's data.
- Standing warnings and the user's own running operations are watched on every
  screen, so the navigation counts and the warning words stay current.

**Empty states**

An empty list shows no table header and one line in the list's place, then the
create action and its command (C19, T21):

```
No instances in project default.
[Create instance  c]    alloy instance create                       [Copy]
```

`No VPCs in project default.` follows the same form. Nodes is never empty. The
Mesh screen with no open session says `No open sessions. Nodes open a session
when they have traffic for each other.`, with no action. A filter that matches
nothing says `No instances match labels.app = "web".` with `Clear filter`.

**Themes and type**

- A light and a dark theme, following the operating system by default and set
  in Settings as `system`, `light`, or `dark` (C14). Neutral grays, one accent
  for focus, selection, links, and the primary action (C13).
- System interface font for text, system monospace font for names, addresses,
  commands, and keys. No font file is downloaded. Four text sizes, two weights,
  tabular figures in tables (C15).

## Errors

Each error appears beside the field or action it concerns and stays until fixed
or dismissed (C17). The message is the API's (rule A11). The next step is a
button when it is an action in the console, else a command with `Copy`.

| Situation | Message | Next step shown |
|---|---|---|
| Invalid fields in a form | Each field's rule, under the field, all at once (rule A12) | Focus moves to the first invalid field |
| Edited resource changed meanwhile (`Conflict`, stale generation) | `web-1 changed since you opened this form.` | `Reload and keep my edits`, which shows the new values beside the user's |
| Name taken (`Conflict`) | `An instance named web-1 already exists in project default.` | The name field, focused, with a free generated name offered |
| Not allowed (`PermissionDenied`) | The API's message naming the action | The action stays visible and disabled, with the message on hover and focus |
| A URL names something absent, or in another organization (`NotFound`) | `No instance web-9 in project default.` Same text for both cases (rule A13) | `Go to instances` |
| Quota (`QuotaExceeded`) | The API's message with the limit and the usage | The command that shows the quota, from `next_step` |
| Rate limited (`RateLimited`) | None while retrying with the same idempotency key. After 30 seconds: `The API is limiting requests from admin. Retrying.` | None needed |
| No control plane quorum (`Unavailable`) | `The control plane has no quorum. Changes are refused until it does; lists show the last data read.` | `Go to nodes` for a cloud admin |
| Connection lost | Top bar: `Stale, 42 s. Reconnecting.` Data stays, marked stale | None needed. Changes are refused while stale, with the same words |
| Session expired or revoked (`Unauthenticated`) | `Your session ended. Log in again to continue.` Unsent form input is kept | `Log in` (public name) or `alloy console` (bridge) |
| Login code used, expired, or wrong | As PB-0001: `This login code was already used.` and the others | `alloy login --issue-code` with `Copy` |
| Bridge: API certificate differs from the pinned one | In the terminal, as PB-0001's certificate mismatch. The browser is not opened | No command (PB-0001) |
| Bridge stopped while the console is open | `The console bridge stopped. Run alloy console again.` | `alloy console` with `Copy` |
| Console and API releases differ | `This console is release 0.0.1-preview.2 and the API answered as 0.0.2. Reload to get the matching console.` | `Reload` |
| Unexpected failure (`Internal`) | The API's message and its request id | `Copy request id` |
| Browser unsupported | `The Alloy Console needs a current or previous major release of Chromium, Firefox, or Safari.` | None |

## Requested design changes

ARFC 0008 (browser wire form):

- Section 2 and clause 3.10: name the form browsers call. The console needs
  every unary method and `Watch` as server streaming. Product preference: the
  Connect protocol (R-0007 option A), because one form then serves the browser,
  `curl` with JSON (rule A20), and GET for reads. If the server side keeps
  `tonic` with gRPC-Web (R-0007 option B), a separate JSON form must still be
  specified for rule A20. The TypeScript client is protobuf-es with Connect-ES
  in either case (R-0007), so it is generated (rule A17).
- Clause 3.12: browser requests travel over HTTP/2 (ALPN `h2`, as clause 3.8
  already offers), so the console's several Watches do not exhaust a browser's
  per-origin HTTP/1.1 connection limit. Paths the API serves stay disjoint from
  the console's paths (URLs above).
- `Watch` has no clause. Specify: the first message carries the current state
  or a version to list from, later messages carry each change and each deletion
  with the resource's version, a client resumes from a version, `Compacted`
  means list again, and the server sends a keepalive at a fixed interval so a
  client can tell a quiet stream from a dead one and mark data stale.
- Clause 3.13: add `WatchNodes`. Every kind a screen lists needs `Watch`.
- Add a method that returns the caller: principal, organization, cluster roles,
  default project, session token expiry. The console needs it to choose the
  navigation, and ARFC 0019 clause 3.1.11 already needs it to print the
  principal.
- Add `ListStandingWarnings` and its `Watch` (ARFC 0019 clause 3.2.5 says the
  API reports them, but names no method): kind, affected resource, message, and
  next step (rule A11).
- Clause 3.3: operations need `ListOperations`, `GetOperation`, and Watch, with
  the stage fields of rule A16 (already raised by T-0087).

ARFC 0008 clause 3.7 and ARFC 0007 section 2.3 (browser authentication):

- Add a method that turns a login code into a session token without creating an
  access key, for the login screen, and accept the same method authenticated by
  an access key, so `alloy console` can make a session token derived from it.
  Password and identity provider login join it later (ARFC 0007 section 2.2).
- Add refresh and revoke of a session token, so `Log out` and a stopped bridge
  end the session at the server.
- Where the browser keeps the token. Product need: it survives a reload and a
  second tab, page script cannot read it, and another site cannot use it.
  Recommended: the API also accepts the session token as an `HttpOnly`,
  `Secure`, `SameSite=Strict` cookie on the browser form, only together with a
  request header a cross-site form cannot send. Clause 3.7.1 today accepts only
  `authorization: Bearer`. Needs an ARFC 0020 check. Whether browsers keep a
  `Secure` cookie on the bridge's `http://127.0.0.1` origin is unverified; if
  not, the bridge keeps the token and the browser holds only an opaque cookie
  the bridge maps to it.
- The API sends no CORS headers: the console is same-origin, and nothing else
  in a browser should call the API with a user's session.

ARFC 0019 (serving and pinning):

- Section 2: control nodes serve the console's files at the API address, with a
  strict content security policy (no inline script, `frame-ancestors 'none'`),
  and each node serves its own release's console.
- Clause 3.1.2: add the top-level command `alloy console [<link>]
  [--no-browser] [--context <name>]`, which runs the console bridge described in
  Behavior. The bridge reuses section 8's pin, so a private cluster needs no
  change to any trust store and no certificate warning.
  Alternative, not recommended as the default: the user installs the API CA in
  the browser. That trusts a cluster key for every name the browser visits,
  unless the API CA carries name constraints and browsers enforce them on
  user-installed roots, which is unverified.
- Clause 3.2.3: the console shows each action's CLI command with no request. The
  mapping from API method and fields to CLI command and flags comes from the
  same definitions as the CLI (clause 3.1.10) and ships with the console.
- Section 3.1 has commands only for `node`, `token`, and `login`. The console's
  Instances, VPCs, Mesh, and Operations actions are provisional until it has
  `instance`, `vpc`, `subnet`, `security-group`, `mesh path`, and `operation`
  commands.
- Section 3.2: carry C1 to C19 and this brief's keyboard map, URLs, and live
  update rules into the console's clauses.

ARFC 0004 and ARFC 0006 (mesh view):

- No API reports paths between nodes. Rung 3's check and the Mesh screen need,
  per open session: the two nodes, `direct` or `relayed`, the relaying anchor,
  the round trip time, and since when. Each node reports only its open sessions,
  so the data grows with sessions, not with node pairs (I-21).
- ARFC 0004 section 3.7 requires the CLI and console to show a relay-only
  node's measured relay throughput, but the `Node` of ARFC 0006 section 2.6 has
  no field for it.

ARFC 0011:

- Clause 3.1.5 offers the serial console as a stream. A browser cannot stream
  to the server (R-0007), so input needs a unary method, and output needs the
  kept 1 MiB on open. The name "serial console" also collides with "console";
  this brief says "serial output".

## Principles check

1. One command to start: `alloy console` opens a signed-in console on any
   cluster, private or public. Every empty state names its create action.
2. Defaults produce something that works: every create form submits as filled
   in and gives a working resource (C8).
3. It works on one machine: the console is in `alloyd`, the bridge is in
   `alloy`, and nothing needs a public name, a trusted certificate, or an
   external service.
4. Say what is true: standing warnings show on Overview, beside the resource,
   and as words in the navigation. Stale data is marked with its age. A private
   cluster is never reached through a certificate warning.
5. Errors lead somewhere: every row in Errors has a next step, except the
   certificate mismatch, as in PB-0001.
6. One name per thing: CLI nouns and verbs, glossary words, and full names as
   URLs. New terms: console bridge, command palette, operation, serial output
   (see the report's issues). "Session" means the AL session in the glossary;
   this brief says "session token" or "browser session".
7. Same abilities everywhere: every console action is a CLI command shown
   beside it. `alloy node leave` and `alloy console` run only on a computer,
   by their nature. Theme and shortcuts are presentation, not abilities.
8. Compatibility is exact: not affected. The console calls only the native API.
9. Tenants are strangers: a URL to another organization's resource gets the
   same `NotFound` screen as a missing one. Node names show only to cloud admins.
10. Fast enough to feel local: screens render from loaded data in under 100 ms,
    the palette filters with no request, and every slow action shows its stages.
11. Beautiful because it is useful: tables, not cards; no illustration; color
    only on states, always beside a word.
- C2 and C4 conflict: Chromium and Firefox bind `Ctrl+K` to their search field,
  and C4 forbids replacing a browser shortcut. This brief follows C2, the more
  specific rule. The palette also opens from the top bar field, and browser
  back and forward work as usual, so no browser shortcut is lost for navigation.

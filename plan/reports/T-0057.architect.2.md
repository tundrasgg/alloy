## Summary

Resolved the six findings of `plan/reports/T-0057.reviewer.1.md` in ARFC 0001.
Finalizing the upgrade to release `R` now has a check that writes nothing, a switch (one write per consensus group that records `R` as finalized and sets per implementation write versions to `V(R)`, after which release `R - 1` is refused), and a conditional rewrite. Groups refuse binding writes at any version other than the write version.
`alloy-seam` gains a type erased configuration codec (`ConfigCodec`, `register_config`, `config`, `configs`, clause 3.19), registered on every supported host, and `SeamConfig` requires `PartialEq`. The control plane uses these for the rewrite and for binding identity.
ADR 0056 is updated to match. This is still a behavior change and needs one review before merge.

## Changes

- `spec/arfc-0001-runtime-seams.md`:
  - Section 2.1: `SeamConfig: Sized + PartialEq`; new `ConfigCodec` trait; `RegistryBuilder::register_config`; `Registry::config` and `Registry::configs`. The `Binding` doc states that its `==` is byte equality, not binding identity.
  - Clause 3.13: stored binding rules rewritten (write versions, check, switch, rewrite, completion, who runs it, binding identity, ordering, bound). There is also a new rule for creating a cluster and a new rule that `VERSION` never decreases.
  - New clause 3.19: configuration type registration and codec behavior, and the rule that every host registers every configuration type.
  - Section 5: suite scope is now 3.10 to 3.19, and the section names where the stored binding rules and the cross host rule are checked.
  - Section 6: failure behavior for refused writes, a failed check, and a failed rewrite.
  - Section 7: limit row for configuration types.
- `adr/0056-finalizing-an-upgrade-rewrites-stored-seam-bindings.md`: decision, consequences, and alternatives updated.
- `adr/README.md`: unchanged (title unchanged, entry already present).

Findings sent:

- F1 (fix), resolved. Finalization starts at the switch and completes when the rewrite is done. From the switch on, no node runs release `R - 1`: rollback, binary fallback, and `alloyd` of `R - 1` are refused, so no release that cannot decode `V(R)` runs. Write versions change only at the switch, so the writing rule and the rewriting rule name the same point. The Bound bullet lists the releases and stored versions for each span. The reviewer offered two options. I took the first: refuse `R - 1` from the start of finalization. The second ("nothing at `V(R + 1)` until completion") is rejected in ADR 0056, because the rewrite itself writes the new version. The new check step keeps rollback possible when a binding cannot be decoded, because nothing is written before the switch.
- F2 (fix), resolved. Each rewrite write names the resource `generation` it read (ARFC 0006 clause 3.5). On `Conflict` it rereads and replaces the binding only if it is still not at `V(R)`. Groups apply a binding write, in log order, only at the write version and otherwise fail it with `UnsupportedVersion`, so after the switch nothing is stored at `V(R - 1)`.
- F3 (fix), resolved. `Registry::config(kind, name)` returns a `ConfigCodec` with `version`, `min_version`, `reencode`, and `same`. `SeamConfig: PartialEq` provides configuration equality. The `Binding` doc and clause 3.13 state that `Binding ==` is byte equality, and that binding identity is `ConfigCodec::same`.
- F4 (fix), resolved. A cluster created at release `R` is created with the finalization of `R` complete: write versions at `V(R)`, and `R` recorded as finalized.
- F5 (note), applied. `V(R)` is at least `V(R - 1)`.
- F6 (note), applied. The check and the rewrite run in `alloyd` of release `R` on a control node, as a controller of each group. Clause 3.19 requires every host to register the configuration type of every implementation that any host of that release registers, even where clause 3.2 excludes the factory.

## Decisions

- N: the `alloy-seam` public interface grows (`ConfigCodec`, `RegistryBuilder::register_config`, `Registry::config`, `Registry::configs`), and `SeamConfig` gains a `PartialEq` supertrait. T-0007, which is defining that crate, must include them.
- N: per group write versions in control plane state, applied in log order, rather than an API layer check. That makes the switch atomic for each group with respect to writes. The storage format of the write versions is left to the control plane ARFC.
- R: `register_config` reuses the existing `RegistryError` variants. Configuration types have their own 1,024 limit.
- R: the refused write error is `UnsupportedVersion` with `min` and `max` set to the write version, so no new error type is needed.

## Issues

- `follow-up`: T-0007 (alloy-seam interface crate, active) predates this change. It must add `ConfigCodec`, `register_config`, `config`, `configs`, and the `PartialEq` bound on `SeamConfig` (ARFC 0001 section 2.1 and clause 3.19). The seam conformance suite needs clause 3.19 cases.
- `spec-issue`: `spec/arfc-0017-upgrades-and-versioning.md` clauses 3.3 and 3.7 and sections 6 and 8 say rollback and binary fallback are possible "until finalization". ARFC 0001 clause 3.13 now ends them at the switch, which records the finalized release. ARFC 0017 should define the switch and completion, refuse the upgrade to `R + 1` until completion, and include the check and rewrite in `--finalize` (this restates the round 1 spec-issue, extended).
- `spec-issue`: `spec/arfc-0006-control-plane.md` does not hold the per group write versions or the finalized release record that ARFC 0001 clause 3.13 places in each group. It should define their storage and the in-log-order refusal of binding writes.
- `follow-up`: the cross host rule of clause 3.19 (same `configs` on x86_64 and aarch64 `alloyd` builds) needs a check once `alloyd` exists, for example a step in `cargo xtask ci`.
- `follow-up`: carried from round 1. ARFC 0017 clause 3.10 names no conformance suite for the upgrade scenarios, and restoring a state backup (ARFC 0006 clause 3.10) taken before a switch is unspecified.

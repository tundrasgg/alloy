## Summary

Added a `Later rounds` section to `agent/protocol/messages.md`. A role dispatched
with `round` greater than 1 continues on `task/T-NNNN` (checking it out if its
workspace came from main, then merging main), and reads every report for the task
before changing anything. The lead commits reviewer reports to main and frees the
branch before dispatching. The dispatch format is unchanged.

## Decisions

- The read set is every `plan/reports/T-NNNN.*.md`, not only reports with a lower round number: rounds count per role, so a reviewer in round 2 needs the developer's round 2 report, whose number is not lower.
- The lead removes the earlier round's workspace before dispatching a later round: git refuses to check out a branch held by another worktree, and `git worktree list` shows `task/T-0021` and `task/T-0026` still held by earlier workspaces.
- A later-round report states per finding id, in `Changes`, how each `block` and `fix` finding was resolved, so the re-review can check them without a new template section.
- A reviewer in a later round never commits to `task/T-NNNN`; it creates `review/T-NNNN.<round>` from main, matching `agent/eng/git.md`.

## Issues

- `process-issue`: `agent/protocol/tasks.md` step 3 dispatches the architect to rule on a `test-issue` for a build task, but no rule says which branch a different role starts from in round 1 of a task whose `task/T-NNNN` already belongs to another role.
- `follow-up`: `.claude/harness.md` could bind the "remove the earlier workspace" step to the harness's worktree cleanup, since Claude Code keeps worktrees that hold commits.

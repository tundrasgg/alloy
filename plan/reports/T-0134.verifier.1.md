## Summary

`task/T-0134` is `task/T-0113` with main merged in, plus the rung 2 profile of ARFC 0002 section 3.15 in `tests/e2e/rung2.ps1`. After `init`, root on the control node issues one login code per other machine with `alloy login --issue-code` through the local admin socket while it has no context. Then each machine, the control node included, runs `alloy login <code>` once, and `node list` on each machine must show all three nodes `active` (healthy). The refused-`leave` checks are gone, since section 3.9 is not built: every machine is uninstalled with `--purge --yes --force`, and its snapshot must equal the pre-install one. Every T-0113 check that the profile still asks for is kept, the joined-node snapshot rule of clause 3.17.6 included.
An uninstall keeps root's CLI configuration (clause 3.16), so the preflight requires it absent on every Linux node, and after the uninstall the driver removes the copy that the run made.
Not run on real machines. Local checks: both shells parse every script, 18 fixed-input cases of the new functions pass, the shell scripts behave as documented, the usage errors exit 2, and a dry run stops at preflight.

## Decisions

- N: the preflight needs no CLI configuration for root on each Linux node, and the driver removes what the run made after the uninstall. With a current context, `--issue-code` goes to the API and is denied (ARFC 0019 clause 3.1.14), so a leftover context would break every rerun.
- R: the Windows client's CLI configuration is neither checked nor removed. ARFC 0019 clause 3.1.9 does not name its path, and a stale context there is replaced at login: its `replaces` is ignored by ARFC 0007 clause 3.9.10.
- R: so the no-socket `--issue-code` check (exit 4) runs only on joined Linux nodes, where the driver knows that root has no context.
- R: the client's code is issued with `--user admin --org default` and the second node's with the defaults, which covers both forms of clause 3.1.14.
- R: the other-user case runs `runuser -u nobody -- /usr/local/bin/alloy login --issue-code` (util-linux).
- R: a spent code must exit nonzero, since no exit code is fixed for `login_code_used`. The login output must name `admin` and `default` as whole words, and the key name is not checked.

## Issues

- spec-issue: `spec/arfc-0019-cli-and-console.md` clause 3.1.9 says "the platform equivalent" and names no path for Windows, so no check can find or clear a Windows context.
- spec-issue: `spec/arfc-0019-cli-and-console.md` clauses 3.1.7 and 3.1.11 give no exit code for an exchange refused as `Unauthenticated` or `login_code_used|voided|expired`.
- spec-issue: `spec/arfc-0002-identity-and-join.md` section 3.15 says that `alloy login` makes a context with no default project, but rung 2 builds no command that shows a context, so the e2e check cannot see it. Not covered.

## Summary

The `concurrency` group in `.github/workflows/ci.yml` now depends on the event, which resolves finding F1 of `plan/reports/T-0016.reviewer.1.md`.
Pull request runs use `ci-pr-<number>` with `cancel-in-progress: true`, so a newer push still cancels superseded runs.
Push runs use `ci-push-<sha>`. Each commit on `main` gets its own group, so a newer push cannot cancel it, whether it is pending or running.
The workflow comment now describes this behavior. actionlint 1.7.12 and `cargo xtask ci` both exit 0.

## Changes

- `.github/workflows/ci.yml`: concurrency group keyed by PR number for pull requests and by commit SHA for pushes; comment updated
- `plan/reports/T-0033.developer.1.md`: this report

(https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#concurrency).

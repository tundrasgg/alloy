## Summary

`check-commits` now finds the footer block the way git's `find_trailer_block_start` (`trailer.c`) does. It can only be the last paragraph after the title. That paragraph counts as the block when all its lines are trailers or indented continuations, or when it holds a git-generated trailer (`Signed-off-by: `) and at least a quarter of its lines are trailers. `#` lines are treated as comments.
The `footers`, `trailers`, and `task-id` rules, and `task_ids` for the path lock, read only that block. The scan that judged `Key:` lines in earlier paragraphs is gone, so commit 9cb9b92 passes.
The no-space form `Key:value` from T-0046 still counts as a trailer when it is in the block.
The `trailers` rule has a new passing fixture that copies 9cb9b92. Its failing fixture, a stray `Co-Authored-By:` in the last paragraph, is unchanged and still fails.

## Changes

- `xtask/src/commits.rs`: new `trailer_block_start` and helpers. `Message::parse` uses it, and the unused `body()` is removed.
- `xtask/src/commits.rs`: `check` no longer reports `Key:` lines outside the block, under either `footers` or `trailers`.
- `xtask/src/commits.rs`: unit tests. Thirteen messages check the block against what `git interpret-trailers --parse` printed for them. One test covers the `BREAKING CHANGE:` deviation and one covers body keys. Two older expectations changed to the git reading.
- `xtask/src/commits.rs`: the fixture harness also runs cases named `pass-<what>` and `fail-<what>`. It still requires `pass` and `fail`, and it rejects any other case name.
- `xtask/tests/fixtures/commits/trailers/pass-body-key/message`: the 9cb9b92 message, with `T-0006: ...` in a middle paragraph.

## Decisions

- N: `BREAKING CHANGE:` counts as a trailer when finding the block, although git's key grammar has no space and git finds no block in case 11. Conventional Commits 1.0.0 and `agent/eng/git.md` make it a footer.
- N: a `Key: value` line outside git's block no longer breaks any rule. A misplaced `Task:` still fails through `task-required`, and a footer paragraph that git does not read as trailers (case 13) now yields no footers instead of a `footers` breach.
- R: comments are lines that start with `#`, git's default `core.commentChar`. `trailer.*` configuration is ignored. The `---` patch divider is not handled, since commit messages carry no patch.

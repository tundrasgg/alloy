## Summary

Resolved F1 to F5 of `plan/reports/T-0105.reviewer.1.md`. No forwarded request now acts on the anchor's mesh key word alone: `withdraw` carries an identity key signature over its mesh key, and `renew` issues a record only for the serial of the node's current record, so each signed `renew` issues at most one record, expired or not. Requests end only by their reply or time limit, and a waiting heartbeat goes first. ARFC 0018 defines every node message's audit source address as one the control plane saw. ADR 0065 records the node channel decision and supersedes ADR 0042, keeping its other bullets.

## Decisions

- N: the audit source address of a forwarded request is the forwarding anchor's infrastructure address, not the address it states, so no anchor writes an address into an audit record (ARFC 0020 clause 3.3).
- N: ADR 0042 is marked superseded whole, and ADR 0065 keeps its other bullets, since ADRs cannot be amended in part.

## Issues

- `spec-issue`: an anchor without `control` holds the secret of every `join_request` it carries and can use that token, including under a mesh key it does not hold, which can block that joiner with `key_in_use` (`spec/arfc-0002-identity-and-join.md` section 8). This predates T-0105, and ARFC 0020 clause 3.3 may make it pivotal. One option: send a keyed BLAKE3 proof over `cluster_id`, mesh key, and `identity_pub`, keyed with `BLAKE3(secret)`, instead of the secret. Must be settled before any anchor without `control` forwards.
- `follow-up`: a `withdraw` deletes a `pending` request or `joining` node but writes no audit record. ARFC 0018 clause 3.3.7 has no row for it.
- `process-issue`: `agent/protocol/decisions.md` has no way to supersede part of a multi-decision ADR, so ADR 0042 is marked superseded whole.

## Summary

Round 5 handles the two lead items from T-0141 round 2's Issues. It had no review findings.
`alloyd` now treats a node as Windows when `facts.os` starts with `windows ` (the section 3.3 step 6 form, `windows 10.0.x`) or is exactly `windows`. This applies to default roles and to the join usage check.
`InitOptions` takes `cluster_id: Option<ClusterId>`. When `Some`, `init` uses the id the CLI drew for the section 3.8 `addresses` check. When `None`, `init` draws one, as it did before.
The `init` and `join` signatures are unchanged. Because `InitOptions` gained a field, T-0141's struct literal must now set `cluster_id`.

## Changes

- `crates/alloyd/src/nodes.rs`: `is_windows(os)` replaces the `WINDOWS_OS` equality, and `default_roles` uses it. The unit test covers `windows 10.0.26100`, `windows`, and `windowsxp`, which is not Windows.
- `crates/alloyd/src/join.rs`: the client-node roles refusal in `check_options` uses `is_windows`. The `JoinOptions.facts` doc gives the section 3.3 form.
- `crates/alloyd/src/init.rs`: `InitOptions.cluster_id`, which `create` uses when it is set.
- `crates/alloyd/src/tests/node.rs`: the three-node loopback test joins the client node from `windows 10.0.26100` facts. That node gets no role, and every node is heard from before and after the control restart. A join with `--roles storage` from `windows 10.0.22631` facts is a usage error. The init test passes a drawn id and checks that the join token carries it.

## Decisions

- R: a bare `windows` still counts as Windows, as the lead's wording keeps it. Only `windows` alone or followed by a space matches, so `windowsxp` does not.
- R: `cluster_id` is an `Option`, so library callers and tests can still let `init` draw the id.

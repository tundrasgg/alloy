Attack 1, an `R - 1` binding write that lands after the check (F1), by trace:
ARFC 0001 clause 3.13 Check (lines 504-514) begins at a global group position
where every running release is `R`, then reads each regional group at some later
regional position. Nothing ties that regional position to the writes that group
still has in flight. ARFC 0006 clause 3.4: a follower forwards writes to the
leader, and a Raft entry appended before a leader change can commit later.
Trace: node n runs `R - 1` with running release `R - 1`. It encodes binding B at
`V(R - 1)` with the field value that the release `R` decoder rejects (the case
ARFC 0017 clause 3.12 builds). n proposes B to region `west`, and the entry is
appended but not committed. n is upgraded: `R - 1` exits, `R` starts and writes
running release `R`. The check begins and reads `west` before B commits. B
commits. `west` still holds `W(R - 1)`, so B applies (Writing a binding, lines
493-494). The switch's condition (lines 517-520) covers running releases only, so
it applies. The rewrite of B fails with `Invalid`. By Completion (lines 546-548),
finalization stays incomplete. By the Switch (526-529), rollback is refused. By
ARFC 0017 clause 3.7, the upgrade to `R + 1` is refused. This is the state F3 of
T-0057.reviewer.2 required the check to prevent. The architect's report lists the
same gap as a `spec-issue`.

Attack 2, availability of the running-release gate (F2), by reading:
ARFC 0017 clause 3.11 (lines 74-83) applies to every `alloyd` on every node. It
requires a write to the global group "after each start, and again before each
subscription to its view, including a resume after a disconnect". Until that
write is applied, `alloyd` "serves no API call, runs no controller, applies no
view change, and decodes no stored binding". ARFC 0006 section 6 says: "Quorum
lost: all writes fail with `Unavailable`". ARFC 0006 clause 3.9 says: "A node that
cannot reach the control plane keeps serving its last view". ARFC 0006 section
2.2 puts guests, VPCs and volumes, the content of views, in the regional group.
Trace: the global group loses quorum while region `west`'s group is healthy. Any
node in `west` that briefly disconnects, or whose `alloyd` restarts, cannot
apply its running-release write. It then applies no view change from the healthy
regional group, and after a restart it decodes no stored binding, so it does not
serve its last view. Before this change, a global group outage left regional
resources unaffected. Neither ARFC 0017 nor ADR 0059 (Consequences) states this
coupling.

Attack 3, a listed region with no regional group (F3), by reading:
ARFC 0001 Switch (lines 522-524) "waits for a group that is not yet created".
Completion (lines 540-543) requires "the regional group of every region the
global group lists" to have switched. ARFC 0006 section 2.2: a regional group is
"a Raft consensus group among the control nodes of its scope". No ARFC states when
a region gets control nodes. `grep -rln -i "create.*region"` over `spec/` finds
only ARFC 0001 and 0017.
Trace: a cloud admin creates region `west` in the global group before adding
nodes. Finalization of `R` switches, then waits for `west`'s group. Finalization
cannot complete. Rollback is refused by the Switch, and the upgrade to `R + 1` by
ARFC 0017 clause 3.7. No clause says that the wait ends, that it is reported, or
that it blocks `--finalize`. A group created later would hold `W(R)` from its
first entry anyway (Completion, lines 543-544).

Attack 4, suite coverage (F4), by reading:
ARFC 0001 section 5 (lines 714-718) assigns to the ARFC 0017 clause 3.12 suite
"write versions, writing a binding, a write that races the switch, check, ...".
ARFC 0017 clause 3.12 (lines 85-112) lists eight scenarios. None writes a
configuration that release `R` can encode at the write version but not at its own
`VERSION`. That is the Writing a binding rule (ARFC 0001 lines 490-493), the
mechanism behind the claim in the Rewrite bullet (lines 537-539) that a binding
written after the check re-encodes. No scenario stores a binding whose
implementation has no configuration type in release `R` (Check, lines 510-513).
`agent/protocol/spec-change.md`: "Every 'must' is testable and has a conformance
test."

Attack 5, the `instantiate` detail (F5), by reading:
ARFC 0001 line 98: `const KIND: &'static str`, with no length bound. Lines 442-444
say that the detail "holds `S::KIND` and the `NameError`". Line 144 and section 7
(line 757): `Detail` is at most 1,024 bytes and is truncated. Take an `S::KIND` of
2,000 bytes. Its `NameError` is `TooLong`. A detail holding both strings is longer
than 1,024 bytes, so the truncated detail cannot hold both.

Attack 6, a regional group's first entry against the switch write (F6), by trace:
ARFC 0001 lines 481-484 say that a group's "first log entry" sets its write
versions from a global read made "when that entry is proposed". Lines 522-524 say
finalization waits for "a group that is not yet created". "Created" is not
defined. The creator reads `W(R - 1)` and proposes E0. The switch commits.
Finalization sees `west`'s Raft group formed and proposes S. A leader change
reorders the two, so S commits first and E0 second. The clause does not say
whether E0, which is now not the first entry, sets the write versions. If it
does, `west` holds `W(R - 1)` after its switch write. Finalization writes "one
write each", so nothing switches `west` again.

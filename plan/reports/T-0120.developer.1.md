## Summary

`DiskIo` now has `create_file`, `create_dir_protected`, `security`, `set_mode`, and `rt_path`, with `Protection`, `Security`, `Sid`, and `Ace`, exactly as ARFC 0005 section 2.4 states.
`os` implements clause 3.1.15 on Linux and macOS (mode passed to the creating call, then checked and set through the new descriptor) and on Windows (SDDL descriptor passed to `CreateFileW` and `CreateDirectoryW`, `security` from `GetSecurityInfo` on a handle opened with `FILE_FLAG_OPEN_REPARSE_POINT`).
`mem` keeps a mode per entry (0o755, 0o644, 0o660; 0o600 and 0o700 for `Private` and `PrivateRoot`), logs `set_mode` as a change that only `sync(All)` or a `sync_dir` of the directory itself makes durable, and writes `disk-op` operations 13 to 16.
Tested on Windows here, not elevated. Linux and macOS code was not compiled or run here: no Linux or macOS target is installed on this host. The lead runs the Linux tests (task notes).

## Decisions

- R: `os` on Linux and macOS checks, through the new directory's descriptor, that a `Private` or `PrivateRoot` directory is owned by the effective user id, and otherwise removes it and returns `PermissionDenied` (review T-0117.2 F9). A file needs no check: `O_CREAT | O_EXCL` made it.
- R: when `os` resets a new entry's mode, it `fsync`s that entry through the same descriptor, so a crash cannot bring back the set-group-ID bit (review T-0117.2 F10).
- R: on Windows `ERROR_INVALID_OWNER` and `ERROR_PRIVILEGE_NOT_HELD` from a protected create map to `PermissionDenied`; a malformed list or SID read from the system is `Io`.
- R: `create_file` on a directory returns `IsDirectory`, as `open` with `Create::New` does under `os`.

## Issues

- `spec-issue`: review T-0117.2 F7 is not an implementation matter. `security` returns `NotFound` for a missing entry as clause 3.1.15 says; ARFC 0002 section 3.12 must say that `NotFound` for a missing data directory or host file leads to creating or adopting it, not exit 5 (`spec/arfc-0002-identity-and-join.md`).
- `spec-issue`: review T-0117.2 F8 needs spec text. `rt_path` returns `Unsupported` under `mem` as clause 3.1.15 says; ARFC 0002 section 3.12 must say how the data directory is named on an instance with no native paths (`spec/arfc-0002-identity-and-join.md`).
- `spec-issue`: clause 3.1.15 says `create_file` has the errors of `open`, but `open` with `Create::New` on a directory gives `IsDirectory` under `os` and `AlreadyExists` under `mem` (`crates/alloy-sim/src/disk.rs` `Disk::open`). The clause should name one.
- `follow-up`: the Windows test that creates `Private` and `PrivateRoot` entries owned by `Administrators` takes its elevated branch only on an elevated host. Here it ran the unelevated branch (`PermissionDenied`, nothing left at the path); the same descriptors with the test account as owner were checked in full. The Windows CI host should run elevated (`crates/alloy-rt/src/os/disk/tests.rs`).
- `follow-up`: no test covers `security` on a Windows reparse point; creating one needs a privilege or a junction helper (`crates/alloy-rt/src/os/disk/tests.rs`).

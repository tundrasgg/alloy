## Summary

`rung1.ps1` now writes each Linux script's bytes to the standard input of `ssh.exe`, which runs `sh -s -- <words>` on the node. No script text goes through a command line. Nothing is copied to the node.
The first-run error reproduces exactly with the old transport and an MSYS-runtime `ssh.exe` (Git for Windows) under Windows PowerShell 5.1. The Windows OpenSSH 9.5 client did not fail on this machine. The cause on the pilot's machine is unknown. The driver now prints the `ssh.exe` it uses.
Windows PowerShell 5.1 writes a UTF-8 BOM at the start of redirected stdin when the console input encoding is UTF-8. The driver turns that preamble off while ssh starts.
`host-snapshot.sh` drops `transient` and `generated` units. The README lists every class of state the comparison ignores, and gives the corrected acceptance forms.

## Changes

- `tests/e2e/rung1.ps1`: `Invoke-RemoteScript` sends the script on stdin through `System.Diagnostics.Process`. It refuses any argument that is not a plain word, quotes arguments by the C runtime rules, sets `$SshOptions` for every connection, and prints the SSH client in use.
- `tests/e2e/host-snapshot.sh`: `norm_units` drops `systemctl list-unit-files` rows whose state is `transient` or `generated`.
- `tests/e2e/README.md`: describes the stdin transport. Adds a "What a comparison ignores" table (state, where, why) and a "Checking the scripts" section with the per-file `sh -n` loop and the PowerShell parse with initialized variables.

## Decisions

- Snapshot noise is dropped in `host-snapshot.sh`, not in the comparison, so a snapshot read by hand matches what is compared. Class R.
- `Invoke-RemoteScript` refuses an argument that does not match `^[A-Za-z0-9._+/=:@-]+$` before ssh runs. Every caller passes a version, `--proxmox`, `--check-b64`, or base64. Class R.
- No local stand-in for `ssh` was needed: a real sshd was reachable (Git for Windows `sshd` on loopback). Its remote shell is MSYS bash, not Linux. The Linux side was checked in a container. Class R.

Attack H: host fault chaos with replays, 1,000 seeds, each run twice. A host's boot records its first 8-byte draw and spawns three workers that sleep and draw. The control task makes 30 steps, each after a random sleep. It applies `Stall` up to 10 s, `Crash` with `after_polls` 0 to 2, or, when the host is crashed, `Restart` with `rng_replay` `None` or a random `Some(s)` from 1 to the last start. Then it crashes the host and awaits a future that never completes. Checks: the two runs of a seed give equal summary lines. A start with `Some(s)` draws what start `s` drew, so replays of replays are covered. The run ends with `liveness` within 100 ms of world time, so no stall that a crash ended moves time on.

Attack R (finding F1): start 1 creates one `rng` instance. Start 2 replays start 1 and creates two. Start 3 also replays start 1 and creates two. Instance 0 is the boot runtime's. Instance 1 comes from `Runtime::from_registry` on the start's registry. Each instance records its first 8-byte draw.

```
ATTACK R: (start, instance, first draw) = [(1, 0, 14741779163376352888), (2, 0, 14741779163376352888), (2, 1, 872026031924761541), (3, 0, 14741779163376352888), (3, 1, 872026031924761541)]
```

Instance 0 of starts 2 and 3 repeats start 1's stream, as clause 3.3.4 requires. Start 1 drew no stream at instance 1. Even so, instance 1 of start 3 draws exactly the stream of instance 1 of start 2, which start 3 did not replay. The cause, by reading: `new_rng` (`host.rs:430-446`) seeds every instance of a replaying start from `(host, source, index)`. Every replay of one source therefore shares its streams at every index, including indexes the replayed start never reached.

## Summary

`alloy-state` now stores `JoinToken`, `Org`, `User`, `LoginCode`, and `AccessKey` through the resource API, each held to its kind's field checks, plus the org scope that ARFC 0006 section 2.1 names. `Group::issue_login_code` and `Group::exchange_login_code` each commit as one log entry, decided at apply against committed state. An issue records the hash, issuer, user, and expiry, and drops the oldest of 10 unused codes. An exchange spends the code once and creates one access key, sealed as ARFC 0007 section 3.11 says, with the naming of 3.9.3, `replaces` of 3.9.10, and the limits of section 7. T-0121 review F2 and F3 are folded.

## Decisions

- N: Issue and exchange are each one `Command::Identity` entry that every member decides at apply from the state it holds. That enforces the 10-code limit, the key limits, name uniqueness, and at most one exchange of a code under concurrency (ARFC 0007 clause 3.9.4).
- N: `Scope::Org(String)` added for the org-scoped kinds (ARFC 0006 section 2.1, ARFC 0007 section 2.5). It is a new key tag `o` and a new encoding tag 2, and existing encodings are unchanged.
- N: `IssuedBy` stores only `init` and `root@<node>` (ARFC 0007 section 3.11). That is what makes it correct for `replaces` to revoke and delete the named key in the exchange transaction and void no code.
- N: A generic create of `AccessKey` or `LoginCode` is refused (clause 3.9.1). Generic writes of every new kind must decode as that kind in its scope.
- N: The leader generates the key id, secret, and nonce, and seals the secret with the `AeadKey` the caller passes. The log entry holds only the sealed secret. Ids are checked unique across all orgs at apply, and an id in use is drawn again, at most 8 attempts.
- R: The secret check compares `BLAKE3` digests by xor-fold. `alloy-state` has no `subtle`, and adding it changes `Cargo.lock`, which is outside `touches`. The values compared are digests, not secrets, and a wrong guess spends the code.
- R: The "oldest" code is the earliest `expire_time`, ties broken by name. `create_user` does not check that its org exists; an issue or exchange against a missing org fails with `PermissionDenied`.

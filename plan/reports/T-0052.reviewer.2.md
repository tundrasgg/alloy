Attacks tried. This is a spec task with no code, so each attack is a scenario traced through the amended clauses.

1. **Path to tenant data outside `iam`.** Root on control node C, which lacks `compute`, calls `cluster:UpdateNode` on C to add `compute` and `storage` (ARFC 0019 line 84, ARFC 0000 line 24), and steers placement with the node and pool management that `cloud-admin` allows (taints and placement rules, ARFC 0011 clause 3.4.1). Org P's next guest or volume replica lands on C, which then reads it as it legitimately serves it (ARFC 0020 clause 3.3). No call names P or a resource in P, so 3.10.6 writes nothing to P's chain. The calls are in the cluster chain and raise the warning. The amended 3.3 sentence and section 8's "no third way" both say otherwise (F1).
2. **Cross-org call by the recovered key.** Recovered `U` in `O` with `cloud-admin` makes a call whose target lies in org P. Clause 3.2 requires an allow from a resource policy on the target or a policy in P; `cloud-admin` is a cluster role, neither. Clause 3.10.7 says the call must be allowed once target-side denies are detached. Whether 3.2 applies to cluster role calls is unstated (F2).
3. **Deny in an unlisted place.** Caller side `U`, groups, `O`; target side resource policy, project, org, principal and groups. A deny attached to any other principal, group, project, or org does not apply under 3.1 to that call, and the clause now says so ("must not refuse"). No attachment point in 2.4 found outside the list.
4. **Lock out through a resource policy.** A thief holding the PB-0001 `owner` key attaches a bucket policy denying `object:*` to every principal. Under 3.1 the deny binds every caller, the bucket's owner included, and 3.10.7 puts resource policies outside the local admin. Cluster recovery is unaffected, as 3.10.7 states, but nothing can remove that bucket policy. Raised as an issue, outside this task's scope.
5. **Narrowing the local admin by editing `cloud-admin`.** Clause 3.10.1 now forbids any method that changes what a built-in role allows. Holds.

- `spec-issue`: a resource policy whose deny covers every caller cannot be removed by any principal, the org `owner` and the local admin included, so a stolen `owner` key can lock a bucket or repository for good (`spec/arfc-0014-object-storage.md` clause 3.5, `spec/arfc-0007-tenancy-and-iam.md` clauses 3.1 and 3.10.7).

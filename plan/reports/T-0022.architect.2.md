## Decisions

- ARFC 0002 follows ARFC 0007 clause 3.9.4: the exchange returns the access key secret once. Reason: ARFC 0007 owns access keys and is merged, and F6 requires the two to agree. `touches` does not include ARFC 0007. Join token and login code secrets stay client-generated.
- A join retry is recognized by `identity_pub`, a mesh key authenticated by the AL session, and the same `token_id`, after the secret matches. Reason: `identity_pub` alone is not proven by the request, and the mesh key is.
- A retry is answered whatever the token's state since admission. Reason: a one-use token is used up by the first attempt, and section 6 promises the retry succeeds.
- Every node gets advertise addresses, which the record carries. Reason: F5, and ARFC 0007 clause 3.10.1 already speaks of the advertise addresses in a node record. This widens PB-0001's "used only when the node holds anchor" to anchor or control.
- The token carries preset roles but not the preset zone. Reason: only roles affect the checks before contact.
- Tokens across a cluster key rotation work during the overlap and are revoked at its end, rather than capping token lifetime at 7 days.
- New reason `login_code_voided` for a code voided under ARFC 0007 clauses 3.9.7 and 3.9.8. An exchange spends the code only on success and on a wrong secret for a known id.
- Method names `IssueLoginCode` (matching action `iam:IssueLoginCode`), `CreateJoinToken`, `ListJoinTokens`, `RevokeJoinToken`. `CreateLoginCode` is gone.
- After a step 6 request, the joiner waits at most 10 seconds for the answer, then the attempt fails with exit 6.

## Issues

- `spec-issue`: I-22 says secrets never appear in API responses, but ARFC 0007 clause 3.9.4 returns the new access key secret in the exchange response. One of them needs to change: I-22 could allow the one response that creates a secret, or ARFC 0007 could take a client-generated secret (`agent/domain/invariants.md`, `spec/arfc-0007-tenancy-and-iam.md`).
- `spec-issue`: ARFC 0008 clause 3.7 lists only session tokens and SigV4. It does not mention `ExchangeLoginCode` (ARFC 0002 section 3.7) or the local admin socket (`spec/arfc-0008-native-api.md`).
- `spec-issue`: the glossary defines an advertise address as an anchor's, and a context as having one API endpoint. Both are now wider (`agent/domain/glossary.md` lines 27 and 63).
- `follow-up`: PB-0001 wording for the new refusals `key_in_use` and `login_code_voided`, and for `init` when no advertise address is local (`product/briefs/PB-0001.md`).
- `follow-up`: `alloy node leave` refuses while a disk is in a pool, and `join` puts every storage node's disk in pool `default`, so `leave` on such a node always fails with no next step. This needs a pool brief and a command that takes a disk out of a pool (`spec/arfc-0012-storage-core.md`).
- `follow-up`: `--api-port` on `join` (PB-0001 Errors, "Port in use") belongs with T-0024 (`spec/arfc-0008-native-api.md` clause 3.8).

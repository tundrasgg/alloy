## Summary

ARFC 0011 section 2 no longer asks for a per-guest seccomp filter. The filter is
fixed per `hypervisor` implementation and version, enforcing, on every thread.
Per-guest confinement is a Unix user, cgroup, user, mount, and network namespaces,
a guest directory, and a Landlock rule set fixed at start (clauses 2.1 to 2.7).
Hot attach uses vhost-user sockets in the guest directory, so it needs no new
Landlock rule. Unix sockets are confined by mount view, socket file modes, and the
network namespace. This is a behavior change, recorded in ADR 0038.

## Decisions

- Behavior change, so ADR 0038 was written. It refines ADR 0022 and does not supersede it: each VMM still has its own filter instance, user, namespaces, cgroup, and Landlock policy.
- No outer Alloy seccomp filter. Writing one needs the VMM's syscall set per release, which no research note gives, and a wrong entry kills guests.
- Added a per-guest network namespace with only loopback, to isolate abstract Unix sockets, which Landlock does not cover. Consequence: migration traffic leaves through a Unix socket in the guest directory, not a VMM TCP listener.
- ARFC 0020 is not weakened: the guest to host boundary is still one sandboxed VMM per guest, and the sandbox gains a network namespace and explicit socket rules. The per-guest seccomp wording was stronger than any available implementation meets; it is replaced, not relaxed silently.

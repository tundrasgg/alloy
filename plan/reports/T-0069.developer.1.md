## Summary

F1: `alloy-seam` has a `proptest` property test of the ARFC 0001 section 4 codec. It checks the round trip for every valid value, the empty and largest payloads included, and checks every byte string against a model of section 4.
`proptest` runs from fixed seeds with `RngSeed::Fixed`, no failure persistence, `max_shrink_time` 0 and every limit set explicitly. So it reads no OS entropy, has no time-based limit, and ignores `PROPTEST_*` variables. The `timeout` and `fork` features stay off.
F2: `Datagram` and `RecvSlot` `Debug` print lengths only (`Datagram { len: N }`, `RecvSlot { capacity: C, len: L }`). A property test in `alloy-rt` checks this for any addresses, flags and bytes.
Both crates take `thiserror` and `proptest` (dev) from the workspace. `cargo xtask ci` exits 0.

## Changes

- `crates/alloy-seam/tests/config_codec.rs`: new property tests for round trip and totality of `ConfigValue::to_bytes`/`from_bytes` (F1).
- `crates/alloy-rt/src/net.rs`: `Datagram` and `RecvSlot` `Debug` print lengths only, and the unit test expects the new text (F2).
- `crates/alloy-rt/tests/debug_lengths.rs`: new property test that the two `Debug` outputs hold lengths only for any input (F2).
- `crates/alloy-seam/Cargo.toml`, `crates/alloy-rt/Cargo.toml`: `thiserror.workspace = true`, and `proptest.workspace = true` as a dev-dependency.
- `Cargo.lock`: adds the `proptest` tree. It is already on the `deny.toml` allowlist. Only the lock file changes outside `touches`, as any dependency change requires.

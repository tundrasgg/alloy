## Summary

`tests/e2e/rung2.ps1` reruns M11 rung 2 from a clean state. It installs everywhere, runs `init` on the first `-LinuxNode`, then `join` on the other Linux nodes and on the Windows client, and logs each machine in. Then `node list` (JSON and table) on every machine must show all three nodes `active` with their roles. While joined, each snapshot may differ from the pre-install one only in reserved objects. Last it uninstalls with `--purge`, client first, and each snapshot must equal the pre-install one.
The rung 1 helpers moved, unchanged, into `e2e-lib.ps1`. Both drivers dot-source it.
Not yet run on real machines. Per the task notes, the lead runs it once T-0111 and T-0112 merge. Locally verified: both shells parse every script, 33 fixed-input tests of the new lib functions pass, the usage errors exit 2, and a dry run stops at preflight without installing anything.

## Decisions

- N: the rung 1 helpers moved verbatim into `tests/e2e/e2e-lib.ps1`, so later rungs share one copy. Proven byte-identical by rebuilding the original.
- N: `Write-Check` hides `alyt_…` and `alyc_…` in detail lines, so a report that quotes a run leaks no join token or login code.
- R: names expected from the hostname by the rule of ARFC 0002 section 3.3 (`uname -n`; `[Dns]::GetHostName()` on Windows), suffixed in join order. Roles from the `/dev/kvm` read-write open.
- R: "al then a digit" read as a name prefix (`^alv?[0-9]`). The 30 s and 10 s bounds are timed from the driver, SSH and 1 s polling included, so the check is at least as strict as the spec.
- R: `node list` runs through a context from `alloy login`, as ARFC 0002 section 3.7 requires. The local admin path of ARFC 0019 clause 3.1.14 does not cover `node list`.

## Issues

- spec-issue: ARFC 0006 section 2.6 says `Node` fields are "spelled in JSON as ARFC 0008 section 2 says", but `spec/arfc-0008-native-api.md` section 2 gives no JSON spelling. It leaves open the nesting, the enum spelling, whether `name` is `x` or `nodes/x`, and whether an empty `roles` is omitted. The check accepts each field flat or under `spec`/`status`/`metadata`, both name forms, and a missing `roles`.
- spec-issue: in `spec/arfc-0002-identity-and-join.md`, section 3.3 step 7 puts every storage node's `file` disk in pool `default`, and section 3.9 refuses `leave` for a node with a disk in a pool. So a node joined with default roles can never leave, and `uninstall --purge` exits 5 unless `--force` is given, which leaves its record until it expires. The task asks that "the second node leave first". The check follows the spec: exit 5, the node still listed, then `--force`.
- spec-issue: `spec/arfc-0017-upgrades-and-versioning.md` clause 3.17 reserves interface kernel parameters only under `net.ipv{4,6}.conf.<if>`, and routes "only in the main table". The kernel itself makes `net.ipv{4,6}.neigh.<if>.*` and `table local proto kernel` routes for any interface and address. The check accepts both on reserved interfaces (README table).
- follow-up: rung2.ps1 is unrun against real machines. The lead runs it after T-0111 and T-0112 merge, and any driver defect found there goes back to the verifier.

## Summary

Round 2 resolves every finding of `plan/reports/T-0006.reviewer.1.md` (F1 to F9) by edits to ARFC 0001 and ARFC 0005. The reviewer was right on all nine.
ARFC 0001: swap futures start at their first poll (F5), configuration values are persisted and written at a chosen version through `to_value(version)` (F6), `SeamState` and `ConfigValue` print version and length only (F7, new clause 3.18), and the order of `ConfigValue` checks is fixed (F8).
ARFC 0005: the `mem` stream buffer is 262,144 bytes per direction (F1), host time under skew has an exact integer formula and a wake rule that holds under skew (F2), `mem` rng streams are distinct per instance and per host start (F3), section 4.1 fixes which event writes each trace record and its field values (F4), and `RecvSlot::new` is bounded at 65,535 bytes (F9).

## Decisions

- Serialized configuration values are persisted control plane state that crosses nodes and releases. So `SeamConfig::to_value` takes the version to write, and writers use the previous version until an upgrade is finalized. This constrains every implementation's configuration ARFC.
- Configuration messages never hold a secret in the clear. A secret is named by reference, or stored encrypted under a `key-provider` key as ARFC 0007 clause 3.8 does. This binds the `authn` `oidc` configuration when it is specified.
- Swap futures are lazy: they claim the slot at first poll. Dropping one that was never polled is harmless.
- The `mem` stream buffer is a fixed 262,144 bytes per direction and is not a `StreamOptions` field, so `os` keeps platform buffer sizing.
- The `mem` clock rate offset is bounded to plus or minus 500,000 ppm so host time stays strictly increasing in world time and the formula never divides by zero or runs backward.
- The trace records stream events per endpoint and per API call (`write`, `read`, `connect`, `accept`), not per simulated delivery, so each record maps to one observable call.

## Summary

`crates/alloy` and `crates/alloyd` exist as workspace members, each a library with a thin `main`. `alloy` parses `alloy <noun> <verb>` and top-level commands from a command table that registers only `version`. Anything else is a usage error (exit 2) with a `Try:` line. `alloy version` prints the package version and a line feed, nothing else.
`alloyd version` prints the same version. `alloyd` with no command starts an `OsHost` and logs that it started, with its data directory. It reads the host file through the `os` `disk-io` seam, logs "not initialized" naming `alloy init` and `alloy join` when there is no join state, waits for SIGTERM or SIGINT (Linux), a service stop or shutdown (Windows service `alloyd`), or Ctrl-C (Windows console), then shuts the host down with a 20 s grace and exits 0.
The two crates add 2,299 lines of Rust, about half of them tests, which is above the 2,000-line target of `agent/core/6-pace.md`. All four acceptance commands pass on this Windows host. Linux was not compiled here, because no Linux target is installed. The lead's Linux build and test run is still owed.

- `deny.toml`: allowlists the eight crates above (licenses under Evidence).
- `plan/workspace.md`: `alloyd` and `alloy` kind `lib, bin` (the binaries' library entries carry the tests).
- `crates/alloy/src/grammar.rs`: `CommandSpec` table (`COMMANDS` = `version`), `parse` (flags anywhere, `--`, `-h`/`--help`, longest path wins), usage errors naming the first wrong word, flag, or extra argument, with a `Try:` command that runs as printed (nearest word within 2 edits, else `alloy --help`), and help text with usage, flags with default, and examples (T5, T8, T27, T29).
- `crates/alloy/src/text.rs`: wrapping at 80 columns outside backticks (T3), and edit distance for suggestions.
- `crates/alloy/src/lib.rs`, `main.rs`: `run(args, out, err, style) -> u8`. Results go to stdout only (T1) and usage errors to stderr. `Style::of_stream` follows T12: the `Try:` command is bold only on a terminal with `NO_COLOR` unset or empty and `TERM` not `dumb`, never on Windows. `main` returns `ExitCode` (D-0039).
- `crates/alloyd/src/lib.rs`: `run(options, stop_when)`, the run loop described above; `VERSION`, `SHUTDOWN_GRACE` (20 s), `DaemonError`; builds the `os` seams with `disk-io` rooted at the data directory's file system root.
- `crates/alloyd/src/data_dir.rs`: default data directory (`/var/lib/alloyd`, or `Alloy` in `%ProgramData%`, ARFC 0002 section 3.3); total parser of the host file's first two lines (ARFC 0017 section 4.2); `read_join_state` through `DiskIo`, `unjoined` when there is no host file (ARFC 0002 section 3.12).
- `crates/alloyd/src/stop.rs`: `Stop` (first trigger wins, callable from any thread) and `StopCause`.
- `crates/alloyd/src/signals.rs`: `os_signals`: SIGTERM/SIGINT through `tokio::signal::unix`, Ctrl-C/Ctrl-Break through `tokio::signal::windows`.
- `crates/alloyd/src/service.rs` (Windows): `dispatch` hands the thread to the service control manager. If the process was not started as a service (Win32 error 1063), it returns `false` and `main` runs at the console. The service reports `Running` (accepts stop and shutdown), `StopPending` with a 25 s hint, then `Stopped` with exit code 0, or service-specific 1 on failure.
- `crates/alloyd/src/log.rs`: `LineLog`, a `tracing` subscriber that writes one `LEVEL message key=value` line per event at INFO and above. It quotes and escapes values, so an event never spans two lines.
- `crates/alloyd/src/args.rs`, `main.rs`: `alloyd`, `alloyd version`, `alloyd --help`; anything else exits 2 naming the argument.

## Decisions

- alloyd depends on `tokio` directly, with the `signal` feature, to watch SIGTERM, SIGINT, and Ctrl-C. No `alloy-rt` seam carries process signals, and `alloy-rt` is outside this task's `touches`. The code is confined to `crates/alloyd/src/signals.rs`, and no `clippy.toml` entry bans it.
- Logging uses `tracing` with no `tracing-subscriber`. alloyd has its own `LineLog` subscriber, about 110 lines without its tests, which avoids `sharded-slab`, `thread_local`, `nu-ansi-term`, and `tracing-log` (agent/eng/deps.md "Necessary"). The `attributes` feature is off, so there is no proc macro tree.
- No argument parser crate. `alloy` uses its own table-driven grammar (`grammar.rs` and `text.rs`, 630 lines with their tests), and `alloyd` takes only `version` and `--help`. Choosing a parser is better done when shell completion (ARFC 0019 clause 3.1.10) is built, because completions must come from the same definitions.
- The Windows service uses `windows-service` 0.8.1 without its `define_windows_service!` macro, because that macro expands `unsafe` into the caller and alloyd forbids it. alloyd's own `extern "system" fn` ignores the service arguments and needs no `unsafe`.
- A usage error exits 2, as ARFC 0019 clause 3.1.7 says, rather than 1 as the task's note allowed. `ExitCode` is permitted (D-0039, and `check-repo` passes).
- The Windows data directory reads `%ProgramData%` from the `ProgramData` environment variable, in `main` and in the service main. An unset, empty, or relative value is an error (exit 1, or service exit code 1), and no fallback path is guessed.
- `SHUTDOWN_GRACE` is 20 s, which leaves 10 s of the uninstall's 30 s (ARFC 0017 clause 3.16 step 5) for the process to exit.

## Issues

- `spec-issue`: ARFC 0005 section 2 has no seam for process stop signals or service control requests, and `agent/eng/rust.md` rule 2 says only `alloy-rt` reaches the OS. alloyd watches them through `tokio::signal` and `windows-service` in `crates/alloyd/src/signals.rs` and `crates/alloyd/src/service.rs`. The spec should either allow the daemon entry to do this or add a seam.
- `spec-issue`: no ARFC says where `alloyd` logs on Windows. As a service, its standard error is discarded, so the `LineLog` lines are lost there (`crates/alloyd/src/main.rs`). On Linux, systemd's journal keeps them. The Windows Event Log is the usual destination (ARFC 0017 or ARFC 0018).
- `follow-up`: ARFC 0002 section 3.12 and ARFC 0017 section 4.2 require `alloyd` to check that its data directory is an Alloy data directory at every start, and to log the reason every 60 s and serve nothing when it is not. This release logs a host file it cannot parse once, as a warning, and does not check owner or mode (`crates/alloyd/src/lib.rs` `report_join_state`). It belongs to the alloyd task that adds `init` and `join`.
- `follow-up`: the lead's Linux run of `cargo build`/`cargo test -p alloy -p alloyd`, and a manual `kill -TERM` of a running `alloyd`, are still owed. Neither the `cfg(unix)` code in `crates/alloyd/src/signals.rs` nor the unix-only tests were compiled on this host.
- `follow-up`: `alloy` does not implement the `--color` flag of principle T12 or the terminal-width bound of T3. It wraps at 80 columns and never styles on Windows (`crates/alloy/src/lib.rs` `Style::of_stream`). Fold this into the next CLI output task.

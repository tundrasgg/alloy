## Summary

`alloy-state` serves the kind `Node` of ARFC 0006 section 2.6 through T-0107's resource API, with field checks, create, update with a generation, get, and list.
The leader accepts heartbeats (the `NodeStatus` of 4.3) as clause 3.14 says. It keeps their time, wall time, and addresses as soft state in memory, never in the group, and commits only `reported` and the running release.
Reads compute `state` by clause 3.15. That includes the leader-start rule and `unreachable_since`, with a fresh tenure at every `open` and `initialize`.
The change is 1,377 lines without `Cargo.lock`, within the 2,000-line target.

## Decisions

- N: `spec` and the committed `status` are stored as `alloy.cluster.v1alpha1.NodeSpec` and `NodeStatus` (2.1: kinds are protobuf messages). `state`, `addresses`, `last_heartbeat_time`, and `mesh` are left unset.
- N: `accept_heartbeat` takes the node's name. Mapping the AL session's mesh key to the node record is the node channel's job (T-0111).
- N: a pending join request is a `Node` whose `record` is `None`. `RecordTerms` holds `serial` and `not_after` of the current record.
- N: soft state is keyed by `uid`, so a node created again under a deleted node's name starts with none. Every `list_nodes` drops entries of nodes the group no longer holds.
- R: a heartbeat from a node that is `deleting` is `REFUSED`, the same as from a deleted node (3.14).
- R: node names are 1 to 63 bytes of `[a-z0-9-]` (ARFC 0002 3.3). A release is SemVer 2.0.0 `MAJOR.MINOR.PATCH[-pre]` with no build metadata, at most 64 bytes (https://semver.org/spec/v2.0.0.html).
- R: soft state is recorded before the commit, in the order 3.14 lists. A commit that conflicts with another write is retried at most 3 times, then the reply is `UNAVAILABLE`.

## Issues

- follow-up: the running release write is never refused, because no finalized release exists in state yet (ARFC 0017 clause 3.11). `StatusReply::ReleaseRefused` is never produced (`crates/alloy-state/src/nodes.rs`).
- follow-up: the commits of `reported` and of the running release write no audit record (ARFC 0018 clause 3.3.7), because no audit crate exists yet (`crates/alloy-state/src/nodes.rs`).
- follow-up: `mesh` (ARFC 0004 section 3.7) is not held, and the node lifecycle controller of 3.16 (setting and clearing `unreachable_since`, dropping soft state on delete) is not built. The tests commit `unreachable_since` through `update_node`.
- follow-up: a tenure starts only at `open` and `initialize`, which is right for one voter. A group with several voters must start one at each leader change (3.15) (`crates/alloy-state/src/group.rs`).

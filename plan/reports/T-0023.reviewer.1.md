Attacks tried. This is a spec task with no code, so there is nothing to fuzz or run in the simulator. Each attack is a scenario traced through the clauses:

1. Hostile tenant or compromised compute node tries to reach the local admin. The tenant breaks into its VMM on a node that is both compute and control, which is the `init` default. The attack fails. The VMM is not root in the initial user namespace (ARFC 0011 clause 2.1), and its mount namespace contains no socket outside its guest directory (clause 2.3). A compute node that forwards a forged local admin write is refused by the control plane (ARFC 0007 clause 3.10.4). No finding.
2. Stolen user access key, with the goal of persistence past revocation. Going through the access key alone is caught by the descendant count. Going through a session token or a temporary key breaks the `issued_by` chain. See F1.
3. Getting around org containment and user disable through the local admin. An org deny on `iam:IssueLoginCode` does not clearly bind the local admin (F2). A disabled user can get a working key again (F3).

The ruling against ARFC 0020 was checked independently. Root on any control node already controls every key-holding principal. Every control node serves the API (ARFC 0006 clause 3.4) and authenticates every call (ARFC 0008 clause 3.7). SigV4 needs the access key secret to verify (ARFC 0007 clause 3.8). Secrets at rest on a node sit under a node key file of mode `0600` (ARFC 0020 clause 3.7). The control plane is Raft (ARFC 0006 section 2.2), which tolerates crashes but not lying members. So the local admin adds no trusted party. That holds even though no ARFC says that a control node keeps the cluster key, which is the premise ADR 0041 actually cites (F6).

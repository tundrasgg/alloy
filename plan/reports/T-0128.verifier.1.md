## Summary

`task/T-0128` is branched from `task/T-0121` with main merged in. Both `native` harnesses now first ask `disk-io` whether this process can create a `Private` file. If it can, every `native` check runs as before. If it cannot (only `PermissionDenied` on Windows counts), the harness checks that building `native` returns `BuildError::Failed` and leaves the directory empty. It then prints one line, not captured by the test harness, naming how many `native` checks did not run and why. `cargo xtask ci` exits 0 on this unelevated Windows host. The `mem` checks are unchanged.

## Changes

- `tests/conformance/log-store/tests/conform.rs`: `NativeHarness::prepare` (a fresh runtime, registry, and directory pair), `can_create_private` (probe, with a check that a refused create leaves nothing at the path), `check_refusal` (`log-store` `native` build is `Failed` and `a/` is still empty), and the `native` test that runs the suite or checks the refusal and prints the skip line.
- `tests/conformance/state-store/tests/conform.rs`: the same for kind `state-store`. The file keeps its CRLF line endings from main.

## Decisions

- R: only `PermissionDenied` on Windows counts as "cannot create `Private`". Any other probe error, and any refusal on Linux or macOS, fails the test.
- R: "nothing was created" is checked as an empty store directory, which is stronger than checking that the store file is missing.
- R: the skip line goes straight to the `stderr` handle, so it shows in `cargo test` output without `--nocapture`.

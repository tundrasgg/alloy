## Summary

All four `fix` findings and both `note`s of `plan/reports/T-0066.reviewer.1.md` are resolved by edits to ARFC 0001 clause 3.13, sections 5 and 6, clause 3.12, ARFC 0017 clauses 3.7, 3.11, and 3.12, and ADR 0059.
Delayed binding writes are fenced by a per-group binding epoch that the check increments. Regional groups are recorded in the global group, and write versions only move forward.
A restart at the same release no longer writes to the global group. The one remaining dependency is stated as the exception to ARFC 0006 clause 3.9.
The work is on `worktree-agent-a8a37f89b8d84327c`, which contains `task/T-0066` and main (Issues).

## Changes

- `spec/arfc-0001-runtime-seams.md`, F1 (fix): new Binding epoch bullet. Every binding write names the group's epoch. The check increments it with one write in each group recorded at `P` and reads that group after the write, so a write whose epoch was read earlier is refused with `Conflict`. The Check bullet now argues that every binding stored at the switch was read by the check or written after `P` by a release `R` process.
- Same file, F3 (fix): new Groups bullet. A regional group is created by a global write that records it. A region with no recorded group is not waited for. The Switch no longer waits for uncreated groups. A recorded group that refuses finalization's write is reported with its region and error, and is cleared by restoring quorum and running `--finalize` again (Completion, section 6).
- Same file, F6 (note): the Write versions bullet makes write versions monotonic. A write that sets those of release `X` applies only over none or an older release, so the first entry and the switch write commute. A group holding no write versions refuses binding writes with `Unavailable`. The error order is stated: `Unavailable`, `Conflict`, `UnsupportedVersion`.
- Same file: the race bullet now covers both a switch and a check: one retry, stated once. Section 5 lists the new rule names. Section 6 covers `Unavailable`, epoch `Conflict`, unreadable groups, unregistered implementations, and unswitched groups.
- Same file, F5 (note): clause 3.12 fixes the `BuildError::Failed` detail as `Detail::new(&format!("seam kind {:?} is invalid: {}", S::KIND, e))`, so it holds for every `S::KIND` after truncation. This matches `crates/alloy-seam/src/registry.rs` on main (lines 204-209).
- `spec/arfc-0017-upgrades-and-versioning.md`, F2 (fix): clause 3.11 adds node-local started and applied releases. `alloyd` skips the running release write when its release equals both, so a same-release restart and a view resume do not touch the global group. An `alloyd` that must write (upgrade, fallback, lost local state) serves nothing while the global group has no quorum, and the clause names this as the one exception to ARFC 0006 clause 3.9. `alloyd` writes again if its node record shows another release. `alloy cluster recover` clears running releases. Clause 3.7 refuses while any running release is not N+1.
- Same file, F4 (fix): clause 3.12 adds test implementation `u`, which only R-1 registers, and scenarios for an unregistered implementation, a writer's own-`VERSION` refusal, a delayed R-1 write fenced by the epoch, retry after the check, the quorum-loss restart, a region with no group, the first-entry and switch-write order, and an unswitched group without quorum.
- `adr/0059-finalization-covers-new-groups-running-releases-and-re-encoding.md`: rewritten in this task before merge. It records the group record, monotonic write versions, the binding epoch, the start-write skip, and the global group dependency as a consequence. It adds two rejected alternatives. The README row is unchanged.

## Decisions

- N: Each group holds a binding epoch that every binding write names, and only the check increments it (F1). A fence by writer release was rejected because a rollback after a failed check would have its own writes refused.
- N: A regional group exists once a global group write records it. Write versions only move to a newer release (F3, F6).
- N: `alloyd` skips the running release write when node-local state shows that its release was the last one started and written for the node. It rewrites the running release when its node record differs, and `alloy cluster recover` clears all running releases (F2).
- N: The `BuildError::Failed` detail text for an invalid `S::KIND` is fixed to the format the T-0007 implementation uses (F5).

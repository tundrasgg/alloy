## Summary

`agent/protocol/tasks.md` gains a "Shared workspace files" section. The root
`Cargo.toml` `members` list, the root `deny.toml` `[bans] allow` list, and
`Cargo.lock` are shared for tasks that add crates or dependencies: add only, sorted,
one entry per line. The readiness rule leaves them out of the disjointness check.
The lead merges added entries in sorted order, regenerates `Cargo.lock` from main's
copy with `cargo update --workspace`, runs `cargo xtask ci`, and sends anything else back.

## Changes

- `agent/protocol/tasks.md`: readiness bullet now also leaves out the shared workspace files.
- `agent/protocol/tasks.md`: new section "Shared workspace files": which parts are shared, the add-only and sorted-order rule, how a task may touch `Cargo.lock`, what makes a task hold a file exclusively, and the lead's three-step conflict resolution.

## Decisions

- Class N: only the `members` list and the `[bans] allow` list are shared. Any other edit to `Cargo.toml` or `deny.toml` (lints, licenses, `[workspace.dependencies]`), any removal, and any move of an existing locked version holds the file exclusively. Reason: the task scoped only these lists, and other edits are not add-only.
- Class N: `Cargo.lock` is rebuilt from main's copy, not the task's. Reason: main's locked versions are the ones `cargo xtask ci` already proved; only the task's additions get resolved anew, and the CI run right after tests them.
- Class N: both lists are kept one entry per line in ascending byte order; a task may break a one-line list into lines. Reason: the root `members = ["xtask"]` is on one line, so every pair of additions would conflict on that line.

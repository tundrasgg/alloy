## Summary

ARFC 0003 section 3.1 now names the Noise pattern (`IKpsk2`), the empty prologue, the initial `h` padding, the nonce counter byte order (8 bytes little-endian after 16 zero bytes), the psk size, position and all-zero default, and which message fields are Noise message bytes.
Section 3.3 now derives `send_key`, `recv_key` and `salt` by HKDF over HMAC-BLAKE2s from the `Split()` keys `k1 || k2`, salted with the handshake hash `h`. Both are values a Noise library exposes (R-0004: `snow` has `dangerously_get_raw_split` and `get_handshake_hash`).
ADR 0043 records the change. It is indexed under Mesh, and the ARFC's Decisions line names it.
On the two `spec-issue` entries from T-0014: the researcher was right on both.

## Decisions

- N: psk position is `psk2`. A responder picks a per-pair psk by the initiator static key, and it learns that key only by processing message 1. A Noise library processes a whole message per call, so the psk can only be supplied between messages. Under `psk0` or `psk1` the psk would be needed during message 1.
- N: with no psk configured, the psk is 32 zero bytes. This keeps one pattern and one protocol name, and the message layout does not change (ADR 0030 slot kept).
- N: the session KDF is `HKDF-Extract(salt = h, IKM = k1 || k2)`, then three Expands with labels `alloy/al/session-i2r/v1`, `alloy/al/session-r2i/v1` and `alloy/al/session-salt/v1`. The labels follow the rule 6 form in `agent/eng/crypto.md`. Salting with `h` binds the keys to the full transcript. The `Split()` cipher states are never used to encrypt.
- R: the prologue is zero length. The protocol name already binds the version.

## Issues

- `spec-issue`: `spec/arfc-0003-mesh-wire-protocol.md` section 6 allows "one DH per packet when not under load". IK needs two DH operations on the responder for message 1 (`es` and `ss`) and two for message 2 (`ee` and `se`), so the limit as written cannot be met. Out of scope for T-0026.
- `follow-up`: the conformance suite for ARFC 0003 3.1 and 3.3 needs a fixed handshake vector: static and ephemeral keys, a psk, the expected message bytes, and the expected `i2r`, `r2i` and `salt`. Without it, an implementation that swaps `k1` and `k2` or orders the labels differently interoperates only with itself.

External sources used by the findings, fetched for this review:

- https://raw.githubusercontent.com/cloud-hypervisor/cloud-hypervisor/v54.1/vmm/src/landlock.rs:
  `static ABI: ABI = ABI::V3;`. The ruleset handles `AccessFs::from_all(ABI)`
  only, with no scope or socket rights. `restrict_self()` is called with no flags
  and no TSYNC.
- https://raw.githubusercontent.com/cloud-hypervisor/cloud-hypervisor/v54.1/docs/landlock.md:
  Landlock is enabled at the `vm_create` stage. The page says nothing about threads.
- https://raw.githubusercontent.com/cloud-hypervisor/cloud-hypervisor/v54.1/docs/seccomp.md:
  the VMM has separate threads for vCPUs, devices, and the HTTP server. The main
  thread applies its filter "after starting the worker threads and before sending
  initial VM lifecycle requests".
- https://docs.kernel.org/userspace-api/landlock.html: by default the ruleset
  applies to the calling thread and its future children, and it is not applied to
  sibling threads. `LANDLOCK_RESTRICT_SELF_TSYNC` (ABI 8) applies it to all
  threads. `LANDLOCK_SCOPE_ABSTRACT_UNIX_SOCKET` (ABI 6) restricts connecting to
  abstract Unix sockets. `LANDLOCK_ACCESS_FS_RESOLVE_UNIX` (ABI 9) restricts
  connecting to pathname Unix server sockets created outside the domain.

Attack attempts. Nothing could be run against a VMM because the repository has no
code and there is no KVM host, so each attempt was done by reading the sources.

1. Guest compromises the VMM and tries to reach another guest's sockets. Pathname
   sockets are blocked by 2.2, 2.3 and 2.7 (mount view and file modes, both
   per process). Abstract sockets are blocked by the per-guest network namespace.
   No hole found.
2. Guest compromises the VMM and leaves Landlock through a sibling thread. CH
   v54.1 calls `restrict_self()` without TSYNC at `vm_create`, and the HTTP and
   main threads exist before that, so they are outside the Landlock domain. These
   threads share an address space with the confined vCPU and device threads. The
   per-guest user and mount namespace still hold, so this is F1 at `fix`, not
   `block`.
3. Hot attach under a fixed rule set. CH v54.1 handles only ABI V3 filesystem
   rights, so `connect()` to a vhost-user socket made by `alloy-blk` or
   `alloy-net` needs no rule. Clause 2.6 holds for v54.1.

Banned list (`agent/core/4-evidence.md`): the change contains no code. No future

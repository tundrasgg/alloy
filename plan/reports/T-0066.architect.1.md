## Summary

ARFC 0001 clause 3.13 now covers regional groups created at any time, nodes that fall back to `R - 1` before the switch, bindings that cannot be encoded at `V(R)`, and writes that race the switch. Section 5 names the finalization suite.
ARFC 0017 defines "finalized" as the switch and the running release of each node. Clause 3.7 runs the full finalization and refuses the next upgrade until it completes. New clause 3.12 is the finalization suite.
ARFC 0001 section 2.1 adds `Display` for `Kind` and `ImplName`, and `SeamConfig` now requires `Eq`. Clauses 3.10, 3.11, 3.12, and 3.19 state the error precedence and what `instantiate` returns for an invalid `S::KIND`.
ADR 0059 records the behavior changes. ADR 0056 is not edited.

## Changes

- `spec/arfc-0001-runtime-seams.md`: T-0057.reviewer.2 F1 (block). The Write versions bullet now says a regional group's first log entry copies the global group's write versions, read linearizably, and that only the switch changes them afterward. The Switch bullet writes every regional group the global group lists after the switch, and waits for a group that is not created yet. Completion requires every listed regional group to have switched. The Bound bullet holds in every group.
- Same file, F2 (fix). The check begins at a global position where every node's running release is `R`. The switch write names that position and applies only if every running release is `R` at the switch and no other release was written between the two positions. Otherwise finalization reports the node and does not start. An `alloyd` of `R - 1` whose running release was not written before the switch never serves.
- Same file, F3 (fix). The check computes `reencode(value, V(R))`, a decode plus an encode, and stops before the switch on any error, for example `TooLarge`. A new Writing a binding bullet makes every writer also encode at its own release's `VERSION` and refuse what it cannot write there. So a binding that release `R` writes after the check also re-encodes at `V(R)`.
- Same file, F4 (fix). Section 5 now points the stored-binding rules to the ARFC 0017 clause 3.12 finalization suite, not to the mixed-version mode of clause 3.10.
- Same file, F5 (fix). A new bullet covers a write that races the switch: the writer encodes again at the write version the error names and writes once more, once and only for that cause. Section 6 says the caller sees `UnsupportedVersion` only if that second write fails for its version too.
- Same file, F6 (note). The `SeamConfig` bound is now `Sized + Eq`, and its doc comment says why.
- Same file, T-0007 issues. `impl fmt::Display` for `Kind` and `ImplName` writes `as_str()`. Clause 3.10 checks `Empty`, `TooLong`, `InvalidByte`, in that order. Clauses 3.11 and 3.19 check `InvalidKind`, `KindConflict`, `Duplicate`, `Full`, in that order. Clause 3.12: an invalid `S::KIND` returns `BuildError::Failed`, whose detail holds the kind and the `NameError`, and no factory is called. In all three rulings the developer's reading was right, and the spec now states it.
- Same file: `Decisions` lists 0059. Section 6 covers check failures on encoding and refused switches.
- `spec/arfc-0017-upgrades-and-versioning.md`: Clause 3.3 says "finalized" means the switch of ARFC 0001 clause 3.13, and rollback is possible until then. Clause 3.7 makes `--finalize` run the check, switch, and rewrite, report success only at completion, and resume when run again. It also refuses `alloy cluster upgrade` to N+2 and `alloyd` of N+2 until completion. New clause 3.11 defines the running release. New clause 3.12 defines the finalization suite `tests/conformance/upgrade/` with three builds and eight scenarios. `Decisions` lists 0056 and 0059.
- `adr/0059-finalization-covers-new-groups-running-releases-and-re-encoding.md`: new, 39 lines.
- `adr/README.md`: adds the 0059 row under Operations.

## Decisions

- N: `SeamConfig` requires `Eq` instead of `PartialEq` (F6). The follow-up interface task in `plan/STATE.md` that names "the `PartialEq` bound" should use `Eq`.
- N: A write that races the switch is encoded again and retried once, not reported as a retryable error (F5). After the switch, a writer of release `R` can always encode at the new write version.
- N: The global group stores each node's running release next to its node record, outside the signed record of ARFC 0002 section 2, so the record format does not change (F2).
- N: The finalization suite runs three builds of one tree that report releases R-1, R, and R+1, each with a test configuration type, so the rules can be tested before a real previous release exists (F4).
- N: `Registry::instantiate` returns `BuildError::Failed` for an invalid `S::KIND`. The order of name and registration errors is the order clauses 3.10 and 3.11 list them. Both match the T-0007 implementation.

- `follow-up`: `spec/arfc-0017-upgrades-and-versioning.md` will conflict on the `Decisions` line with `task/T-0059`, which sets it to `0029, 0057`. The merged line is `0029, 0056, 0057, 0059`. T-0066 does not edit section 6, so the two section 6 changes do not overlap.
- `follow-up`: The STATE item "ARFC 0017 clause 3.10 names the upgrade conformance suite" should extend `tests/conformance/upgrade/` from clause 3.12, not name a second suite.
- `follow-up`: ARFC 0006 section 2.2 could cross-reference ARFC 0001 clause 3.13 for a new regional group's first entry, and ARFC 0002 section 2 could cross-reference the running release of ARFC 0017 clause 3.11. Neither file was in `touches`.
- `spec-issue`: One case is still handled only by the existing fallback. A binding write proposed by an `R - 1` process before the check began, and applied after the check read its group, is not checked. If the rewrite then cannot replace it, it is reported and finalization stays incomplete until the resource is rebound or deleted (clause 3.13 Completion). Closing it fully would mean groups refuse binding writes from releases older than `R` during the check, which this task did not decide.

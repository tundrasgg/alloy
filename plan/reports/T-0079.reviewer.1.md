Under D-0006, a task that adds a dependency lists `Cargo.toml`, `Cargo.lock`, and `deny.toml`. Here that is no longer enough. If the crate is `alloy-wire`, the gate also needs `fuzz/Cargo.lock`. The `fuzz` step has `hint: None` (`xtask/src/main.rs`, `CI_STEPS`), so the failure does not name that file. See F1.

Workflow logic, by reading. The workflow runs only on `push` to `main` and on `pull_request` (`ci.yml:6-9`), so free-form task branch commits are never checked. A push always gets `--commits "$BEFORE..$GITHUB_SHA"`. `--base`/`--branch` are added only when `BEFORE` is not all zeros, which is the old behaviour. `commit_range` passes the range to `git merge-base --is-ancestor` as plain arguments. A `from` that git rejects, such as one starting with `-`, counts as not an ancestor, so the range falls back to the cut. After a forced update that rewrote history before `5429bb9`, `5429bb9..<sha>` also lists the rewritten older commits. The check then fails loudly instead of passing.

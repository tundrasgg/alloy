## Decisions

- Stream derivation (class N): each random stream's 256-bit state is the BLAKE3 hash, through `alloy_crypto::Hasher`, of a length-prefixed encoding of the domain `alloy-sim/stream/v1`, the seed, a purpose label, and place ids (for example host and start). Values come from xoshiro256**, checked against the reference outputs for state 1, 2, 3, 4. Labels in use: `schedule` (task pick and the order of simultaneous events) and `scenario` (`random_u64`). T-0076 and later add host, router, and link streams through the same function. Reason: ARFC 0005 clause 3.1.5 asks for distinct streams per host, start, and instance; a 256-bit derived state makes accidental repeats negligible, and adding a stream never shifts another. The output is not secret (section 8). The R-0001 estimate suggests xoshiro or PCG.
- Simultaneous world timers are woken in an order shuffled by the `schedule` stream, then picked by the same stream (clause 3.2.2). Routine.
- A panic in the `scenario` function itself, before a control task exists, counts as a control task panic: `fail` at world time 0. The ARFC names only the control task's panic. Routine.
- Between an observer panic and `run-end`, world calls that return a `Result` return `Ended` and no record but `run-end` is written. Clause 3.2.7 says the run has ended at the panic and the next record is `run-end`. Routine.
- Buffered trace file bytes are flushed before the result is fixed, so a write error among them makes the run `fail`. A write error in the `run-end` record itself cannot change the result, which clause 3.2.8 fixes when that record is written. Routine.
- The failure line escapes `\n` and `\r` in the failure text, so it stays one line (section 6). Routine.
- `World`'s `Debug` prints `World { now: <duration>, hosts: 0 }`. Hosts arrive in T-0076. Routine.

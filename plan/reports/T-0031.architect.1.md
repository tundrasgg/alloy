## Decisions

- Probe messages carry a 16-byte challenge and an echo. A challenge goes in an answer only when it answers a probe from an unverified endpoint, which bounds an exchange at three messages. Reason: a reply plus a separate probe is 2 packets per received packet, and allowing challenges in answers to answers can loop without end between two sides with address-and-port-dependent mapping and endpoint-independent filtering. I traced this by hand and did not run it: each answer leaves from a new mapping that the other side has not verified. ADR 0039, corrected on the branch.
- Unverified endpoints are answered only while probing the sender, from the first round until 1 s after the fifth. Repeats under 3.4 are signaled so both sides probe at once. Reason: this bounds a replayed probe in time, and without signaling, repeats with independent backoff would not overlap.
- Home session keepalive after 5 s idle. Reason: half the lab's 10 s minimum timeout, at a cost of at most 0.4 packets per second per node. ADR 0045.
- The lab filters per mapping, and a new mapping never reuses another mapping's external port. Reason: section 3.3's classes depend on both, ARFC 0005 was silent on them, and both models (the reviewer's and this one) assumed them.
- Defined probe set and probing in 3.2 step 3. This also answers the reviewer's follow-up on section 7's "8 concurrent probe sets per peer".

## Issues

- `spec-issue`: `spec/arfc-0003-mesh-wire-protocol.md` section 3.6 must define the plaintext bytes of probe messages: challenge (16), echo (16), a fixed unpadded length, and padding for path MTU probes, as ARFC 0004 section 3.2 step 4 now requires. ARFC 0003 was outside this task's `touches`.
- `spec-issue`: probes have no replay check (`spec/arfc-0003-mesh-wire-protocol.md` section 3.6, no counter), while `spec/arfc-0020-security-model.md` section 3.2 says an underlay attacker must not replay mesh traffic. This was already true on main. ARFC 0004 section 8 now bounds the effect to one answer of at most the same size during probe sets. Closing it fully needs a counter or a per-probe-set token in ARFC 0003.
- `follow-up`: `spec/arfc-0004-path-manager.md` section 3.4 starts a probe set immediately when either side's candidates change, with no rate bound. A compromised node that keeps changing its advertised candidates can make peers send probe rounds to a third party again and again.
- `follow-up`: `spec/arfc-0004-path-manager.md` section 3.4, last bullet. An authenticated packet from a new source moves the return path at once, so an underlay attacker that drops a fresh transport packet and reinjects it with a spoofed source can redirect data to a third party. The review did not raise this.
- `follow-up`: behavior changed in ARFC 0004 sections 3.2 to 3.4 and ARFC 0005 section 3.4. The NAT models (T-0011), the matrix (T-0012), and conformance suites for the new musts need recutting: answer count and size, the probing window, challenge placement, the 2 s challenge lifetime, the 64 outstanding challenge limit, and the 5 s home keepalive.

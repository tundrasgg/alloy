- F1: ARFC 0001 lines 502-505 (Binding epoch), 512-519 (a write naming an old epoch fails with `Conflict`), 531-550 (the check increments the epoch in each group recorded at `P`, then reads after that write). The round 1 Attack 1 trace now ends with B refused with `Conflict`. Its proposer exited at the upgrade, so there is no retry. Resolved.
- F2: ARFC 0017 lines 77-107. A restart at the same release and a view resume write nothing. The remaining dependency is stated as the one exception to ARFC 0006 clause 3.9, and ADR 0059 Consequences records it. Editing ARFC 0006 is outside `touches` and is a follow-up in the architect report. Resolved.
- F3: ARFC 0001 lines 481-486. A region with no recorded group is not waited for. A recorded group that refuses the switch write is reported with its region (lines 579-585, section 6). Resolved.
- F4: ARFC 0017 lines 124-126 (own-`VERSION` refusal) and 120-123 (implementation `u`). Resolved for the two rules named. See F1 below for the rules added in this round.
- F5: ARFC 0001 lines 438-445 fix the detail text, which holds after truncation. Resolved.
- F6: ARFC 0001 lines 488-492. Write versions only move forward, so the first entry and the switch write commute. Resolved.

Attack 1, an `R - 1` writer that retries on the epoch `Conflict`, by trace. The race rule (ARFC 0001 lines 520-525) lets any writer retry once after an epoch `Conflict`, re-reading the new epoch. For the retried write to land after the check, the `R - 1` writer has to be alive after `P`. At `P` every running release is `R`. ARFC 0017 lines 82-84 set the started release before anything else, and a write of `R` for a node comes only from an `alloyd` of `R` that started on that node. So an `R - 1` `alloyd` alive after `P` either wrote `R - 1` after `P`, which refuses the switch (lines 551-557), or it runs at the same time as an `R` `alloyd` on the same node. ARFC 0017 clause 3.5 replaces and restarts `alloyd`, so the second case is outside the spec. No finding.

Attack 2, the skip-write rule against fallback and crashes, by trace over ARFC 0017 lines 77-98. (a) `R` starts and sets started `R`. Its write is pending when it crashes. The fallback `R - 1` reads started `R` and must write. (b) The write is applied, but `R` crashes before it sets applied. The next `R` reads applied `R - 1` and writes again. (c) After the switch, `R - 1` reads `(R, R)`, writes, and is refused. In each case, skipping the write needs node-local `(X, X)` while the global record holds `X`. Only `alloy cluster recover` breaks that agreement, and it can only clear the record. See F2 below. No other finding.

Attack 3, suite coverage of the rules added in round 2, by reading ARFC 0001 section 5 (lines 753-757) against ARFC 0017 clause 3.12 (lines 109-155). Groups, binding epoch, and the race rule are assigned to the suite. These rules have no scenario:
- A group that holds no write versions refuses binding writes with `Unavailable` (line 498).
- Errors come in the order `Unavailable`, `Conflict`, `UnsupportedVersion` (lines 515-519).
- A retry happens once and only for those causes, and a stale-`generation` `Conflict` goes to the caller unchanged (lines 525-526).
- The check stops before the switch when a group recorded at `P` cannot be written or read (line 536).

The only scenario with a group that has lost quorum is after the switch (lines 145-147).

Attack 4, a lossy recover that loses the switch, by trace. ARFC 0006 clause 3.11 rebuilds a one-voter group from one node's state "and must print what may have been lost". Suppose the global group is recovered from a node that lacks the switch for `R`. Regional group `west` has already switched (write versions only move forward, ARFC 0001 lines 488-492) and stores a binding at `V(R)`. The global group records `R - 1` as finalized again. ARFC 0017 clause 3.3 (line 41) then allows rollback to `R - 1`, and the running release write of `R - 1` is not refused (lines 87-88). An `alloyd` of `R - 1` in `west` cannot decode a binding at `V(R) > V(R - 1)`, which contradicts the Bound bullet (ARFC 0001 line 611). Round 2 handles recover only for running releases (ARFC 0017 line 96).

## Summary

Reviewed `task/T-0057` at 17249c4. `cargo xtask ci` passes, the diff stays inside `touches` plus the architect's report, and the branch merges cleanly with main.
The new clause 3.13 closes the T-0006 F1 trace for upgrades that finalize completely: a binding written at `V(R - 1)` is rewritten to `V(R)` before the upgrade to `R + 1` can start.
No `block` findings. Four `fix` findings: the new span between the start and the completion of finalization lets release `R` run against bindings already at `V(R + 1)`; the rewrite is not specified against concurrent writers; nothing in the `alloy-seam` interface lets the control plane run the rewrite or the identity rule for an arbitrary binding; a cluster initialized at `R` has no "upgrade to `R`" to finalize.
Two `note` findings.

| F1 | fix | `spec/arfc-0001-runtime-seams.md:428-457` | Clause 3.13 makes finalization a span that can stay incomplete indefinitely, but does not refuse release `R` during that span, and release `R` cannot decode bindings already rewritten to, or written at, `V(R + 1)`; the Writing bullet also contradicts the Rewriting bullet on which version writers use during that span. | Attack 1 trace above; ARFC 0017 clause 3.3, section 6, section 8; ADR 0029 ("Rollback is possible until finalization"). | Clause 3.13 states what holds between the start and the completion of a finalization: either no node may run release `R` from the start of finalization (rollback and binary fallback refused), or nothing is written at `V(R + 1)` until completion; and the Writing and Rewriting bullets name the same switch point. |
| F2 | fix | `spec/arfc-0001-runtime-seams.md:433-443` | The rewrite is not specified as conditional on the stored binding being unchanged since it was read, so it can overwrite a concurrent binding change, and "none does" after completion is asserted without a rule that stops a writer from storing `V(R - 1)` after the switch. | Attack 2 trace above; line 444 ("A rewrite is not a binding change"); line 439. | Clause 3.13 states that a rewrite replaces a stored binding only if it is still the value that was read, and that after the switch the control plane refuses to store a binding at a version other than `V(R)`. |
| F3 | fix | `spec/arfc-0001-runtime-seams.md:433-447` | The rewrite and the binding identity rule need, for an arbitrary stored binding, its implementation's `VERSION`, `from_value`, `to_value`, and configuration equality, and the `alloy-seam` interface provides none of these by kind and name; the derived `Binding` equality compares bytes and contradicts the identity rule. | Attack 3 above; section 2.1 lines 181-189, 212-216, 264-277; ARFC 0001 section 2.1 ("the crate's whole public interface"). | The spec names where the control plane gets each implementation's `VERSION`, decoder, encoder, and configuration equality by kind and name, and `Binding` equality agrees with the identity rule or the rule names the comparison the control plane uses instead. |
| F4 | fix | `spec/arfc-0001-runtime-seams.md:428-430, 448-450` | A cluster initialized at release `R` has no "upgrade to release `R`", so the Writing bullet does not say whether it writes `V(R - 1)` or `V(R)`, and the Ordering bullet read literally forbids it from ever upgrading to `R + 1`. | Clause 3.13 Writing and Ordering bullets; Attack 4 (ARFC 0017 defines no initial upgrade state). | Clause 3.13 states the state of a newly initialized cluster, for example that it is as if the upgrade to its first release were finalized. |
| F5 | note | `spec/arfc-0001-runtime-seams.md:424-426` | The clause no longer requires `V(R) >= V(R - 1)`, which the Writing bullet needs: if a release lowers `VERSION`, its own `to_value(V(R - 1))` returns `UnsupportedVersion` and it cannot decode what release `R - 1` stored. | The removed text ("A release that raises `VERSION` from `p` to `p + 1`"); clause 3.13 first paragraph (`to_value` is defined only from `MIN_VERSION` to `VERSION`). | Clause 3.13 states that `VERSION` never decreases from one minor release to the next. |

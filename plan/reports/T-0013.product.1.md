## Decisions

- The initial admin credential is a one-use login code that carries the API endpoints and the CA fingerprint. Logging in pins the certificate with no trust-on-first-use prompt and exchanges the code for an access key per computer. This needs ARFC 0007 to let users hold access keys. Reason: login takes one command with no prompts or required flags, and the CA is pinned safely.
- Root on a control node acts as a local admin through `alloyd`, and every such action is audit-logged. It is the recovery path for a lost login code and for an anchor whose address changed. Reason: root there already holds the cluster key, which ARFC 0020 §2.2 trusts. The architect must confirm this.
- A joiner without preset roles defaults to `compute,storage`. It does not become an anchor automatically. Reason: an anchor is exposed to unregistered sessions, so that should be the user's choice. The single anchor warning gives the command to add one.
- Proposed default mesh port: UDP 7270. API and stream fallback share TCP 443 through ALPN. Reason: no ARFC fixes the mesh port. The architect must confirm 7270 is unassigned.
- Join tokens and login codes get a checksum so a mistyped string is rejected locally and does not count as a use. Reason: ARFC 0002 §6 counts every wrong secret as a use and audit-logs it.

## Issues

- `spec-issue`: ARFC 0002 §3.1 requires `--advertise` and does not define the form of the admin credential. §3.3 sets no default roles for a joiner, no version check, no behavior for a machine that is already joined, and no approve command. See `product/briefs/PB-0001.md`, Requested design changes.
- `spec-issue`: no ARFC sets a default AL mesh port, and ARFC 0008 §3.8 and ARFC 0004 §3.6 both claim TCP 443 on an anchor that is also a control node, with no rule for sharing it (`spec/arfc-0008-native-api.md`, `spec/arfc-0004-path-manager.md`).
- `spec-issue`: under ARFC 0007 §2.2, users authenticate only with a password and second factor or an identity provider. PB-0001 needs users to also hold access keys created by `alloy login` (`spec/arfc-0007-tenancy-and-iam.md`).
- `follow-up`: the download host in `install.sh` is a public name that is costly to change, so it is a class P decision for the pilot. PB-0001 uses `<download-host>` until it is decided.
- `follow-up`: `alloy pool update default --copies 2` in the init output is a placeholder until a pool brief fixes its wording.
- `follow-up`: architect task to turn PB-0001 into changes to ARFC 0002, 0019, 0008, and 0007, including an ARFC 0020 check of the local admin path.

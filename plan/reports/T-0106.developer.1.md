## Summary

`alloy-crypto` gains Ed25519, ECDSA P-256 with RFC 6979, X.509 certificates through `rcgen`, and XChaCha20-Poly1305 for data at rest. The new crate `alloy-id` holds ids, keys, node records, join tokens, infrastructure addresses, the API CA, the data directory rules, and the stored data of sections 3.12 and 3.14.
The data directory rules are pure checks over facts the OS reports. The `disk-io` seam cannot read an owner, a mode, or an ACL, and cannot set them when it creates something. Gathering those facts and creating the directory with its ACL wait on `alloy-rt` (see Issues).
Size: about 3,200 product lines (half of them doc comments) and 2,100 test lines, against a 2,000-line target. The scope was not cut.

## Changes

- `crates/alloy-crypto/src/{ed25519,ecdsa,x509,aead}.rs`: Ed25519 (strict verify), P-256 (RFC 6979, PKCS#8, 91-byte SPKI, RFC 7093 key id), the CA and server certificate profiles, and the AEAD with a caller-chosen nonce.
- `crates/alloy-crypto/src/tests/identity.rs`: RFC 8032 vectors 1 to 3, RFC 6979 A.2.5 vectors, the XChaCha draft vector, bit-flip refusal, and exact extension sets for both certificate profiles.
- `crates/alloy-crypto/src/lib.rs`, `al/keys.rs`, `al/mod.rs`, `al/noise.rs`: module docs, a `Zeroizing` re-export, `StaticSecret::to_bytes`, the erasure limit, and the HMAC/HKDF ruling.
- `crates/alloy-crypto/Cargo.toml`: `ed25519-dalek`, `p256`, `rcgen` (default features off), `sha2`, `time`.
- `crates/alloy-id/src/{ids,keys,record,token,base32,api,datadir,store,proto,lib}.rs`: the crate. The `lib.rs` docs list its interface.
- `crates/alloy-id/src/tests/*.rs`: tests for tokens, records, and the data directory on Linux and Windows.
- `crates/alloy-id/tests/{store,api}.rs`, `tests/common/mod.rs`: simulator tests for stored data, crash and rotation, and the API CA.
- `Cargo.toml` (member), `Cargo.lock`, `deny.toml` (36 allow entries).

## Decisions

- N: the public interface of `alloy-id` is the one its `lib.rs` lists: `ids`, `keys`, `record`, `token`, `api`, `datadir`, `store`, and `proto`, with the re-exports there.
- N: new dependency versions are pinned in the crate manifests (`alloy-crypto`, `alloy-id`), not in `[workspace.dependencies]`. This keeps the root `Cargo.toml` change to the shared `members` list while T-0107 and T-0109 add dependencies in parallel.
- N: `prost` 0.14.6 is used through `#[derive(Message)]` on hand-declared structs, with no build script and no `protoc`. `alloy-id` sits above `alloy-proto` in `plan/workspace.md` and cannot depend on it.
- N: HMAC and HKDF stay composed in `alloy-crypto`. `hmac` 0.13.0 keeps `opad_key` with no erasing `Drop`, and `hkdf` 0.13.0 keeps the PRK in that state, which ARFC 0003 section 3.3 forbids. Recorded in `al/noise.rs`. Both stay dev-dependencies as test oracles (T-0085 F1).
- N: moved-from key copies are not erased. Rust cannot erase compiler copies. The limit is stated in `al/mod.rs` under Erasure (T-0085 F2).
- R: a node record is refused on decode for a `node_id` that is not BLAKE3 of `identity_pub`, for other than 1 or 2 mesh keys, for roles that are unknown, unsorted, or repeated, for a name not 1 to 63 bytes or a zone over 63, for more than 16 advertise addresses, and for a port over 65535.
- R: the CA certificate's `not_after` is the same date 10 calendar years later. 29 February becomes 28 February.

## Issues

- `follow-up`: `alloy-rt` `disk-io` (ARFC 0005) has to report an owner uid and mode, `lstat` kind, and a Windows owner, DACL, and reparse flag, to fill `alloy_id::datadir::DataDirFacts`. It also has to create directories and files with mode 0700/0600 or a protected DACL in the creating call (section 3.12). Today files get the umask mode.
- `follow-up`: `alloy-rt` `os` rename on Windows uses `std::fs::rename`. Section 3.14 names `MoveFileExW` with `MOVEFILE_WRITE_THROUGH` (`crates/alloy-rt/src/os/disk.rs` line 214).
- `follow-up`: `alloy-proto` (T-0109) will define the same `alloy.node.v1alpha1` messages. Once the crate order allows it, one definition should serve both crates (`crates/alloy-id/src/proto.rs`).
- `process-issue`: the task's scope (four primitives, seven `alloy-id` modules, and two platforms of data directory rules) came to about 5,300 lines against a 2,000-line target. A split into crypto, records and tokens, and data directory work would fit.

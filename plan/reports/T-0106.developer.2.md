## Summary

Round 2 on `task/T-0106`, with main merged in (the `alloy-link` member resolved beside `alloy-id` in `Cargo.toml`, `Cargo.lock`, and `deny.toml`). F1 and F2 are fixed. F3 and F4 are not: both are rules of the `alloy-rt` `disk-io` seam, which is outside this task's `touches`, and the spec work for them is T-0117. `DataDir::write` now states that limit.

## Changes

- F1 `crates/alloy-id/src/datadir.rs`: `only_admins` refuses every allow entry for a principal other than `SYSTEM` or `Administrators`, inherit-only or not, on the data directory and on the host file. The ancestor rule still counts only entries that apply to a directory itself, as section 3.12 says.
- F1 `crates/alloy-id/src/tests/datadir.rs`: refusal cases for an inherit-only `Users` read entry (the reviewer's attack), an inherit-only `CREATOR OWNER` entry with no rights, and an inherited `Users` entry on the host file.
- F2 `crates/alloy-crypto/src/x509.rs`: `certificate_request` and `RequestName` build the PKCS#10 CSR (RFC 2986) of an ACME order through `rcgen`, signed by the API server key through the RFC 6979 signer. The subject is empty, and an extension request carries one critical subject alternative name extension of `dNSName` and `iPAddress` entries (RFC 5280 section 4.2.1.6).
- F2 `crates/alloy-crypto/src/tests/identity.rs`: the CSR's exact encoding, its determinism, its signature, refusal of every flipped bit of the signed part, and refusal of no names or a non-ASCII DNS name.
- `crates/alloy-crypto/src/lib.rs`: the module docs name the CSR.
- F3, F4 `crates/alloy-id/src/store.rs`: not fixed. The `DataDir::write` docs state that the umask mode on Linux and the `std::fs::rename` on Windows are the seam's, citing T-0117.
- `Cargo.toml`, `Cargo.lock`, `deny.toml`: merge of main, both members kept.

## Decisions

- N: `alloy_crypto::x509::certificate_request(key, &[RequestName])` joins the public interface. The CSR has an empty subject and names its identifiers only in the subject alternative name extension, so one form serves `dns` and `ip` ACME identifiers.
- R: an allow entry with an empty mask for another principal is refused too, so the rule reads "no allow entry for anyone else" with no exceptions to reason about.

The attacks below used a scratch integration test, `crates/alloy-wire/tests/review_attack.rs`, which was deleted afterwards and never committed. It contained:

1. `exhaustive_three_bytes`: every 3-byte input (2^24) on VNI 0 and VNI 7, checked through `InnerFrame::decode` and `InnerFrame::decode_reassembled`. An independent oracle written from the 3.4 table and the 3.5 drop rules decides whether each input should be accepted. Every accepted frame must re-encode to the same bytes.
2. `random_frames_and_transport`: 5,000,000 random frames of 0 to 23 bytes on VNIs 0 to 2, biased toward the kind bytes `0x00 0x10 0x20 0x45 0x60 0x01 0x11 0x21`, control types 0 to 3, and fragment index and count 0 to 17, all checked against the same oracle. Each iteration also builds a random transport packet of 0 to 39 bytes: `Transport::decode` and `Message::decode` must accept exactly when the first byte is 4 and the length is at least 26, and the header fields and ciphertext must be the right slices.
3. `counter_against_independent_model`: 2,000,000 `(wire, H)` pairs, with `H` drawn from none, edges ±2 (0, 2^31, 2^32, `u64::MAX` - 2^31, `u64::MAX`), values below 2^31, and arbitrary values, and `wire` drawn at random or near `e` and `e + 2^31`. Each pair is checked against a brute-force search over `k` in -3 to 3 for the one `c` with `e - 2^31 < c <= e + 2^31`.

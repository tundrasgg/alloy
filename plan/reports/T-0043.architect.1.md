## Summary

ARFC 0004 sections 3.1, 3.2 to 3.6, 7 and 8 are revised, and ADR 0049 records the decision; ADR 0039 stands. F1: a peer-reflexive candidate is never sent an unpadded probe, which keeps ADR 0039's counts. F2: no packet moves where a node sends until the endpoint is verified, anchors included, and section 8 lists every packet that may go to an unverified endpoint. F3: `usable` means the node verified the far endpoint and received a transport packet from it. F4: the layered reduction has one reading. F5: the 5 s bound states its delays. Probe sets are capped at 2 per 5 s and 20 per 5 min per peer. A new model agrees with the rule on all 81 single and 7,290 layered cases and on R-0003's 144 preset pairs.

How each item is resolved:

- F1 (block): the reviewer was right that the text allowed both readings. Section 3.2 step 6 now says a node never sends an unpadded probe to a peer-reflexive candidate, in the probe set that verified it or any later one. Step 7 limits unpadded probes to advertised candidates. That is the reading under which ADR 0039's counts hold (34 of 81, 55 of 144, 0 layered mismatches above), so ADR 0039 is not superseded. Padded probes reach a peer-reflexive endpoint only after the path is usable, so they cannot change the class.
- F2 (block): the reviewer was right. Section 3.4's move to any new source is gone. A node sends session traffic only on its active path, and only to verified endpoints. A transport packet from an unverified endpoint starts a signaled probe set within the bound, so a real NAT rebinding is re-verified in under 0.6 s (`rebind fresh`). Anchors follow the same rule: they verify a homed node's endpoint through its reflection requests, which a node sends at least every 25 s (3.1.1, 3.1.2). Section 8 now lists every packet a node may send toward an unverified endpoint: unpadded probes to advertised candidates within the bound, answers one for one and no larger, and handshake responses and cookie replies one per initiation and smaller (ARFC 0003 section 3.1). A reinjected transport packet sends 0 packets to V.
- F3 (fix): `usable` (step 8) is now verified far endpoint plus a transport packet received from it. Both are local observations. Transport goes only to verified endpoints, so receiving one shows that the peer verified this node. Confirmation keepalives make sure each side receives one. In the reviewer's ('AD','EI','AD','AD') trace, X verifies Y' and sends keepalives, Y never verifies X', and neither side becomes usable: the pair is relayed, matching section 3.3.
- F4 (fix): the reduction is now a list. The inner layer's filtering counts as EI, under the stated condition, before the stricter of the two values is taken. Agreement is 0 of 7,290 mismatches above; the other reading still gives 22.
- F5 (note): the 5 s bound states its assumption (signal within 750 ms, one-way at most 500 ms) and what happens beyond it.
- Probe set rate: at most 2 per peer in any 5 s and 20 in any 5 min, whatever the trigger. Triggers beyond the bound coalesce into one deferred, signaled set. A set started on a signal is not signaled back. Section 7 replaces "8 concurrent probe sets per peer", which this bound makes unreachable.

## Decisions

- ADR 0049 (new decision, behavior change): only answers, bounded unpadded probes, and handshake replies reach an unverified endpoint. `usable` is local verification plus a received transport packet. A packet from an unverified endpoint starts a probe set and never moves where a node sends. Anchors verify homed endpoints. Probe sets per peer are capped. Reason: the model gives ADR 0039's classes with no `mixed` outcomes, and 0 packets to a spoofed source.
- Peer-reflexive candidates are never probed without padding (F1), instead of probing them and widening section 3.3 by 6 single and 244 layered cases. Reason: the task prefers ADR 0039's counts, and a wider class set would need a new rule, matrix, and ADR.
- A node sends a reflection request on each home session at least every 25 s and when its local candidates change. Reason: the anchor's only way to verify a rebound endpoint without sending anything else toward an unverified one. It also keeps the reflexive candidate current. Cost: 2 packets per home session per 25 s.
- A change of candidates now starts a probe set on a direct path as well as on a relay. Reason: after a NAT rebinding where the peer filters by address and port, nothing else reconnects the path before the 75 s failure rule. In the `rebind fresh` model all 170 runs recover; under `stale` 65 do not within 10 s.
- A direct path that becomes usable in a probe set started by a candidate change or an unverified source becomes active at once, without hysteresis. Reason: otherwise traffic stays on the dead endpoint until the 75 s failure rule.
- The 5 s direct bound assumes a signal delay of at most 750 ms and a one-way delay of at most 500 ms, and does not widen the probing window. Reason: a longer window lengthens the time a replayed probe is answered, and the stated delays cover the model with margin.

## Issues

- `follow-up`: behavior in ARFC 0004 sections 3.1 to 3.6 changed again. The NAT models (T-0011), the matrix (T-0012), and conformance suites need the new musts: no unpadded probe to a peer-reflexive candidate, transport only to verified endpoints, confirmation keepalives, the `usable` condition, the unverified-source trigger, the probe set bound with deferral, the reflection request schedule, and the anchor send rule.
- `follow-up`: `spec/arfc-0005-simulator-and-natlab.md` section 3.4 does not state the link delays the matrix scenarios use. The direct time bound holds only within ARFC 0004 section 3.2's stated delays (signal 750 ms, one-way 500 ms), so the matrix should use delays inside them.
- `spec-issue`: `spec/arfc-0003-mesh-wire-protocol.md` section 3.6 must let an anchor's reflection answer carry the observed source endpoint and a challenge (ARFC 0004 section 3.1.1). T-0038 owns the probe bytes.
- `spec-issue`: `spec/arfc-0004-path-manager.md` section 3.1.2 says an anchor's verification of a homed node lasts while the home session is open, but no spec says when an anchor considers a home session closed. Until one does, an anchor's traffic to a node that has gone away is bounded only by that undefined close.
- `follow-up`: the probe set bound in `spec/arfc-0004-path-manager.md` section 3.4 is per peer. A compromised node with sessions to many nodes can make each of them send up to 20 probe sets per 5 minutes toward the third party it advertises. A per-node cap on probes toward unverified advertised candidates would bound the total. Not done here, because it limits honest re-probing after a network change and needs a number from the session limit.

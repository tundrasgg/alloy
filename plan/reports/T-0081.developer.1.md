## Summary

The four `alloy-wire` fuzz targets build against the compact layout of T-0064, and each ran for 66 seconds with no finding. `inner_frame` takes its VNI from the first 3 input bytes and now also covers `InnerFrame::decode_reassembled`, which answers the T-0064 reviewer follow-up. The seeds were regenerated.
Review finding F1 of T-0064 is fixed. The `reconstruct_counter` doc now gives the true overflow condition, and a new unit test pins it.

## Changes

- `fuzz/fuzz_targets/inner_frame.rs`: reads the VNI from 3 little-endian bytes and passes it to `InnerFrame::decode`. A decoded frame must have a kind carried on that VNI and re-encode to the same bytes. `decode_reassembled` must return exactly what `decode` returns, except `KindNotReassemblable` for a keepalive or fragment.
- `fuzz/examples/write_seeds.rs`: uses the current API (`WireCounter`, a header with no queue, `InnerFrame` enum, `Control`, `IpPacket`, a fragment with no inner kind). Inner frame seeds get the VNI prefix. The shortest transport seed is now 26 bytes. Each target's seed directory is emptied before it is written, so seeds in an old format do not stay behind.
- `fuzz/seeds/inner_frame/*`: `keepalive`, `bind_request`, `bind` (VNI 0), `fragment`, `ipv4` (VNI 0x123456), `ipv6` (VNI 0); `control` removed.
- `fuzz/seeds/message/transport_shortest`, `transport_longer`: the 9-byte header. The handshake and payload seeds have not changed.
- `fuzz/README.md`: the `inner_frame` row names both decoders and the VNI prefix.
- `crates/alloy-wire/src/counter.rs`: F1. The doc now says `None` is returned when `c` is above `u64::MAX`, which happens only when `H` is at least `u64::MAX - 2^31`. The new unit test `overflow_only_within_2_31_of_the_top` checks both sides of that boundary and the reviewer's case (`wire` 0, `H` = `u64::MAX - 1`).

Diff: 113 insertions and 36 deletions over 13 files. 92 of the insertions are in `fuzz/`, and the binary seeds are not counted.

## Decisions

- R: no fuzz target for `reconstruct_counter`. It cannot panic on any input. All of its arithmetic is in `i128`, on values below 2^65 in magnitude: `expected` is at most 2^64, `wire` is below 2^32, and the offset is in -2^31 to 2^32. `rem_euclid` has the constant positive divisor 2^32, so it cannot divide by zero or overflow. The final step is a checked `u64::try_from`. The input space is two integers and is already covered by unit tests at every edge and by three property tests against a brute-force model (`crates/alloy-wire/tests/properties.rs`).
- R: `decode_reassembled` is fuzzed inside the `inner_frame` target, checked against `decode` on the same input, and not in a target of its own. It is `decode` plus a kind filter, so one target checks both decoders and the relation between them.
- R: `write_seeds` empties each target's seed directory before it writes, so a renamed or removed seed (here `inner_frame/control`) does not stay behind.

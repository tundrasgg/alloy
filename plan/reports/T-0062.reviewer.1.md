## Issues

- `follow-up`: the first crate that adopts `proptest` (the T-0054 follow-up, `crates/alloy-wire/tests/properties.rs`) must set a fixed `rng_seed` and print it on failure. The declared features leave the default `RngSeed::Random` from OS entropy in place, and `agent/eng/rust.md` (Determinism: "No unseeded randomness") and `agent/eng/testing.md` ("A failure prints its seed") bar it.
- `process-issue`: `agent/eng/deps.md` says the standing choices are settled ("see the ADRs"), but no file in `adr/` names `thiserror` or `proptest` (`grep -rli "thiserror\|proptest" adr` finds nothing). The same file requires a research note for each added crate, and none exists in `research/` for these 22 crates. That rule could not be met inside this task's `touches`. Either the ADRs get written, or the rule says that a standing choice and its tree are exempt.
- `process-issue`: main at `b1c22c1`, where this review branch starts, fails `cargo xtask check-repo` with `plan/tasks/T-0053.md:12: front-matter: reads names plan/reports/T-0051.developer.1.md, which matches nothing, and the task is active`. This is the failure the T-0062 developer reported for its own task file. A task's `reads` should exist on main before the lead commits its dispatch.
- `process-issue`: concurrent role sessions on this harness share one scratch directory (`.claude/harness.md` says nothing about it). A fixed log name (`ci.log`) used by this review was overwritten at the same moment by another worktree's CI run, and that output showed a different worktree's crates. It cost one rerun, and it could make a report quote another branch's output. Each role should put scratch files under a task-specific subdirectory.

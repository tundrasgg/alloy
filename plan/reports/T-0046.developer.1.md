## Summary

D-0017: a root `clippy.toml` bans, by `disallowed-methods` and `disallowed-types`, every item the old `direct-io` text list covered, and the `clippy` step of `cargo xtask ci` now passes `-D clippy::disallowed_methods -D clippy::disallowed_types`.
A Clippy fixture workspace (`xtask/tests/fixtures/clippy/`, real tokio 1.54.1 and rand 0.9.5) shows a grouped import, a renamed and a glob import, a `macro_rules!` call, `#[tokio::main]`, `#[tokio::test(flavor = "multi_thread")]`, and `try_from_os_rng` rejected in `demo`, and nothing in `alloy-rt` or `alloy-sim`, which opt out with a crate-level `allow`.
Clippy sees the `#[tokio::main]` and `#[tokio::test]` expansions, so no text check for them is kept. It does not see a unit struct used as a value (`rand::rngs::OsRng.try_next_u64()`), so `OsRng` and `SysRng` stay text patterns. All other text patterns are gone. In their place, `direct-io` rejects an `allow` or `expect` of the ban lints outside the two crates, and any Clippy config file other than the root one.
T-0042 F1: a test attribute on a field, match arm, or statement now ends at its `,` or `;`, or at the bracket that closes around it. T-0018 F1: any line git reads as a trailer (`Key:value`, `Key : value`) is a trailer. F2: the period check ignores trailing whitespace.

Clippy behavior, observed in scratch crates against tokio 1.54.1 and rand 0.9.5 with clippy 0.1.100:

- A grouped `use` is not reported at the `use` line, but every call through it is.
- A `#[tokio::main]` or `#[tokio::test]` expansion is reported. tokio-macros spans the builder call with the user's tokens, so the span does not count as an external macro.
- `rand::rngs::OsRng.try_next_u64()` and `let r = OsRng;` are not reported. Only the `use` line is. Hence `IO_VALUES`.
- These source attributes switch the lints off despite the command-line `-D`: `#[allow(clippy::style)]`, `#[allow(clippy::all)]`, `#[cfg_attr(all(), allow(clippy::disallowed_methods))]`, and `#[expect(clippy::disallowed_methods)]`. `#[allow(warnings)]` does not, and neither do `[lints.clippy] disallowed_methods = "allow"` and `style = "allow"` in a crate's `Cargo.toml`, so `BAN_LINTS` lists exactly the first set.
- An unresolvable path is a non-lint warning ("does not refer to a reachable function"), which `-D warnings` does not deny.

## Decisions

- xtask opts out of the Clippy ban with a crate-level `allow` and a reason. It is the build tool, not under `crates/`, and it must run cargo and git. The old text rule never scanned it.
- `tokio::runtime::Builder`, `Runtime`, and `Handle` are disallowed types. That rejects every `#[tokio::main]` and `#[tokio::test]` outside the two crates, current-thread flavors included. The old rule rejected the text `tokio::runtime` whatever the flavor.
- The ban follows the categories of ARFC 0005 clause 3.1.1, not the old token list. It adds the `std::path::Path` file system methods and names `std::fs` and `std::thread` items one by one. For processes it bans `Command`, `Child`, `exit`, `abort`, and `id`. `std::process::ExitCode` is allowed, which settles the T-0042 developer follow-up.
- The Clippy fixture uses real tokio and rand, pinned by its own `Cargo.lock`, so that it shows the real `#[tokio::main]` expansion. These crates are outside `deny.toml`'s graph. On a cold Cargo cache, `cargo test -p xtask` fetches them, about 28 crates.
- `allow-invalid = true` goes on every non-std path and on the unix-only std paths. The fixture strips it, so every path whose crate the fixture has must resolve.
- Trailer keys follow git's `find_separator` rule (`[A-Za-z0-9-]+`, optional blanks, `:`), so a key may now start with a digit or a hyphen.
- A line under a `#[cfg(test)]` whose target has not reached its body, such as `mod tests;`, now counts as test code. One existing unit-test expectation changed to match: `[true, false, false]` became `[true, true, false]`.

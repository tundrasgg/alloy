## Summary

T-0111 is several tasks, and three of its parts need crates outside `touches` or specs that do not exist yet (Issues). Following `agent/roles/developer.md`, I built one coherent part and stopped there.
Done, in `alloyd` only: the sans-I/O node channel core (messages, IPv6/UDP carriage, requester, control node entries, heartbeat schedule), T-0091 F1 (data directory check at start) and F3 (escaped arguments).
Not done: `init` and `join` steps, anchor join service, control node handling of node messages, API server and local admin, lifecycle controller, the CLI interface, and both acceptance tests. `cargo test -p alloyd` therefore passes without the three-node loopback test it asks for.

## Changes

- `crates/alloyd/src/channel/proto.rs`: `alloy.node.v1alpha1` `NodeMessage` with every body of ARFC 0002 §3.13 and the status messages 16/17 of ARFC 0006 §4.3 (prost derive, reusing `alloy-id`'s record, view, and facts messages); `decode` checks every stated bound, the 16,384/16,512 sizes, and the `request_id`/`forwarded` rules; `Kind` with reply matching.
- `crates/alloyd/src/channel/frame.rs`: the IPv6 + UDP packet (ports 7477, hop limit 64, RFC 8200 §8.1 checksum) and the receiver's acceptance checks.
- `crates/alloyd/src/channel/requester.rs`: request id = handshake counter value + 1 (through a `RequestIds` trait), byte-identical resend every 1 s within the step's limit (cap 10 s), one request outstanding, one held per kind, heartbeat first and then fell-due order, reply matching by id, peer, and kind; `ControlChoice`.
- `crates/alloyd/src/channel/entries.rs`: one entry per origin (session key plus forwarded key), handled once / resend kept reply / drop lower, forgotten after 30 s, 8,192 direct and 8,192 per anchor.
- `crates/alloyd/src/channel/heartbeat.rs`: the clause 3.13 schedule (5 s after a success, 1/2/4 s after failures, 60 s after a refusal) and the address list (no loopback, link-local, or `al*`, IPv4 first, ascending, at most 64).
- `crates/alloyd/src/channel/mod.rs`: the module map.
- `crates/alloyd/src/data_dir.rs`: `check_at_start` reads `security` once per entry (ancestors, data directory, host file) and the host file's first line, then applies `alloy_id::datadir::check_at_start`. A failed `security` call fails that entry, with the owner reported as `unknown`.
- `crates/alloyd/src/lib.rs`: reads the join state only from an Alloy data directory. Otherwise it logs the reason at start and every 60 s and reads nothing. A missing directory is `unjoined`.
- `crates/alloyd/src/args.rs`: control characters in echoed arguments are escaped.
- `crates/alloyd/Cargo.toml`, `Cargo.lock`: `alloy-crypto`, `alloy-id`, `prost` (already in the workspace; no new crate in the lock).

## Issues

- `follow-up`: `alloy-link` drops every initiation from a static key that is not a peer (`crates/alloy-link/src/link.rs:542`). An anchor therefore cannot accept the unregistered initiators of ARFC 0002 §3.3 steps 3 and 4. It needs an opt-in accept-unknown mode with the 10/s per source and 100/s total limits.
- `follow-up`: `alloy-link` keeps its handshake counter private, so request ids cannot draw "the next counter value no initiation has used" (§3.13). It needs a call that takes a counter value.
- `spec-issue`: §3.3 step 3 has the joiner send a reflection request and answer the anchor's challenge (ARFC 0004 §3.1.2). No crate implements it, and `alloy-relay` does not exist.
- `spec-issue`: `init` step 3 creates an org, a project, the user `admin`, a pool, and a login code (ARFC 0007, 0012). None of these has a store or crate. T-0045 (queued) or a new spec task must say what M11 rung 2 builds of them. The same applies to join tokens: ARFC 0006 §2.6 defines no resource kind for them.
- `spec-issue`: the local admin socket (ADR 0055) needs Unix peer credentials, and alloy-rt does not have them yet (the board lists it under "Still to cut from T-0006").
- `follow-up`: `alloy_id::proto::JoinRequest` still has a `secret` field and the old body layout (`crates/alloy-id/src/proto.rs:120`). `NodeSecrets.join_request` must hold the §3.3 step 6 `JoinRequest {body, token_signature, identity_signature}`. Fix it with T-0121, which owns alloy-id.
- `follow-up`: T-0091 F2 and F3 for `alloy` (`crates/alloy/src/grammar.rs`) are outside `touches`. Fold them into T-0112.

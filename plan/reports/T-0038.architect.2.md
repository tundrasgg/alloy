## Summary

Probe messages now travel inside a session, and no probe message is accepted twice. Each handshake derives one probe key per direction alongside the session keys (3.3). A probe message carries `receiver_index`, a per-session probe `counter`, and an 88-byte unpadded layout holding the challenge, echo and observed endpoint. The receiver keeps a 2,048-counter window per session, erased with the probe receive key. Replays fail the window while the key lives, and nothing opens once the key is discarded or lost in a crash. Persistent epochs, probe records and the static-static probe key are gone. Probes cost no DH and no synced write. ADR 0046 is rewritten for this design.

## Changes

- `spec/arfc-0003-mesh-wire-protocol.md`: 3.3 derives `pi2r` and `pr2i` (labels `alloy/al/probe-i2r/v1` and `alloy/al/probe-r2i/v1`) and gives them the erasure rule and lifetime of the session keys. 3.6 is rewritten: sessions only, layout, sealing, replay window, replay protection, effects, fixed values and cost. The section 6 probe row is one AEAD open with no DH.
- `adr/0046-probes-are-sealed-under-session-keys-with-a-replay-window.md`: replaces `adr/0046-probe-replay-protection-uses-a-persistent-epoch-per-probe-set.md`, which never reached main.
- `adr/README.md`: the 0046 row names the new file and title.
- `plan/reports/T-0038.architect.2.md`: this report.

How each finding of `plan/reports/T-0038.reviewer.1.md` was resolved (the reviewer was right on all three):

- F1 (block): resolved without a pivotal question. No probe message is accepted more than once while the keys that sealed it are unchanged. That includes record drops, crashes and restarts. 3.6 "Replay protection": while the receiver holds the key, the window rejects a repeated counter. Once the key is discarded (3.3) or lost, nothing sealed under it opens, and every later session has new keys. A handover keeps the window with the key (ARFC 0017 section 3.5). Probe records no longer exist, so they cannot be dropped.
- F2: 3.6 names the one condition under which a message is accepted after it was sent: it was never accepted, its key is still held, and its counter is inside the window. That is a dropped or reordered message (ARFC 0020 section 2.1), not a replay. 3.6 "What an accepted message changes" defers to ARFC 0004 section 3.2 and says that a replay draws no answer, verifies nothing, adds no answer challenge, and creates or refreshes no state. The verified-endpoint case the reviewer traced is covered, because acceptance no longer depends on whether the node is probing.
- F3: probe records are removed. The only probe state is per session (336 bytes), and only an accepted message changes it. Replays are never accepted, so they cannot hold the state that probing needs. The probing bound is the session limit of ARFC 0004 section 7, and replays do not touch that limit.

## Decisions

- N: probes are sealed under per-session probe keys, not a static-static key. A probe message is accepted at most once by a per-session counter window (ADR 0046). The round 1 epoch design cannot meet ARFC 0020 section 3.2 without durable per-peer state: a synced write per epoch, kept for every peer ever heard, against ADR 0031. Probing already runs only between nodes that exchange traffic, so a session exists: a relayed one per ARFC 0004 section 3.2 step 1, or the home session for anchors.
- N: a node that must probe a peer it holds no session with opens one first. A responder may probe once it has sent the response. That delays the initiator's first probe by one relay round trip after first traffic. Traffic already waits for that round trip.
- N: an accepted probe message does not move the session's return path. It is not a transport packet, which keeps the behavior that sessionless probes had.
- N: the probe keys are derived in 3.3 from the handshake `prk`, with their own labels, so each key has one purpose (`agent/eng/crypto.md` rule 6). This edits 3.3, outside the task's sections 3.6 and 6. The alternatives were deriving them from the transport keys (one key, two purposes) or sharing the transport key with a reserved queue id (3.4 does not bound queue ids).
- R: the probe nonce is 16 zero bytes followed by the counter, as in 3.1, because the probe key is used for nothing else.

## Issues

- `spec-issue`: `spec/arfc-0004-path-manager.md` section 3.2 does not say that probing needs a session (ARFC 0003 section 3.6). Step 2 should say that B starts its probe set once it holds a session with A, and the 5 s direct bound (T-0043 F5) should count the handshake round trip.
- `spec-issue`: `spec/arfc-0004-path-manager.md` section 3.4 moves the return path on "an authenticated packet from a new source endpoint". It should say transport packets only, as ARFC 0003 section 3.6 now states. This belongs with T-0043 F2.
- `spec-issue`: `spec/arfc-0004-path-manager.md` section 8 ("Probes carry no counter ... not a replay check") and ADR 0039's consequence line are now false. This is already listed in `plan/STATE.md` for after T-0038 and T-0043.
- `spec-issue`: `spec/arfc-0003-mesh-wire-protocol.md` section 3.1 does not say what happens when both nodes initiate at once. Under 3.6, either side may now open a session in order to probe, so simultaneous initiations are more likely.
- `spec-issue`: as the round 1 reviewer noted, a host that receives A's genuine probes meant for a private address B also uses can inject each one at B once. Such a message was never accepted, so it passes the window and draws an answer challenge (`spec/arfc-0004-path-manager.md:199`). This is not a replay. It belongs with T-0043 or a follow-up.
- `follow-up`: the round 1 follow-up on a flood of probe messages that each cost one DH is resolved: probes cost no DH. The round 1 issues on the relay envelope `src` (3.1 and 3.7) and on path MTU probes inside relay envelopes still stand. They are already listed in `plan/STATE.md`.
- `follow-up`: the ARFC 0003 conformance suite needs tests for 3.6: the byte layout and fixed value drops, the 2,048 window (repeat, too old, out-of-order inside the window), no acceptance after key discard or rekey grace, separate probe and transport counters, and the 3.3 probe key derivation vectors.

Attacks tried. This is a spec task, so there is nothing to fuzz or simulate. Each attack is a scenario traced through the clauses.

1. Crash and lost message during join. The control plane commits the record and the anchor dies before replying. The joiner times out and keeps its keys (section 6), then retries. The result is undefined, and with `--name` it is refused (F1). With a reset handshake counter the retry is dropped at the AL layer (F2).
2. Outside client against the unauthenticated surfaces. Refusals are byte identical before the secret matches, and a guessed 64-bit id with a 128-bit secret learns nothing. The version step hands the cluster public key and the anchor's node record to anyone who holds the anchor's mesh key, which every token contains. Neither is secret, and PB-0001 asks for the version reply, so this is not a finding. `ExchangeLoginCode` has only a per-address rate limit, and every attempt writes an audit record (F9).
3. Default network setups the brief targets: a node behind NAT with a forwarded public address (F3), a node promoted to anchor or control after a plain join (F5), a token with preset roles (F4), and a cluster key rotation while tokens are live (F8).

## Issues

- `follow-up`: `alloy node leave` refuses while a disk of the node is in a pool (`spec/arfc-0002-identity-and-join.md` section 3.9). But `join` puts every storage node's disk into pool `default` (section 3.3 step 7), and no ARFC names a command that takes a disk out of a pool (`spec/arfc-0012-storage-core.md` clause 3.1.2 covers only data movement). So `leave` on a default joined node always ends in a `Conflict` with no next step (principle 5). This needs a pool brief and then a spec change.
- `follow-up`: PB-0001 Errors, row "Port in use", says the `--api-port` flag "works on `join`". ARFC 0002 section 3.3 gives `join` no `--api-port` flag. This belongs with T-0024, which owns ports and TCP 443 sharing (`spec/arfc-0008-native-api.md` clause 3.8).
- `follow-up`: ARFC 0002 section 7 still states "10,000 live tokens per cluster" with no behavior at the bound (I-21). The text predates this task (`spec/arfc-0002-identity-and-join.md` line 353).
- `spec-issue`: the glossary defines a context as having "an API endpoint". ARFC 0019 section 2 now gives it one to four (`agent/domain/glossary.md` line 63).

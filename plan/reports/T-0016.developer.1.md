## Summary

`.github/workflows/ci.yml` runs `cargo xtask ci` on `ubuntu-24.04` for pushes to `main` and for every `pull_request`.
It checks out the source, installs the toolchain from `rust-toolchain.toml` with the runner's rustup, restores the Cargo cache, installs `cargo-deny@0.20.2` with `cargo install --locked`, and runs the gate. A failing gate fails the job, which fails the run.
Permissions are `contents: read`. Both third-party actions are pinned to full commit SHAs. Superseded pull request runs are cancelled. Runs on `main` are not.
Three of the four acceptance commands pass. `actionlint` was not run: the session's permission system refused to execute the downloaded binary (see Question).

## Changes

A first local run of plain `rustup toolchain install` (without `--no-self-update`) also tried a rustup self-update. The update failed with "Access is denied" and rustup stayed at 1.29.2. That run showed the self-update risk, so the workflow passes `--no-self-update`.

## Decisions

- Toolchain from the runner's preinstalled rustup (`rustup toolchain install --no-self-update` reads `rust-toolchain.toml`) instead of a third-party toolchain action: one fewer pinned dependency, and the pin stays in one file.
- Cargo cache via `Swatinem/rust-cache` v2.9.3. It also caches `~/.cargo/bin`, so `cargo install` skips the cargo-deny build when 0.20.2 is already cached. The cache is saved only from `main` (`save-if`). Pull requests restore it and never write it.
- cargo-deny from `cargo install --locked cargo-deny@0.20.2`, not a prebuilt binary. The archive layout of the prebuilt release could not be checked here.
- `actions/checkout` with `persist-credentials: false`. The gate needs no git credentials.
- Concurrency group keyed by pull request number, or by ref for pushes. `cancel-in-progress` only for `pull_request`, so every commit on `main` gets a verdict.
- `timeout-minutes: 60` on the job, so a hung step cannot hold a runner for the 6 hour default.

| F1 | fix | `crates/alloyd/src/lib.rs:160` (with `crates/alloyd/src/data_dir.rs:202`) | `alloyd` reports a join state from any host file at the data directory path without the Alloy data directory checks. A directory that any local user can create, such as `Alloy` in `%ProgramData%` on Windows, therefore makes `alloyd` log `join_state=joined` instead of "not initialized". | ARFC 0002 section 3.12: the local join state is the `join` line "of the host file of an Alloy data directory, and is `unjoined` when the path holds none". `alloyd` checks at every start that the directory is an Alloy data directory, and logs the reason every 60 seconds when it is not. Attack 2 above: a planted host file in a user-created directory gives `INFO local join state join_state=joined`. | `alloyd` derives the local join state only from a directory that meets section 3.12, and otherwise reports it as not an Alloy data directory, as that section says. If the check stays deferred to the init/join task, the lead records that, and no later task reads secrets or acts on the join state before the check lands. |
| F2 | fix | `crates/alloy/src/grammar.rs:236` | When the mistyped command is followed by further words, the `Try:` line suggests a command that is itself a usage error. Words with spaces or shell metacharacters are also printed unquoted, so the line does not run as printed. | Principle T5 ("A command shown to the user runs as printed"). ARFC 0019 clause 3.1.8 (the `Try:` line holds the next command). `alloy verison now` prints `Try: alloy version now`, which exits 2. `alloy verison "a b"` prints `Try: alloy version a b`. In Attack 3, 1,009 distinct fuzzed command lines produced a `Try:` command that exits 2. | Every `Try:` command that `alloy` prints parses as a valid command line when run as printed, and a test covers trailing words after a mistyped command. |
| F3 | note | `crates/alloy/src/grammar.rs:96` | Usage errors write the user's argument bytes to standard error unescaped, so control characters and terminal escape sequences in an argument reach the terminal. `alloyd`'s `LineLog` escapes them. | Attack 3 above: `alloy $'\e]0;pwned\a'` writes `033 ] 0 ; p w n e d \a` raw (`od -c`). | Control characters in echoed arguments are escaped before `alloy` writes them to a terminal, as `LineLog` already does for `alloyd`. |

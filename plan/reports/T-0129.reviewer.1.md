## Issues

- spec-issue: `spec/arfc-0005-simulator-and-natlab.md` clause 3.1.16 (`mem`) promises "after any later crash `to` names the file", but forces only the rename and the create of `from`. The promise fails, with `Ok` returned, in three cases: the directory's own create is unsynced, `from`'s name was freed by an unsynced remove, or `from`'s name was reached by an unsynced rename. All three reproduce under `Lost` on seed 1. This extends the developer's issue with the unsynced-directory case. The clause should either state the precondition for the caller or say what `replace` also makes durable.
- follow-up: T-0078 (`mem` streams, paused) must include `peer_uid` returning 0 on both ends (clause 3.1.9.2). See F2.

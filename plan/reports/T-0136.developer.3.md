## Changes

- `crates/alloyd/src/mesh.rs`: drives one `alloy-link` `Link` over the mesh-port UDP sockets. It persists counter blocks, carries node messages as section 3.13 frames on VNI 0, and runs one `Requester` with the control node choice. It applies the 3.15 endpoint rule and the join service filter with its rate limits (1/s per session, 100/s in total).
- `crates/alloyd/src/join.rs`: `join` and `resume`. These cover step 1's conflicts, step 2's writes (keys reused after a failed attempt), steps 3 to 7 with the cluster-key and record checks, and the failed-attempt cleanup of section 6. Also `JoinOptions`, `Joined`, `Refusal`, and `JoinError` with exit codes.
- `crates/alloyd/src/nodes.rs`: `NodeService`, the control node's one node-channel task. It handles `join_hello` (version window), `join_request` (the step 6 checks in order, retry, `key_in_use`, the refusals, default roles and name suffixes, token use counting) and `join_state`. It also handles `renew` (section 3.5) and heartbeats (clause 3.14), with entries per origin. It runs the lifecycle controller each second: it deletes expired `joining` nodes, sets and clears `unreachable_since`, and renews the control node's own record.
- `crates/alloyd/src/records.rs`: the resource kind `NodeRecord`, one per node. It holds the signed record, facts, token id, and source address (ARFC 0002 section 3.14).
- `crates/alloyd/src/member.rs`: `MemberNode`, a joined node without `control`. It dials its control-holding homes from the view, heartbeats on the clause 3.13 schedule, renews at half life, and retries 60 s after a renewal with no reply.
- `crates/alloyd/src/control.rs`: `Listeners.mesh`. `ControlNode` reads the cluster and mesh keys and runs the mesh and `NodeService` beside the API.
- `crates/alloyd/src/init.rs`: also stores the init node's `NodeRecord`.
- `crates/alloyd/src/lib.rs`: serves a joined node as a control node or a member node, resumes `joining` at start, and binds the mesh port on IPv4 and IPv6.
- `crates/alloyd/src/tests/node.rs`: the three-node loopback and restart test. Also tests for the wrong token, `name_taken`, a default-name suffix, `compute_unsupported`, a retry with the kept keys, and a usage error.
- `crates/alloy-id/src/token.rs`, `src/tests/token.rs`: `join_message` and `JOIN_CONTEXT` (section 3.3 step 6), tested.
- `crates/alloyd/Cargo.toml`, `Cargo.lock`: `alloyd` depends on `alloy-link` and `alloy-wire`, and on tokio `sync`.

## Decisions

- N: `join` runs steps 3 to 7 in the CLI's process (D-0069), so the session it joined on ends with the CLI. `alloyd` then opens a new home session from the same mesh port.
- N: the control plane keeps each node's signed record, facts, token id, and source in a `NodeRecord` resource beside its `Node`, because `alloy-state` is outside `touches`. An admission writes the token use first, then the record, then the `Node`. A crash in between over-counts a use, and a retry recreates a missing `Node`.
- N: empty `roles` in a request means "not given". The default is then the token preset, else none when `facts.os` is `windows`, else `compute,storage` (without `compute` when there is no virtualization). See the spec-issue.
- N: the version window uses the control node's own release as the lowest and highest, since rung 2 records no running release.
- N: UDP only. `alloy-link` has no `stream` framing, so step 3 tries every address over UDP.
- N: `alloyd` started in `joining` resumes the attempt with `join::resume` (section 6).
- R: the 3.15 endpoint rule is kept per peer, for its latest session, not per session. A renewal of an expired record goes over the node's registered session, since a control node keeps every recorded node as a peer.
- R: a request whose name breaks the node-name rule is refused `name_taken`, since no refusal names it. `pending` exits 0.

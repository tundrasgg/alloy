## Summary

`alloy-link` has an opt-in accept-unknown mode. With it on, an initiation from a static key that is not a peer is accepted, at most 10 per source address and 100 in total per sliding second (ARFC 0002 §3.3 step 4). The initiator is then reported with `Event::UnknownInitiator`, and the caller admits it with `add_peer` or drops it with `remove_peer`. Nothing else about the handshake changes.
`Link::draw_counter` takes the next handshake counter value no initiation has used and marks it used. Draws and initiations share one sequence, the same blocks, and the same `CounterBlockNeeded` events (§3.13, ARFC 0003 §3.2).

## Changes

- `crates/alloy-link/src/lib.rs`: `UNKNOWN_PER_SOURCE`, `UNKNOWN_TOTAL`, `UNKNOWN_WINDOW`, `UNKNOWN_REPLAY_ENTRIES`; `Event::UnknownInitiator`; `DropReason::RateLimited`; crate docs for both features.
- `crates/alloy-link/src/link.rs`: `set_accept_unknown`, `is_admitted`, `is_unknown`, `draw_counter`. `add_peer` admits an unknown initiator. The rate window in `on_initiation` counts only initiations that pass every earlier check, replays excluded. An unknown initiator with no session and no pending initiation is forgotten at the end of each public call. Replay entries for never-admitted keys are LRU-bounded.
- `crates/alloy-link/src/link/tests.rs`: unit test for the bound and eviction order of the unknown replay entries.
- `crates/alloy-link/tests/unknown.rs`: off by default; accepted and reported; handshake and transport unchanged; admit; drop with replays still refused; idle forgotten; per-source and total limits at both edges (count, last nanosecond, window reset, port ignored, IPv6); rekeys counted; 8 seeds against a sliding-window model that reach both limits.
- `crates/alloy-link/tests/counter.rs`: draws and initiations take successive values; random interleavings across blocks and two restarts from the persisted block end, strictly increasing; a used-up block stops both until `add_counter_block`.

## Decisions

- N: the per-source limit keys on the IP address: `src` minus its 2-byte port when it is 6 or 18 bytes, the whole `src` otherwise. Port hopping does not get around it.
- N: replay entries for keys never added as peers are capped at 65,536, least recently accepted evicted first. At 100/s an entry lives at least 655 s, longer than the 180 s session it protects. Admitted keys keep their entries for good, as before.
- R: `UnknownInitiator` is pushed after `SessionMade` for every session an unadmitted key makes, its rekeys included, so a caller that has not decided yet is asked again.
- R: `draw_counter` returns `None` when the blocks are used up and counts no drop. No message was dropped.

## Issues

- `spec-issue`: ARFC 0003 §3.2 states no bound for the per-initiator replay table once unregistered initiators are accepted. This crate caps it at 65,536 (`crates/alloy-link/src/lib.rs`, `UNKNOWN_REPLAY_ENTRIES`), and the spec should state the bound.
- `spec-issue`: ARFC 0002 §3.3 step 4 limits handshakes "per source address". The `ExchangeLoginCode` limit in §7 says "per source address or IPv6 /64". Say whether handshakes also group IPv6 by /64. This crate uses the exact address.

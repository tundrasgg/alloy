## Summary

The Proxmox VE `/etc/pve` digests now hash the HA status files
(`/etc/pve/nodes/*/lrm_status` and any `*/manager_status`) after normalizing them:
the file is parsed as JSON, every `timestamp` key is removed at any depth, and the
keys are sorted. The normalizer is `perl` with JSON::PP, else `python3`. If neither
is present, or the file is not JSON, the file is hashed raw and its line ends
`(raw: not normalized)`. Every other file is now a raw SHA-256: the earlier `sed`
that stripped `"timestamp":<n>` from every file is gone.

## Changes

- `tests/e2e/host-snapshot.sh`: `pve_status_file`, `pve_json_tool`, `pve_normalize_json`; `pve_digests` prints a first line naming the tool and hashes status files normalized, all others raw
- `tests/e2e/README.md`: the "What a comparison ignores" row now covers timestamps and key order; new subsection "The HA status files under /etc/pve" names the files, the normalization, the tools, and the raw fallback

`perl -MModule::CoreList -e 'print Module::CoreList->first_release("JSON::PP")'` prints `5.013009`, so JSON::PP is a Perl core module. Rung 1 on the real Proxmox VE node was not run: the lead reruns it as acceptance.

## Decisions

- `timestamp` is removed at every depth, not just at the top level, so that a nested timestamp in `manager_status` cannot fail the check. Any other value change still shows
- `perl` comes before `python3` because Proxmox VE is written in Perl. One tool is chosen per snapshot and named in the section, so a change of tool shows as a difference

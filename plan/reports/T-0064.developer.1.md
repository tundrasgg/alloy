## Summary

`alloy-wire` now encodes and decodes the compact layout of ARFC 0003 sections 3.4 and 3.5. The transport packet has a 9-byte header (`type`, `receiver_index`, 32-bit `counter`) and no version byte, the overhead is 25 bytes, and the minimum packet is 26 bytes. The inner frame's kind is the high 4 bits of its first byte (keepalive `0x00`, control `0x10` with bind request and bind, fragment `0x20` with a 7-byte header, IPv4, IPv6). Each kind is checked against the VNI it arrives on.
`reconstruct_counter` is a pure function that rebuilds the 64-bit counter from the wire value and the window position `H`, as section 3.4 states. Property tests check it against a brute-force model, across the 32-bit wrap, and at the 2,047 reorder bound.
Review note F1 of T-0054 is fixed. T-0061 has not merged and `fuzz/` does not exist on main, so no fuzz target was changed.
`cargo test -p alloy-wire` passes 43 tests and `cargo xtask ci --base main` exits 0.

## Changes

- `crates/alloy-wire/src/lib.rs`: crate docs; `TRANSPORT_HEADER_LEN` 9, `TRANSPORT_OVERHEAD` 25, `FRAGMENT_HEADER_LEN` 7, new `COUNTER_LIMIT` (2^31); `INNER_HEADER_LEN` removed; new re-exports.
- `crates/alloy-wire/src/transport.rs`: `TransportHeader { receiver_index, counter: WireCounter }`. `Transport` has no version byte and `MIN_LEN` 26. `InnerFrame` is now an enum (`Keepalive`, `Control`, `Fragment`, `Ip`), with `decode(bytes, vni)`, `decode_reassembled(bytes, vni)`, `encode` and `encoded_len`. New `FrameKind` (with `is_carried_on`), `IpPacket`, `IpVersion` and `Control` (`BindRequest`, `Bind`). `Fragment` has no inner kind or reserved byte and needs at least 1 byte of data. Unit tests cover every layout and drop rule.
- `crates/alloy-wire/src/counter.rs`: new `reconstruct_counter(WireCounter, Option<PacketCounter>) -> Option<PacketCounter>`, computed in `i128` so it never overflows, with unit tests at the interval edges, the wrap, and `u64::MAX`.
- `crates/alloy-wire/src/types.rs`: new `WireCounter(u32)` and `PacketCounter::wire`; `QueueId` removed, since no wire field carries a queue any more; `SessionIndex` docs cover block indexes.
- `crates/alloy-wire/src/error.rs`: new `MalformedKindByte`, `KindNotCarried`, `KindNotReassemblable` and `UnknownControlType`; `InvalidFragmentKind` removed; `UnknownFrameKind` now carries the 4-bit kind.
- `crates/alloy-wire/src/message.rs`: F1 fixed, so the `MessageType` doc states behavior only; the test covers every refused first byte (0 and 5 to 255).
- `crates/alloy-wire/src/codec.rs`: `min_header` removed (unused). The file was the only one in the crate stored with CRLF line endings, and it is now LF like the rest. That is why the diff stat shows the whole file.
- `crates/alloy-wire/tests/properties.rs`: generators for the new types. Inner frame round trip, canonical encoding, truncation and mutation, all with the VNI. Arbitrary frame inputs on three VNIs. An exhaustive check of every input of up to 2 bytes. Three counter properties: a model match over edge and random window positions (about 33,000 cases), exactness for every counter below 2^31 no more than 2,047 below `H`, and a round trip across the wrap for any `H` (20,000 cases).

## Decisions

- N: the public API changes shape for T-0055. `InnerFrame` is an enum, its decoders take the VNI of the block the packet arrived on and enforce the "carried on" column themselves, and `decode_reassembled` applies the 3.5 rule for reassembled frames. That keeps every 3.4 and 3.5 frame rule in one decoder. `QueueId`, `FragmentKind` and `InnerBody` are removed.
- N: `reconstruct_counter` returns only the reconstructed `c`, or `None` when it is negative or above `u64::MAX`. The "more than 2,047 below `H`" and "already accepted" checks need the window bitmap, so they stay with the session state in `alloy-link`.
- N: new public `COUNTER_LIMIT` (2^31), the sender bound that makes the reconstruction exact, so `alloy-link` and the tests share one constant.
- R: a control frame's VNI is not range-checked beyond 24 bits. Whether a bind request or bind for VNI 0 or an unknown VPC is acted on is session state (3.4 "drops the request and counts it").
- R: `IpPacket::new` refuses an empty slice or a first nibble other than 4 or 6. That is the sender rule for non-zero VNIs, and it guarantees that every `InnerFrame::Ip` encodes to bytes that decode back to it.
- R: decode order for frames: empty, then kind, then carried-on VNI, then exact first byte, then length and fields. For transport: type, then length.

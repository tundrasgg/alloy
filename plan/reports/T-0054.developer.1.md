## Summary

New crate `alloy-wire`: sans-I/O, `#![forbid(unsafe_code)]`, no dependencies. It encodes and decodes the initiation (type 1), response (type 2), cookie reply (type 3), both handshake payload plaintexts, the transport packet (type 4), the inner frame, and the fragment header, per ARFC 0003 sections 3.1, 3.4 and 3.5. It enforces every fixed value, drop rule and length those sections state, and it does no cryptography: ciphertexts, MACs, nonces and tags are opaque byte arrays.
Every decoder is total and returns a typed `DecodeError`. Every encoder writes into a caller buffer and returns `EncodeError::BufferTooSmall` when the buffer is too short, writing nothing in that case.
`cargo test -p alloy-wire` passes 30 tests, and `cargo xtask ci --base main` exits 0.

- `crates/alloy-wire/src/message.rs`: `MessageType` and `Message`, which decode and encode by the `type` byte.
- `crates/alloy-wire/tests/properties.rs`: seeded property tests, 8 seeds × 16 cases per type, using an in-file SplitMix64 generator. - `Cargo.toml`: `crates/alloy-wire` added to the workspace members.
- `Cargo.lock`: the `alloy-wire` package entry.
- `deny.toml`: `alloy-wire` added to `bans.allow` as a workspace member.

## Decisions

- N: no dependencies. `thiserror` and `proptest` are the standing choices in `agent/eng/deps.md`, but neither is on the `deny.toml` allowlist, and adding them is the lead's call. So the errors implement `Display` and `Error` by hand, and the property tests use a seeded in-file generator. Both are easy to swap once the crates are allowed.
- N: this public API is the one T-0055 will test against (D-0022). Fixed-size messages provide `LEN`, `decode(&[u8])`, `to_bytes()` and `encode(&mut [u8]) -> Result<usize, EncodeError>`. `Transport` and `InnerFrame` borrow their variable part from the input. `Message::decode` dispatches on types 1 to 4, and types 5 and 6 return `DecodeError::UnknownType`.
- N: fields that version 1 fixes at zero are not struct fields. These are the header `reserved`, the payload `flags` and `reserved`, and the response `mac2`. Encoders write zeros and decoders reject anything else (`NonZeroReserved`, `NonZeroFixed`), so an invalid value cannot be built.
- R: check order is type, version, length, then reserved. A wrong version is reported before a wrong length, because a later version may have another length.
- R: a transport packet needs at least 20 bytes of ciphertext: the 16-byte tag plus the 4-byte inner header. Anything shorter cannot open to an inner frame, so it is dropped before the AEAD open.
- R: the queue id in a transport header is not range-checked here, because the wire allows any `u16`. Checking it against the negotiated queue count is session state.
- R: a fragment's `index` counts from 0 and must be below `count`. Its inner kind must be 1, 2 or 3 (a keepalive has nothing to split, and a fragment is not fragmented again). Its `reserved` byte must be zero.
- R: a keepalive keeps its body bytes as sent, so every byte of a valid frame is represented in the decoded value and decoding stays canonical.

## Issues

- `spec-issue`: ARFC 0003 section 3.4 (`spec/arfc-0003-mesh-wire-protocol.md`) leaves several points about the fragment header open. It does not say whether `index` counts from 0 or 1, which inner kinds a fragment may carry, or whether its `reserved` byte must be zero. It also does not say whether transport queue ids count from 0 below `queues`. This crate assumes from 0, kinds 1 to 3, and reserved zero (Decisions). T-0055 should test whatever the spec settles.
- `follow-up`: `agent/eng/testing.md` requires a fuzz target for every decoder. `fuzz/` is outside this task's `touches`, so no target exists yet. One target per decoder (`Message::decode`, `InnerFrame::decode`, `InitiationPayload::decode`, `ResponsePayload::decode`) can reuse the canonical-encoding check from `crates/alloy-wire/tests/properties.rs`.
- `follow-up`: once `thiserror` and `proptest` are on the `deny.toml` allowlist, move `crates/alloy-wire/src/error.rs` and `crates/alloy-wire/tests/properties.rs` onto them.
- `process-issue`: `agent/eng/deps.md` lists `thiserror` and `proptest` as settled choices, and `agent/eng/rust.md` and `agent/eng/testing.md` require them, but no task has put them on the allowlist. Every first crate will hit this same gap. Allowing both once, in a lead task, would close it.

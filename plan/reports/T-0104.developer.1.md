## Summary

New crate `alloy-link`: one sans-I/O `Link` per node runs ARFC 0003 sections 3.1 to 3.5: handshakes with `mac1`, load-based cookie replies, retries, and counter replay protection; sessions with the 4-per-peer cap, rekey, 10 s and 180 s key lifetimes and erasure; transport with 64-index blocks, binds, session choice, held packets, counters below 2^31 and the 2,048 window; fragmentation and bounded reassembly. Every drop is counted and returned (section 6). Time and randomness come in as `Ctx { now: alloy_rt::Instant, rng: &dyn alloy_rt::Rng }`.
The diff is 3,527 lines, over the 2,000 target: about 2,120 are crate code and docs, 1,375 tests. It is complete, so the status is `done`, not `blocked`. If the review should be split, cut it at `reassembly.rs` plus `seal_frame` (fragmentation).

## Decisions

- N: public interface as above. `Link::{new, add_peer, remove_peer, add_local_vni, remove_local_vni, set_handshake_backlog, is_under_load, add_counter_block, connect, receive, send, tick, next_deadline, drops, session_count, is_pending, public_key}`. Each call appends `Output`s to a caller `Vec`. `Destination::Source` means the source of the datagram that call received.
- N: initiation retry every 5 s, with a fresh ephemeral and counter. The handshake is abandoned at 90 s (`RETRY_INTERVAL`, `RETRY_GIVE_UP`), because ARFC 0003 section 9 leaves this open.
- N: only peers added with `add_peer` can handshake. An initiation from any other static key is dropped after decryption, so the 3.2 replay table is bounded by the peer set.
- N: "under load" counts this link's pending initiations plus a backlog the caller reports. A responder keeps no pending state, so the "1,000 pending handshakes" of section 7 is otherwise empty.
- N: block bases are random multiples of 64, so an index maps to its block by masking. Rekey starts when a packet is sent under the newest session at 120 s or 2^30 packets, on either side.
- N: counter blocks: `Config::counter_start` is already durable. `Event::CounterBlockNeeded` fires at half a block, and `add_counter_block` extends by 65,536.
- N: keepalives, bind requests and binds go on queue 0 and are never fragmented. Packets are held for at most 1,024 VNIs per peer. A session sends at most 1,023 bind requests.
- R: cookie secrets are drawn on first use under load and retired on the 120 s / 240 s schedule. Stack copies of drawn secret bytes are overwritten after the self-erasing key type takes them.

- follow-up: no test covers `DropReason::NoFreeBlock`, because reaching it needs all 2^26 aligned blocks. The 65,535-byte stream frame limit (section 3.8) is out of scope and not tested.
- follow-up: `tests/conformance/wire` holds byte-layout vectors only and does not drive `alloy-crypto`. The flow tests assert that every datagram a link emits decodes with `alloy_wire::Message::decode`.

## Decisions

- `mem` UDP packets in flight are bounded per socket by `send_buffer` and per origin host by 67,108,864 bytes of packet size, with `send` waiting and no copy made at the bound. A per-world bound was rejected because it would couple hosts (ADR 0054).
- A stream byte resets its sender 60 s after its due time, not its send time, so a `Link` fault that raises latency never resets a connection by itself (ADR 0054).
- A connection can be set up only over a route whose delay at the request is below 15 s, so a 30 s `connect` timeout never leaves a half-open accepted end (ADR 0054).
- A segment arriving where no live end is gets exactly one reset back per direction. A dropped `connect` resets the listener's end at `t + 2d`. A dropped listener resets its backlog. A reset end in a backlog leaves it.
- A pending connection request counts as an open stream until its answer or 30 s, which bounds requests in flight per host at the existing 65,536.
- `mem` picks TCP source ports from 49,152 to 65,535 like UDP port 0, and fails with `AddrNotAvailable` when none is free.
- Observers and middleboxes cannot perturb a run: `random_u64` returns 0 from them without advancing the scenario stream.
- 100,000,000 polls at one world instant ends the run with `liveness`. The value leaves room for 10,000 hosts with thousands of tasks woken at one instant.

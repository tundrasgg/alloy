## Summary

New crate `crates/alloy-crypto`, `#![forbid(unsafe_code)]`, the only crate that depends on `blake3` (1.8.7, pinned).
Its public API is `hash(&[u8]) -> [u8; 32]` and `Hasher` with `new`, `update` and `finalize`, plus `Clone`, `Default` and a `Debug` that shows no state. Nothing else.
`blake3` uses `default-features = false, features = ["std", "pure"]`. `pure` means no C or assembly is compiled into the binary.
`blake3` and its new tree are on the `deny.toml` allowlist. Each crate passes the license check under its Apache-2.0 option.
Unit tests cover all 35 official BLAKE3 `hash` vectors, through both forms, and check that the one-shot and incremental forms agree for every piece size and split point tested.

## Changes

- `crates/alloy-crypto/Cargo.toml`: new crate manifest. Its only dependency is `blake3` from the workspace.
- `crates/alloy-crypto/src/lib.rs`: documents and implements `hash` and `Hasher`.
- `crates/alloy-crypto/src/tests.rs`: official vectors, agreement tests for one-shot and incremental hashing, and tests that `finalize` and `clone` leave state unchanged.
- `Cargo.toml`: adds the workspace member and `blake3 = { version = "=1.8.7", default-features = false, features = ["std", "pure"] }` with the reason for its features.
- `Cargo.lock`: adds `arrayvec`, `blake3`, `cc`, `constant_time_eq`, `find-msvc-tools` and `shlex`.
- `deny.toml`: allows `alloy-crypto`, `arrayvec`, `blake3`, `cc`, `constant_time_eq`, `find-msvc-tools` and `shlex`, and updates the reasons for `cfg-if`, `cpufeatures` and `libc`, which `blake3` now shares.
- `plan/reports/T-0074.developer.1.md`: this report.

`blake3` 1.8.7 `build.rs` lines 343-360 and 366-371 (in the cargo registry copy): when `pure` is set, x86 targets get the Rust SSE2, SSE4.1 and AVX2 intrinsics, AVX-512 is left out, and aarch64 gets no C NEON. So no C or assembly is compiled. On x86 targets the build script still calls `c_compiler_support()` (line 344), which probes a C compiler for AVX-512 flags. If no compiler is found it continues with `NoCompiler`, so the build does not need one. `cc` stays in the tree because it is an unconditional build dependency of `blake3`.

Advisories: `cargo deny check advisories` reports none for the new crates. R-0004 line 95 also lists none on file for `blake3`.

## Decisions

- `blake3` features are `std` and `pure`, with defaults off. `pure` keeps C and assembly out of the build, and `std` keeps runtime CPU detection for the Rust SIMD paths. The output is identical either way.
- License choice: `blake3` and `constant_time_eq` are each used under their Apache-2.0 option. CC0-1.0 and MIT-0 are not on the allowlist, and cargo-deny accepts an OR expression when any one of its options is allowed. The `licenses.allow` list is unchanged.
- `Hasher::finalize` takes `&self` and leaves the hasher unchanged, matching `blake3`. A caller can take an intermediate hash and keep feeding input.
- `Hasher::update` returns `&mut Self` so calls can be chained.
- `Debug` for `Hasher` prints only `Hasher { .. }`, so internal state, which is derived from possibly sensitive input, never reaches debug output (`agent/eng/crypto.md` rule 8).

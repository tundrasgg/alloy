## Summary

The Clippy fixture's cargo run now passes `--color never`, so its output has no escape codes whatever `CARGO_TERM_COLOR` or `term.color` says. Under color, rustc's short output wraps `error[E0453]` in escape codes, `parse` missed it, and every `crates/switches` line went missing.
That run is the only place in `xtask` that reads Cargo, Clippy, or rustc output. The gate steps (`run_cargo`, the `deny` probe) read only the exit status, so color cannot change their result and they are unchanged.
A new test runs the `clippy-forbid` step over the fixture with `CARGO_TERM_COLOR=always` and with it unset, and checks the two give the same result and that the colored run has no escape codes.

## Changes

- `xtask/src/clippy_fixture.rs`: `run` passes `--color never` to cargo and takes a `TermColor` (inherit, unset, or set `CARGO_TERM_COLOR` on the child). The existing reports inherit. New test `clippy_fixture_output_ignores_the_callers_color`. 60 lines added, 5 removed.

## Decisions

- R: color is turned off with the `--color never` argument, not with `CARGO_TERM_COLOR=never` on the child. Cargo gives the argument precedence over both the environment variable and `term.color` in config, so one argument covers both.
- R: the gate steps keep the caller's color. They read only exit status, and colored output helps a person reading the terminal.

## Decisions

- `alloy-seam` depends on no Alloy crate and `alloy-rt` depends on `alloy-seam`, so `alloy-rt` can declare its seam markers. This is allowed by the dependency rule in `plan/workspace.md`. The table puts `alloy-rt` above `alloy-seam`, so the lead may want to swap the two rows.
- Seams are typed by a zero-sized marker implementing `Seam` (kind, trait object, factory context, swap class). Factories are closures, so the simulator registers `mem` per host with the host captured. The runtime seams use context `()`, and every other seam uses `alloy_rt::Runtime` unless its ARFC says otherwise.
- Every asynchronous seam method returns `BoxFuture` (one allocation per call, which is per batch on hot paths). Network buffers are borrowed and disk buffers are owned `IoBuf`s aligned to 4,096 and moved through each call, so `os` can use blocking threads and direct I/O.
- A configuration value is a u16 version plus a proto3 payload, at most 65,536 bytes. `alloy-seam` does not depend on `prost`.
- `Slot::swap` takes a deadline future instead of a duration, because `alloy-seam` has no clock. A dropped swap future poisons the slot.
- The trace hash is BLAKE3 through `alloy-crypto`, following the content hashing row of `agent/eng/crypto.md`.
- UDP sockets never fragment. Sends over the path MTU fail with `MessageTooLong { max_payload }`, and the path MTU includes values learned from ICMP. This is how "MTU limits with or without ICMP feedback" becomes visible to callers.
- `Net` includes Unix stream sockets (used for the local admin socket and vhost-user paths) and an interface change wait (`interfaces(Some(generation))`) for ARFC 0004 candidate changes.
- Numeric bounds chosen: 64 datagrams per batch, 256 disk operations per batch, `IoBuf` at most 64 MiB, 4,096 UDP sockets, 65,536 streams, 65,536 open files, 1,048,576 live tasks, 1,048,576 entries per list, 1,024 registrations, 30 s `mem` connect timeout, 600 s `mem` learned path MTU lifetime.

## Issues

- `follow-up`: `alloy-sim` needs `blake3` (through `alloy-crypto`) on the `deny.toml` allowlist before T-0009 can hash traces. See the R-0004 note on `blake3` licensing in `plan/STATE.md`.
- `follow-up`: the `alloy-sim` world and scenario interface (hosts, links, fault injection API, scenario runner, trace file option) is not specified. T-0009 and T-0010 need it, either in their task files or in a short spec task on `spec/arfc-0005-simulator-and-natlab.md` section 3.3.
- `follow-up`: `Spawn` has no blocking-work offload (CPU-heavy work such as Argon2) and `Net` has no Unix peer credentials. The latter waits on the `SO_PEERCRED` research question noted in `plan/STATE.md`. Each needs a spec change to `spec/arfc-0005-simulator-and-natlab.md` before a crate needs it.
- `follow-up`: handover of sockets and devices by file descriptor (ARFC 0017 clause 3.5) is not in the `Net` or `DiskIo` interface. It needs a spec task before `alloy-net` handover is built.
- `follow-up`: starting external processes (VMMs, ARFC 0011) is not in `alloy-rt`, and `check-repo` does not list `std::process` among direct I/O patterns (`xtask/src/rules/code.rs`). The `hypervisor` and `sandbox` seams need a ruling on where process spawning lives.
- `follow-up`: `plan/workspace.md` lists `alloy-rt` above `alloy-seam`, but under this spec `alloy-rt` depends on `alloy-seam`.

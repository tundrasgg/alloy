## Summary

`alloy-link` now follows ARFC 0003 3.3 as T-0115 wrote it. A session records the sessions it
follows, meaning those confirmed when this node sent the handshake message that makes it. The first packet
accepted under the session schedules each of those for discard 10 s later. Discard is whole-session
(rule 1, 2 or 3), so no receive key outlives the session. `moved_on`, `recv_until` and the
VNI 0 or bind heuristic are gone (T-0104 review F1, F2). Session choice applies the 5 s
"qualifies" rule of 3.4.

## Changes

- `crates/alloy-link/src/session.rs`: per session `follows`, `discard_at` (rule 2) and `first_sealed` (3.4 qualify); keys no longer optional.
- `crates/alloy-link/src/link.rs`: `follows` taken at initiation send and response send; rule 2 on first accepted packet; whole-session expiry; `choose` skips sessions past 5 s.
- `crates/alloy-link/src/lib.rs`: `DISCARD_AFTER_FOLLOWED` replaces `PREVIOUS_RECV_TIME`, new `QUALIFY_TIME`, docs for 3.3 rules and the bind note.
- `crates/alloy-link/tests/crossed.rs`: every row of the 3.3 table, rule 1 and 2 lifetimes, the 5 s qualify rule, and the seeded run of 1,000 crossed rekeys.
- `crates/alloy-link/tests/flow.rs`: rekey test asserts the rule 2 discard at 10 s; constant renamed.
- `crates/alloy-link/tests/common/mod.rs`, `tests/faults.rs`: `SplitMix` moved into the shared harness.
- `crates/alloy-link/src/link/tests.rs`: `seal` call updated to its new signature.

Each row test sends one packet each way every second for 400 s with no underlay loss.
Every packet must arrive once, in the second it was sent, and both nodes must end with 0
`UnknownIndex` and 0 `Unauthentic` drops. That covers the rule 2 discard of `O`, a further
rekey that crosses again, and 180 s expiry. Each row also checks the sessions kept against
the table. The "cannot happen" row has no test. The "packet under `O` delayed 5 s" row
runs inside every other row. The seeded run applies 20% loss, 5% duplication, shuffling and
10% delivery 1 to 4 steps late, all during each rekey. After the faults it requires every
packet from the 6th clean second on, which is `RETRY_INTERVAL` + `HOLD_TIME`.

## Decisions

- N: A bind request is answered, and the bind is sealed, under the session the request came under even when that session no longer qualifies. Following the 3.4 text there would blackhole non-zero VNIs after a crossed rekey (T-0115 review F1, D-0058). Until T-0119 settles the rule, the bind path keeps its earlier behavior, and the crate docs say so.
- R: Session choice applies the 5 s qualify rule of 3.4, which is in this task's spec list. The proof behind rule 2 relies on it.

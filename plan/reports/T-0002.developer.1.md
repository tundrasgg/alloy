## Summary

`cargo xtask check-repo` now enforces eight rules: `instruction-files`, `banned-patterns`, `direct-io`, `unsafe`, `path-lock`, `front-matter`, `links`, `dates`. Each violation prints as `path:line: rule: message`.
Every rule has a passing and a failing fixture under `xtask/tests/fixtures/<rule>/`, and each failing fixture lists the exact `path:line: rule` it must produce.
The path lock runs when `--base <ref>` is given (`--branch <name>` for a detached HEAD). `ci` accepts the same options.
T-0001 review F1: the gate runs every cargo step from the repository root, fixed at build time, and the deny step passes `--workspace`. F2: the cargo-deny install hint appears only when `cargo deny --version` cannot run.
On this branch `cargo xtask check-repo` and `cargo xtask ci` exit 0. The document trees are the same as on main.

## Decisions

- Backticked repository paths are checked only when they start with `agent/`, `spec/`, `adr/`, `plan/`, `product/`, or `research/`. ARFCs cite code and test paths that later tasks create, such as `tests/conformance/hypervisor`. Checking those would fail main now and would fail the first verify branch that creates `tests/`, which cannot edit `spec/`.
- Spans with placeholders (`<`, `>`, `*`, `NNNN`, `...`, whitespace) are not paths. A trailing `:line` and `#fragment` are dropped before the lookup.
- The task template's 60-character title limit is not enforced. T-0026 and T-0027 already exceed it, and dispatched task files are immutable, so enforcing it would keep `check-repo` red on main.
- A `reads` entry with `*` must match at least one file. `*` stays within a path component and `**` spans components.
- Front matter keys, their order, `<a | b>` choices, and list fields are read from `agent/templates/` when the check runs, so a template change needs no code change.
- `direct-io` bans items that reach the operating system (`Instant::now`, `SystemTime::now`, `tokio::time`, socket types and their constructors, `to_socket_addrs`, `tokio::net`, `std::os::unix::net`, `std::fs`, `tokio::fs`, `std::thread`, `tokio::spawn`, `tokio::task`, `thread_rng`, `rand::rng`, `rand::random`, `OsRng`, `getrandom`, `from_entropy`). It does not ban all of `std::net`, because address types such as `SocketAddr` are plain values and ARFC 0005 clause 3.1.1 restricts operating system calls. Grouped imports such as `use std::{fs, net}` are not caught.
- `unreachable!()` is banned only with no message. `unwrap()` and `expect(` outside tests are allowed when the line directly above holds only a comment. Test code means files under a crate's `tests/`, files named `tests.rs`, and items marked `#[test]`, `#[cfg(test)]`, or `#[<path>::test]`.
- Not checked, because they need judgment: functions that return success without doing the work, weakened assertions, and mocks of Alloy crates.
- The file set is what git would commit: tracked files plus untracked files that are not ignored, minus `xtask/tests/fixtures/`. A `CLAUDE.md` that is ignored and untracked is not reported, because it cannot be committed without forcing. A tracked one is reported.
- `AGENTS.md` anywhere except the root is a violation (ADR 0004: the single entry). Vendor file names are compared without case.
- The path lock runs only when `--base` is given, and says so when it is skipped. A `task/T-NNNN` branch with no task file is a violation.
- The repository root is the parent of `CARGO_MANIFEST_DIR`, fixed at build time.

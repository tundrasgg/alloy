## Summary

`alloy-rt` now has `PortProtocol`, `PortHolder`, `Host::port_holders`, and the
`os` implementations for Linux (`/proc/net` and `/proc/<pid>/fd`) and Windows
(the extended TCP and UDP tables and `QueryFullProcessImageNameW`), as clause
3.1.18.5 says. The `mem` implementation is not built: `MemMachine` and
`MachineConfig` live in `crates/alloy-sim`, outside `touches`. Until it is,
the workspace does not compile, so `cargo xtask ci` fails.

## Changes

- `crates/alloy-rt/src/host.rs`: `PortProtocol`, `PortHolder`, and the `port_holders` trait method with its docs.
- `crates/alloy-rt/src/lib.rs`: exports the two new types.
- `crates/alloy-rt/src/os/host/ports.rs`: new. Parsers for `/proc/net` lines, `socket:[N]` links, and Windows table rows, the name to text steps, and the sort, dedup, and 256 bound, with unit tests that run on every platform.
- `crates/alloy-rt/src/os/host/linux.rs`: `port_holders` from `/proc/net/{tcp,tcp6,udp,udp6}`, finding owners through the `fd` links and names through `comm`.
- `crates/alloy-rt/src/os/host/windows.rs`: `port_holders` through `GetExtendedTcpTable` and `GetExtendedUdpTable` (AF_INET, then AF_INET6, 4 retries at most) and `OpenProcess` plus `QueryFullProcessImageNameW`.
- `crates/alloy-rt/src/os/host/other.rs`: `port_holders` returns `Unsupported`.
- `crates/alloy-rt/src/os/host/mod.rs`: `OsMachine::port_holders`. Port 0 gives `InvalidInput`. Otherwise it runs on the blocking pool and sorts and bounds the result.
- `crates/alloy-rt/src/os/host/tests.rs`: an `os` test that binds a UDP socket and a TCP listener on `127.0.0.1` and `[::1]`, port 0, and finds each with its own pid and name. A connected stream's port gives no entry with its pid, the listener's port gives none once it is dropped, and port 0 gives `InvalidInput`.

## Decisions

- Port 0 is refused before the platform is consulted, so it gives `InvalidInput` on every platform, `other` included.
- A failure to read `/proc` itself gives `Os`. The skip rule covers only per-process directories, links, and files.
- The parsers are pure functions in `ports.rs`, so Linux and Windows parsing is tested on both platforms.

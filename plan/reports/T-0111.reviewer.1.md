| F1 | fix | `crates/alloyd/src/channel/proto.rs:441` and `:469` | `decode`, documented as the one place a node message is read, drops a `NodeStatus` that breaks ARFC 0006 section 4.3 (over 64 addresses, an address not 4 or 16 bytes, a `release` over 64 bytes). It also drops a `JoinHello`, `VersionRefusal`, or `NodeStatusReply` whose release string is over 64 bytes, a bound ARFC 0002 section 3.13 does not state. | ARFC 0006 clause 3.14: the leader "replies `INVALID`, changing nothing, when the message breaks section 4.3". ARFC 0002 section 3.13 gives no length for `JoinHello.release`, so a joiner whose release is over 64 bytes gets silence, not a `VersionRefusal`. Scratch test: `ODD ADDRESS: Err(Bounds)`, `LONG JOIN_HELLO RELEASE: Err(Bounds)`. | The channel drops only what ARFC 0002 section 3.13 and its limits make it drop. A `NodeStatus` that breaks section 4.3 reaches the clause 3.14 handling and gets `INVALID`. Strings with no stated bound are bounded only by the message size. A test covers both cases. |
| F2 | fix | `crates/alloyd/src/channel/requester.rs:214` | `Requester::receive` takes no time, so a reply that comes after its request's time limit ends the request whenever `receive` runs before the `poll` that would end it as `TimedOut`. Its doc says such a reply is dropped. | ARFC 0002 section 3.13: "a reply that arrives after its request's time limit is not taken". Scratch test: `LATE REPLY OUTCOME: [Ended { .. outcome: Reply(..) }]`, taken after the limit had passed. | A reply that arrives at or after `first_sent + limit` is never taken, whatever order the caller uses for `receive` and `poll`, and a test covers it. |

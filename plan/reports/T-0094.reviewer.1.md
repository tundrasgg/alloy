Attack A (crash chaos, 1,000 seeds, each run twice). This was a temporary test file in `crates/alloy-sim/tests/`. One host has `block_size` 512 and a device `/dev/d0` of 8 KiB. Start 1 runs 60 seeded operations, each followed by a 1 ms sleep. The operations are create, write, truncate, `sync` of files, rename, remove, and `sync_dir /`, plus device writes and device syncs. Each seed has a crash armed after 1 to 70 polls, under `Lost`, `Seeded`, or `Torn` (seed mod 3). Start 2 reads back the whole namespace and the whole device. The test keeps its own model of the namespace and file bytes. It works in one directory, so durable state is a prefix and the model needs no knowledge of the implementation.

- Under `Lost`, the files must equal exactly the names at the last `sync_dir /`, each with its bytes at its last sync, and the device must equal its bytes at its last sync.
- Under `Seeded` and `Torn`, when no namespace change was unsynced, the names must equal the durable names. Every file and the device with no unsynced data change must hold exactly its durable bytes.
- Both runs of each seed must give the same trace hash.

F1 fix (D-0043), checked by reading `Core::start` and `Core::new_rng` (`crates/alloy-sim/src/host.rs`). Instance `i` of start `k` draws `(host, owner, i)`. The owner follows the replay chain only while `i` is below the count that the replayed start had built when the replay began. Every other instance draws its own start's stream. A start gains a replayer only after it has crashed. Any instance it builds after that, through a registry held outside the host, has an index at or above the limit and draws a stream that no replayer draws. The regression test `extra_instances_of_two_replays_of_one_start_draw_distinct_streams` reproduces Attack R of `T-0076.reviewer.2` and passes.

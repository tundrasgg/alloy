## Issues

- `spec-issue`: the ACME account key has no type in `spec/arfc-0008-native-api.md` clause 3.8, and `agent/eng/crypto.md` now says every new signing key is Ed25519 unless an ADR says otherwise. RFC 8555 section 6.2 requires ACME servers to implement only ES256 (EdDSA is a SHOULD), so an Ed25519 account key may be refused. This predates T-0041.
- `follow-up`: no build task can implement ARFC 0002 section 2's P-256 rules until a dependency for RFC 6979 P-256 signing and `alloy-rt`-seeded key generation is chosen through `agent/eng/deps.md` (see F1).

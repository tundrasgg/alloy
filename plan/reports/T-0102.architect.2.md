## Summary

Round 2 resolves both `block` findings and all four `fix` findings of `plan/reports/T-0102.reviewer.1.md`, and the three notes. Forwarding through an anchor without `control` now has a defined control session, per-origin request ids, no anchor queue, and stated bounds. At-rest key rotation is crash safe at every point. `JoinRequest` no longer names a mesh key. Cleartext is allowed only under `mem`. The TLS exception lists every value the provider draws. The status message path that D-0047 relies on (node channel, VNI 0, home session) is unchanged.

## Changes

- F1 (block): `spec/arfc-0002-identity-and-join.md` section 3.13 defines the control session of an anchor without `control` (to which control node, published addresses only, kept open, reopened in 5 s). It also defines forwarding: the request goes unchanged with the origin session's mesh key and number, the outer `request_id` is 0, and the reply comes back the same way. The anchor keeps no per-request state and no queue, drops while no control session is open, and forwards at most 2,000 per s. Once-only is kept per pair of control session and origin session: at most 8,192 pairs, each forgotten 30 s after its last request or when the session closes, with new pairs dropped at the bound. No request is resent after 10 s. `Forwarded.origin_session` was added, and sections 7 and 8 and "This version" were updated.
- F2 (block): `spec/arfc-0002-identity-and-join.md` section 3.14: every rename is made durable before the next write (Linux directory `fsync`, Windows `MoveFileExW` write-through, both cited). `at-rest.key` holds both keys during a rotation. Rotation is three ordered writes, every crash point is shown to open `secrets`, and `alloyd` finishes a rotation at start.
- F3 (fix): `spec/arfc-0002-identity-and-join.md` section 3.3 step 6 and `JoinRequest`: the `mesh_pub` field is removed (`reserved 4`). The mesh key is always the session's, as a `forwarded` carries it.
- F4 (fix): `agent/eng/crypto.md` rule 4, `spec/arfc-0008-native-api.md` clause 3.8.1 and section 8, and ADR 0042: cleartext is allowed only under `mem`. Any other `net` implementation runs TLS or serves neither the API nor `stream`.
- F5 (fix): the same three files list everything the provider draws: both hello randoms, the legacy session id, the extension order seed, and the key share secrets (ML-KEM included). Each is cited to rustls 0.23.46 source lines. Tickets, resumption, early data, and ECH are off.
- F6 (fix): `adr/README.md`: row 0042 now sits between 0026 and 0048.
- F7 (note): `spec/arfc-0004-path-manager.md` section 3.6, `spec/arfc-0002-identity-and-join.md` section 3.14, and `agent/eng/crypto.md`: the self-signed `stream` certificate key counts as an API server certificate key and is held in memory only.
- F8 (note): `spec/arfc-0002-identity-and-join.md` section 3.12: adopting a mount is Linux only. On Windows a mounted folder is a reparse point and is refused.
- F9 (note): `spec/arfc-0002-identity-and-join.md` section 3.13: a `forwarded` may be up to 16,512 bytes, since its other fields take at most 77. `Facts`, `Disk`, and the name and zone strings carry bounds.
- `adr/0042-nodes-talk-to-the-control-plane-over-al-clients-to-the-api-o.md`: node channel forwarding, the TLS draws, the `mem`-only cleartext rule, and crash-safe at-rest rotation.

## Decisions

- Forwarded requests keep the joiner's `request_id`, and once-only is kept per (control session, origin session number) at the control node, so the anchor stays stateless. Why: there is no queue to bound, and a resend carries any request the anchor drops.
- An anchor without `control` uses a dedicated control session to a control node at published addresses, and sends its own node messages there too.
- `JoinRequest.mesh_pub` is removed rather than checked. Why: it can never disagree with the authenticated key. The package is `v1alpha1` and not frozen.

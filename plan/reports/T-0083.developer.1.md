## Summary

`alloy-rt` now exports `OsHost` and `register_os` (ARFC 0005 section 2.6). It has `os` implementations of `clock`, `rng`, `spawn`, `net`, and `disk-io` on one `tokio` multi-thread runtime, with the version 1 configurations of section 4.2.
UDP goes through `quinn-udp`: segmentation offload where the kernel has it, batched receive with receive offload, and packet information for `src_ip` and `dst_ip`. On Linux the socket is set to `IP_PMTUDISC_DO`, so the learned path MTU is honored.
There are 39 new unit tests across the five kinds plus the host, the registration, and the configurations. All 61 crate unit tests, `cargo deny check`, and `cargo xtask ci` pass on the Windows workspace host. Linux and macOS code is type-checked and Clippy-clean but has not run (see Issues).
As an extra check, a throwaway harness outside the repository ran the existing `tests/conformance/rt` cases against `os` on this host. 96 passed, 7 skipped for lack of a block device or Unix sockets on Windows, and 4 did not pass within 60 s. One of the 4 passes given 195 s, and none is an `os` defect (see Issues).

## Changes

- `crates/alloy-rt/src/os/mod.rs`: `OsHost` (start, block_on, shutdown), `register_os`, shared host helpers (`run` enters the runtime context on every poll, `sleep_until` never panics after shutdown), the per-instance `Permit` counter, and host tests.
- `crates/alloy-rt/src/os/config.rs`: `message Empty {}` and `OsDiskIoConfig` with a total Protocol Buffers decoder (unknown fields and groups skipped), plus the `root` rules.
- `crates/alloy-rt/src/os/clock.rs`: monotonic `now` from `std::time::Instant`, never decreasing across threads; `wall` from `SystemTime`; `sleep_until` on `tokio` timers, re-armed if one fires early.
- `crates/alloy-rt/src/os/rng.rs`: `getrandom::fill`, failing only with `Unavailable`.
- `crates/alloy-rt/src/os/spawn.rs`: `tokio` tasks with ids from 1, the 1,048,576 live-task limit, `ShuttingDown` after shutdown, `Cancelled` and `Panicked` joins, and an exact `yield_now`.
- `crates/alloy-rt/src/os/net/mod.rs`: `OsNet` (interfaces with a generation, polled every 250 ms while waiting), TCP and Unix streams and listeners, `Busy`, sticky reset, `Closed` after `shutdown_write`, socket-file mode and removal, and the 4,096 and 65,536 limits.
- `crates/alloy-rt/src/os/net/udp.rs`: batched send with offloaded runs and per-datagram fallback, `MessageTooLong` from the path MTU, the `src_ip` rules, and batched receive with truncation and a queue for offloaded runs.
- `crates/alloy-rt/src/os/net/ifaces.rs`: interfaces from `getifaddrs` on Unix (MTU from sysfs on Linux and `if_data` on macOS) and from `GetAdaptersAddresses` on Windows.
- `crates/alloy-rt/src/os/disk.rs`: `OsDiskIo` and `OsDiskFile`. Paths map below the root, and a component Windows would read as a prefix is `InvalidPath`. One blocking call per batch; whole-batch validation; `O_DIRECT` and `O_EXCL` on Linux, `F_NOCACHE` on macOS, `FILE_FLAG_NO_BUFFERING` on Windows; logical block size from sysfs; `sync` waits for every operation issued before it.
- `crates/alloy-rt/src/os/errors.rs`: maps `io::Error` to `NetError` and `DiskError`. `EMFILE`/`ENFILE` become `TooManyOpen`; codes with no variant become `Os`.
- `crates/alloy-rt/src/os/net/tests.rs`, `crates/alloy-rt/src/os/disk/tests.rs`: unit tests over loopback and a scratch directory.
- `crates/alloy-rt/src/lib.rs`: exports `OsHost` and `register_os`; `forbid(unsafe_code)` became `deny(unsafe_code)`, lifted only in the FFI modules.
- `crates/alloy-rt/Cargo.toml`, `Cargo.toml`: added `tokio`, `quinn-udp`, `socket2`, and `getrandom`, plus `libc` (Unix only) and `windows-sys` (Windows only), pinned exactly as workspace dependencies.
- `deny.toml`: allowed the new crates (licenses under Decisions).
- `Cargo.lock`: 10 packages added.

## Decisions

- Class N: new dependencies, each pinned exactly. `tokio` 1.54.1 (MIT), the standing choice, with features `net`, `rt-multi-thread`, `sync`, and `time` only, and no macros. `quinn-udp` 0.5.16 (MIT OR Apache-2.0), default features off, for offloaded batched UDP and packet information. `socket2` 0.6.5 (MIT OR Apache-2.0). `getrandom` 0.4.3 (MIT OR Apache-2.0), already in the tree. `libc` 0.2.191 (MIT OR Apache-2.0), already in the tree. `windows-sys` 0.61.2 (MIT OR Apache-2.0). Transitive: `mio` 1.2.4 (MIT), `pin-project-lite` 0.2.17 (Apache-2.0 OR MIT), `once_cell` 1.21.4 (MIT OR Apache-2.0), `cfg_aliases` 0.2.2 (MIT), `windows-link` 0.2.1 (MIT OR Apache-2.0), and `wasi` 0.11.1 (Apache-2.0 WITH LLVM-exception OR Apache-2.0 OR MIT, taken under its Apache-2.0 OR MIT options). No research note exists for `quinn-udp`. The task allowed the socket crates, and the lead records them.
- Class N: `alloy-rt` moved from `#![forbid(unsafe_code)]` to `#![deny(unsafe_code)]`. `unsafe` is allowed only in `os::net::ifaces` (`getifaddrs`, `GetAdaptersAddresses`), in `os::net::udp::platform` (Linux `IP_MTU_DISCOVER` and `IP_MTU`), and in the macOS `F_NOCACHE` call. Every block carries `// SAFETY:`. The Clippy direct-io opt-out is on the `os` module, not on the whole crate.
- Class N, spec silent: once the host is shut down, disk operations fail with `DiskError::Io`, `interfaces` with `NetError::Closed`, and sleeps never complete (`tokio` panics on a timer polled after its driver stops). Socket errors with no OS code, as `tokio` gives after shutdown, map to `Closed`.
- Class N, spec silent: `remove` and `rename` of the root return `InvalidInput`. A directory entry whose name is not UTF-8 makes `list` return `InvalidInput`. An open with `O_DIRECT` that the file system refuses (`EINVAL`) returns `Unsupported`. `exclusive` on a block device off Linux returns `Unsupported`, and so does `direct` on Unix platforms other than Linux and macOS.
- Class R: `max_payload` is `min(path MTU - IP header - 8, 65,507 or 65,527)`, which resolves the T-0008 spec-issue on 65,536-byte loopback MTUs as that report proposed. When the MTU cannot be learned, the family minimum (576 or 1,280) is used.
- Class R: ICMP reports that an unconnected UDP socket surfaces (`ECONNREFUSED`, `ECONNRESET`, and `WSAECONNRESET` on Windows) are not passed on: `send` counts the datagram as sent, and `recv` keeps waiting (clause 3.1.8).
- Class R: an offloaded run that the kernel refuses is sent again one datagram at a time, so `SendOutcome` names the failing datagram. `quinn-udp` then turns offload off for that socket.
- Class R: `sync` on a Windows read-only handle returns `Ok` after waiting for earlier operations. Windows refuses to flush without write access, and the handle has no writes to make durable.
- Class R: accepted TCP streams get `nodelay` true, the `StreamOptions` default. An interface MTU the platform does not report is 0. Windows interface names come from `ConvertInterfaceLuidToNameA`; one longer than 15 bytes becomes `if<index>`.

## Issues

- `follow-up`: the Linux and macOS code paths are type-checked and Clippy-clean but have not run. The workspace host is Windows and no Linux machine was reachable. The first run of `cargo xtask ci` on the Linux CI runner is the first execution of `crates/alloy-rt/src/os/net/udp.rs` platform code, `os/net/ifaces.rs` (getifaddrs), and the Linux branch of `os/disk.rs`.
- `test-issue`: `tests/conformance/rt/support.rs:205`: `GateWait::poll` scans every registered waker on each poll. `arfc0005_s3_1_6_an_instance_holds_at_most_1048576_live_tasks` parks 1,048,576 tasks on one gate, which is quadratic on any implementation that polls its tasks. On `os` it had not finished after more than 15 minutes, and I stopped it.
- `test-issue`: `tests/conformance/rt/disk-io/mod.rs`, `arfc0005_s3_1_10_list_returns_every_entry_sorted_bytewise`, creates both `B` and `b`. That gives `AlreadyExists` on a case-insensitive file system (Windows, default macOS), so the `os` run there needs a skip or names that differ by more than case.
- `follow-up`: for T-0084, on `os` `arfc0005_s3_1_10_an_instance_holds_at_most_65536_open_handles` passes but takes 195 s on this host (one blocking open per handle). `arfc0005_s3_1_10_list_above_1048576_entries_is_too_many_entries` creates a million real files and did not finish in 60 s. The `os` harness needs a long timeout or a reasoned exclusion for them.
- `spec-issue`: `spec/arfc-0005-simulator-and-natlab.md` section 2.6 does not say what `OsHost::block_on` does from inside a task (`tokio` panics) or after `shutdown`. It also names no `DiskError` or `NetError` for operations after `shutdown`. The readings taken are under Decisions.
- `spec-issue`: `spec/arfc-0005-simulator-and-natlab.md` clause 3.1.9: no platform call creates a Unix socket file with given bits, so `os` applies `unix_mode & 0o777` with `chmod` right after `bind`. Until then the file has the process umask's bits. The clause should say whether that window is acceptable.
- `process-issue`: `agent/eng/testing.md` says no test binds a real port, sleeps, or reads the wall clock. The task requires unit tests of the `os` seams on the host OS, which can only do those things, so the `os` unit tests bind loopback ports, sleep 5 ms, and read both clocks. The rule should exempt the `os` implementations' own unit tests.
- `process-issue`: the diff is about 4,800 lines: 3,300 of implementation, 1,400 of tests, and 100 of manifests and lockfile. That is over the 2,000-line target. Five seams on three platforms do not fit one task. One task per seam, or net split from the rest, would.

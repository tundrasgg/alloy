## Summary

PB-0002 describes the Alloy Console: a transcript of a cloud admin's first use, users and jobs, seven screens in build priority (Nodes, Instances, VPCs, Mesh, then Overview, Operations, Login and Settings), each with its data and its actions as CLI commands, the command palette, keyboard map, URLs, live updates, empty and error states, themes, and text wireframes.
Private clusters reach the console through a new `alloy console` command that runs a loopback bridge reusing the CLI's pinned API CA, so no browser ever meets a certificate warning or needs a trust store change.
What the browser needs from the API is listed in the brief under Requested design changes and below as `spec-issue` entries. No ARFC was changed.

## Decisions

- Private clusters use a loopback console bridge (`alloy console`) rather than a user-installed API CA. Why: keeps ARFC 0019 section 8's pin, changes no trust store, needs no public name (principle 3); a user-installed CA would trust a cluster key for every name unless name constraints are enforced, which is unverified.
- Browser wire form preference: Connect (R-0007 option A), since one form then serves the browser, `curl` (rule A20), and GET reads. The server-side choice stays the architect's.
- Session token preferred as an `HttpOnly`, `Secure`, `SameSite=Strict` cookie plus a non-simple request header, so page script cannot read it and other sites cannot use it.
- Console URL paths are resources' full names (rule A2); `Copy link` copies the direct API address, which another member opens with `alloy console <link>`.
- Screens follow the task's order: Nodes, Instances, VPCs, Mesh. The Mesh screen needs a path API that does not exist yet; until then the Nodes `MESH` column covers rung 3.
- Instance, VPC, mesh, and operation actions are marked provisional because ARFC 0019 section 3.1 has no commands for them yet.

## Issues

- spec-issue: `spec/arfc-0008-native-api.md` section 2 and clause 3.10 name no browser-callable form; the console needs every unary method and `Watch` (server streaming). Product prefers Connect (R-0007 A); with gRPC-Web (R-0007 B) a separate JSON form is still needed for rule A20.
- spec-issue: `spec/arfc-0008-native-api.md` has no `Watch` clause: initial state, resume version, deletions, `Compacted` meaning relist, and a keepalive interval for stale detection. Clause 3.13 lacks `WatchNodes`.
- spec-issue: `spec/arfc-0008-native-api.md` clause 3.12: browser calls need HTTP/2 to avoid the per-origin HTTP/1.1 connection limit with several Watches, and API paths must stay disjoint from console paths (full names, `/overview`, `/mesh`, `/login`, `/settings`, `/operations`, `/join-tokens`).
- spec-issue: `spec/arfc-0008-native-api.md` has no method returning the caller (principal, org, cluster roles, default project, token expiry); the console needs it for navigation and ARFC 0019 clause 3.1.11 needs it to print the principal.
- spec-issue: `spec/arfc-0019-cli-and-console.md` clause 3.2.5 says the API reports standing warnings but `spec/arfc-0008-native-api.md` names no method; needs `ListStandingWarnings` and its Watch.
- spec-issue: `spec/arfc-0008-native-api.md` clause 3.3 lacks List, Get, and Watch of operations and the stage fields of rule A16 (also raised by T-0087).
- spec-issue: `spec/arfc-0008-native-api.md` clause 3.7.1 and `spec/arfc-0007-tenancy-and-iam.md` section 2.3: no method turns a login code into a session token without making an access key, none makes a session token from an access key for `alloy console`, and none refreshes or revokes one (log out). Only `authorization: Bearer` is accepted; the brief asks for a cookie form with a CSRF guard. Needs an ARFC 0020 check.
- spec-issue: `spec/arfc-0019-cli-and-console.md` section 2 and clause 3.1.2: add `alloy console [<link>] [--no-browser] [--context <name>]` and the console bridge (loopback only, `Host` check, pinned TLS, one-use launch path, session revoked on stop); state the console's content security policy, that each node serves its own release's console, and that the API sends no CORS headers.
- spec-issue: `spec/arfc-0019-cli-and-console.md` clause 3.2.3: the method-to-CLI-command mapping must ship with the console, generated from the CLI's definitions (clause 3.1.10), so the command shows with no request.
- spec-issue: `spec/arfc-0019-cli-and-console.md` section 3.1 has no `instance`, `vpc`, `subnet`, `security-group`, `mesh path`, or `operation` commands, so the matching console actions are provisional (principle 7).
- spec-issue: `spec/arfc-0019-cli-and-console.md` section 3.2 should carry C1 to C19 and PB-0002's keyboard map, URLs, and live update rules.
- spec-issue: `spec/arfc-0004-path-manager.md` and `spec/arfc-0006-control-plane.md` section 2.6: no API reports per-session paths (nodes, class, relaying anchor, RTT, since), which rung 3's check and the Mesh screen need; ARFC 0004 section 3.7 requires showing relay throughput but `Node` has no field for it.
- spec-issue: `spec/arfc-0011-compute.md` clause 3.1.5: serial input from a browser needs a unary method (no client streaming, R-0007); "serial console" collides with "console", and the brief says "serial output".

- follow-up: D-0041 maps "Alloy Console", "Virtual Machines", and "Underlay Mesh" to glossary terms; PB-0002 uses the glossary words (instance, mesh) in navigation until that mapping task runs.

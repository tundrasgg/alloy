## Changes

- `crates/alloy-sim/src/hook.rs`: a per-thread, nesting hook mark. A world call from inside an observer of any world returns `Busy` (F1).
- `crates/alloy-sim/src/core.rs`: the shared run state behind one `core` lock: the executor, hosts, timers, and events. It also holds the pending record queue, which is flushed once `core` is released, and the deferred work (`After`): future drops, joins, and boot calls. It holds task polling with `task-poll` and `task-end` records, cancel, timer firing with `timer-fire`, retiming after a rate change, and event processing.
- `crates/alloy-sim/src/exec.rs`: task owners (control or host and `TaskId`). Futures are taken out of their slots to poll, so no lock is held while task code runs. Adds install for the `boot` task, parking for stalls, and `Joint` for join and the live count per instance.
- `crates/alloy-sim/src/host.rs`: `Boot`, `HostBoot`, `HostConfig`, `HostState`, the host clock arithmetic of clauses 3.1.4 and 3.3.5, and `MemClock`, `MemRng`, `MemSpawn`, `MemTaskHandle`, `MemNet` (`lo` only), and `MemDiskIo` (refuses every call). Also the `mem` registry with a version 1 config check, and host start, crash, stall, and armed or pending crash handling.
- `crates/alloy-sim/src/fault.rs`: `Fault` (`Crash`, `Restart`, `ClockRate`, `ClockStep`, `Stall`) and `Unsynced`. Adds the stateless and state checks, `apply`, `schedule` (limit 1,048,576), and skipped-fault records.
- `crates/alloy-sim/src/history.rs`: `History`, `Call`, `ClientId`, and `Entry` (clause 3.6.2).
- `crates/alloy-sim/src/world.rs`: `add_host`, `host_state`, `runtime`, `apply`, `schedule`, and `history`. World sleeps now use the core timers.
- `crates/alloy-sim/src/run.rs`, `crates/alloy-sim/src/trace.rs`, `crates/alloy-sim/src/lib.rs`: the run loop on the new core, the new record kinds, and the exports.
- `crates/alloy-sim/tests/hosts.rs`: 12 tests: start records, clock rate, step, and retiming, crash and restart with rng replay, armed and own-task crashes, stalls, schedule, the registry, a host task panic, determinism over 40 seeds, and histories.
- `crates/alloy-sim/tests/rt_mem.rs`: a `mem` harness that runs the clock, rng, spawn, and runtime checks of `tests/conformance/rt`.
- `crates/alloy-sim/tests/runs.rs`: F1 test. Two worlds on two threads, whose observers call each other at the same moment, get `Busy` and do not deadlock.
- `crates/alloy-sim/Cargo.toml`, `Cargo.lock`: dev-dependency on `conformance-rt`.

## Decisions

- Class N: a world call from inside a hook is detected by a per-thread mark that nests (`hook.rs`), not by a list kept per world. This is the only state that lives outside a world. It is what lets a call on any world, from an observer of any world, return `Busy` (F1).
- Class N: records are queued while `core` is held and written to the trace after it is released, in queue order. Observers therefore never run under `core`. A `mem` seam call from inside an observer works, and its records follow the current record.
- Class N: cut. The `mem` `disk-io` of this slice refuses every call (`Unsupported`, and `Io` after a crash). `HostConfig` has no `devices`, `capacity`, or `block_size`, and `Fault` has no `Disk` or `Capacity` variant. `HostConfig::interfaces` and `Fault::Link`, `Partition`, and `Heal` are left to T-0077. Leaving fields out is better than accepting values that would have no effect.
- Class N: until T-0077, the `mem` `net` lists `lo` at generation 1 and never changes it, so `interfaces(Some(g))` with `g >= 1` does not complete. `bind_udp`, `connect`, and `listen` return `Unsupported`.
- Routine: `mem` rng stream = `Stream(seed, "rng", [host, source start, index])`, where the source start is the `rng_replay` start or the current start. An armed crash counts host polls whose number is above the last poll number when it was armed. A boot closure that panics gives the `boot` task a future that panics on its first poll. A `Call` carries its history's id, and `complete` ignores a `Call` from another history.
- Routine: the `mem` factories accept configuration version 1 only, and walk the payload as unknown Protocol Buffers fields (section 4.2).

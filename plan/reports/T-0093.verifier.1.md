## Summary

`tests/e2e/` holds the M11 rung 1 check, written from ARFC 0017 clauses 3.15, 3.16, and 3.17. `rung1.ps1` runs on the Windows client: for each Linux node over SSH as root, then for the local machine, it checks a clean start, snapshots, installs from the pinned URL, checks the install and the snapshot, installs again, uninstalls, checks that the snapshot equals the first, and uninstalls again.
The host snapshot of clause 3.17.6 is `host-snapshot.sh` (Linux, with `--proxmox` for the Proxmox VE sections) and `host-snapshot.ps1` (Windows). Both only read and drop counters, statistics, and timestamps. `rung1-probe.sh` reads a node's install state.
Machines are parameters only (`-Version`, `-LinuxNode`, `-ProxmoxNode`). The driver prints one PASS or FAIL line per check and a `SUMMARY` line, and exits 0, 1, or 2 (usage).
Not run against real machines (out of scope). Its logic was exercised offline: the Windows snapshot run twice on this machine, the Linux scripts in an offline container, and the comparison code through a harness that loads its functions.
Two acceptance commands do less than they appear to (see Issues). The evidence includes stronger equivalents.

## Decisions

- The Windows snapshot leaves out the `Status` of services and keeps `Name`, `DisplayName`, `StartType`, and `ServiceType`. Windows starts and stops demand-start and trigger-start services on its own, so `Status` would fail comparisons with no cause on the machine. The start type is what an install changes, like `systemctl list-unit-files` on Linux. Class N, since it reads clause 3.17.6. See the matching spec-issue.
- In `/etc/pve` the snapshot hashes every regular file except the cluster file system's top-level status dot files (`.version`, `.members`, `.vmlist`, `.clusterlog`, `.rrd`, `.debug`) and temporary `*.tmp.<pid>` names. It removes the `"timestamp":<n>` field before hashing, so HA `lrm_status` and `manager_status` do not change on their own. Class N, same reason.
- The driver passes each shell script base64-encoded in the SSH command line, to `sh -s`. Nothing is copied to a node, and no remote command runs beyond the snapshot, probe, install, and uninstall. Class R.
- The second uninstall uses `install.sh --uninstall` or `install.ps1 -Uninstall`, since the first uninstall removes the installed script (clause 3.16 step 7). Clause 3.16 says the two forms are equivalent. Class R.
- The driver does not install on a machine that is not clean. It reports the precondition as a FAIL and moves to the next machine, so it never acts on a machine whose prior state it cannot restore. Class R.

## Issues

- `spec-issue`: `spec/arfc-0017-upgrades-and-versioning.md` clause 3.17.6 lists `Get-Service` in the Windows snapshot but does not say whether the running `Status` is part of it. That status changes on its own for demand-start services. The scripts compare the start type only, and the clause should say which properties make up each Windows snapshot.
- `spec-issue`: `spec/arfc-0017-upgrades-and-versioning.md` clause 3.17.6 removes only counters, statistics, and timestamps. Other state also changes with no action by Alloy: IPv6 temporary addresses rotating, DHCP leases, Proxmox VE key rotation under `/etc/pve`, and the cluster file system's status files. The clause should say how the comparison treats them. The scripts' choices are in Decisions and `tests/e2e/README.md`.
- `spec-issue`: clause 3.15 step 8 requires `alloy version` to print the version, but no ARFC gives that command's output format. The check accepts any whitespace-separated word equal to `<version>` or `v<version>`.
- `process-issue`: acceptance 2 in `plan/tasks/T-0093.md` passes `[ref]$e` with `$e` undefined. PowerShell then raises an error that does not stop the command, and it exits 0 without parsing, even for a broken file. A working form initializes the variables first: `$t = $null; $e = $null; ...ParseFile(..., [ref]$t, [ref]$e)`.
- `process-issue`: acceptance 1, `sh -n tests/e2e/*.sh`, parses only the first file the glob expands to. `sh` treats the rest as arguments to that script. Use `for f in tests/e2e/*.sh; do sh -n "$f" || exit 1; done`.
- `follow-up`: the coexistence scenarios of clause 3.17.6 bullets 4 to 6 (Grafana Alloy objects, Docker with a published port and Tailscale up, a Proxmox VE firewall with a running guest kept reachable) are not covered. They need machine setup beyond rung 1. Bullet 2 (snapshot of a joined node) belongs to rung 2. All of them can reuse `tests/e2e/host-snapshot.sh` and `tests/e2e/host-snapshot.ps1`.
- `follow-up`: the 3.15 requirements that need fault injection (the download timing "must", interrupted and truncated scripts, exit codes 4, 5, and 6) cannot be checked on clean real machines. They belong to a system-level test of the install scripts.

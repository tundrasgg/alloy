## Summary

`alloy login <login code>`, `alloy login --issue-code` (local admin socket, or the API port with a context), and `alloy node list` (table, `--output json|yaml`) are built, registered, and tested end to end against a control node made by `alloyd::init::init` and served by `ControlNode`. The grammar now takes flags with values, an operand, and `--color`. T-0091 F2 and F3 are folded.
`init` and `join` are not built and stay unregistered, so they are still usage errors. Step 4 of section 3.1 and step 2 of section 3.3 enable and start `alloyd`, and step 1 needs facts about the machine: root or elevation, kernel and Windows build, free space, cores, memory, and disks for `JoinOptions.facts`. No `alloy-rt` seam provides any of these, and clippy bans `std::process::Command` outside `alloy-rt`. See Question.
`task/T-0136` is merged in at `9666f6a`, which includes `alloyd::join::join`.

## Changes

- `crates/alloy/Cargo.toml`, `Cargo.lock`: depends on `alloy-api`, `alloy-crypto`, `alloy-id`, `alloy-proto`, `alloy-rt`, `alloy-seam`, `prost-types`; dev-depends on `alloyd`.
- `crates/alloy/src/grammar.rs`: `FlagSpec`, operands, `--flag v` and `--flag=v`, global `--color`, help that lists every flag with its default. `Try:` lines hold only words from the command table and are offered only when they parse (F2). Echoed words are escaped (F3).
- `crates/alloy/src/text.rs`: `escape` for control characters.
- `crates/alloy/src/lib.rs`: `run(args, &Env, out, err)`, exit codes 0 to 6, per-stream `Style` (T12), `Failure` rendering (clause 3.1.8). Command-line checks run before the runtime starts.
- `crates/alloy/src/machine.rs`: the `os` runtime rooted at the config directory's file system root; the config directory of clause 3.1.9.
- `crates/alloy/src/config.rs`: the `contexts` and `credentials` text files (the latter mode 0600, with an inherited ACL on Windows), each replaced atomically; the context naming rule of 3.1.11.
- `crates/alloy/src/api.rs`: endpoints tried in order within 10 s in all. A certificate mismatch exits 1 with no `Try:` line, silence exits 6, and API errors map to their exit codes with `next_step` as the `Try:` line.
- `crates/alloy/src/login.rs`: login (with `replaces`, key name per ARFC 0007 3.9.3) and `--issue-code`, the code printed once on stdout.
- `crates/alloy/src/node.rs`, `crates/alloy/src/repr.rs`: the 3.1.15 table and colors; the proto3 JSON mapping and the same tree in YAML.
- `crates/alloy/src/tests/{mod,e2e}.rs`: CLI tests through `run`, and the loopback scenario (issue, login, spent code, list, JSON/YAML, re-login replacing the key, forged fingerprint, silent endpoint, missing key).

## Decisions

- N: the access key goes in `<config>/alloy/credentials`, readable only by the user. No OS keychain is used, because there is no seam for one (clause 3.1.9 allows the file).
- N: `alloy login` with no argument (the "confirm the current key" form) and `alloy login <address>` are usage errors, since rung 2 does not list them (3.15).
- R: `--output json` leaves default-valued fields out (the proto3 JSON default); an unknown enum value is printed as a number.
- R: the key name falls back to `computer` when no hostname is found; the hostname comes from `COMPUTERNAME`, `/proc/sys/kernel/hostname`, `/etc/hostname`, then `HOSTNAME`.
- R: `machine.rs` repeats alloyd's 10-line `OsDiskIoConfig` encoder, because alloyd's is private.

## Question

How should `alloy init` and `alloy join` enable and start `alloyd` (ARFC 0002 3.1 step 4, 3.3 step 2) and read the machine facts of 3.8 and `JoinOptions.facts` (root or elevation, kernel or Windows build, free space, cores, memory, disks)? No `alloy-rt` seam provides these, and `std::process` is banned outside `alloy-rt`.

1. (Recommended) A spec task adds a `host` seam to ARFC 0005 and `alloy-rt` covering service enable, start, stop, and disable for `alloyd` (systemd and the Windows SCM) and these facts. T-0141 round 2 then builds `init` and `join` on it. This keeps rule 2 intact.
2. `alloyd` (T-0136) exposes `enable_and_start` and `facts` as library functions, the way it already calls the Windows SCM, with a recorded exception to rule 2 for systemd.
3. Ship rung 2 with `init` and `join` registered but refusing to run, and leave service management to the install script. This breaks ARFC 0002 step 4, so it needs a spec change.

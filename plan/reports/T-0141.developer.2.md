## Decisions

- N: `join` enables and starts `alloyd` after `alloyd::join::join` returns. That call runs steps 3 to 7 in the CLI's process (D-0069). `--no-wait` is therefore not registered.
- N: `Facts.os` is `windows <major>.<minor>.<build>`, as section 3.3 step 6 states. `alloyd` compares it to `windows` (see Issues).
- R: the default advertise address is the first address of the interface that the default route uses, read from `/proc/net/route` and `/proc/net/ipv6_route`.
- R: the CLI re-gathers the data directory facts for `alloy_id::datadir::check_for_init`, because alloyd's gathering code is private.

## Issues

- `follow-up`: `alloyd` treats a node as Windows only when `facts.os == "windows"` (`crates/alloyd/src/nodes.rs:67`, `join.rs:388`). Spec facts are `windows 10.0.x`, so a Windows client node would get default roles. Rung 2's Windows join needs a `starts_with("windows ")` fix in T-0136's crate.
- `follow-up`: `init` skips the `addresses` check. `alloyd::init::InitOptions` takes no `cluster_id`, so the CLI cannot draw and check it as section 3.8 says (`crates/alloyd/src/init.rs:60`).
- `follow-up`: the `names` check does not cover `nftables` tables (no seam reads them) or users and groups outside the files. Guest ids are read from `/etc/passwd`, `/etc/group`, `/etc/subuid`, `/etc/subgid`, and `/proc/*/status`. The ports check does not name the process holding a port (`crates/alloy/src/setup/checks.rs`).
- `follow-up`: `cargo xtask ci` does not yet install the test service or set `ALLOY_TEST_SERVICE=1` on CI hosts (ARFC 0005 section 5). `xtask/` is outside `touches`.
- `process-issue`: `touches` lists `tests/conformance/rt/host/**`, but the path lock lets only `verify` tasks write it (`agent/core/4-evidence.md`). So the conformance suite is left to the verify task that `plan/STATE.md` names. The rules are unit-tested in each crate instead.
- `follow-up`: `alloy-sim` gives `HostConfig.machine` no `Debug` output, so the existing `Debug` test stays as it is (`crates/alloy-sim/src/host.rs`).

## Summary

ARFC 0007 section 3.10 now makes the local admin a full break-glass administrator: everything the cluster role `cloud-admin` allows plus `iam:*` in every org, with no deny binding it.
Every local admin call, reads included, is audited as `root@<node name>` in the cluster chain and in each org it touches, and every successful write raises the standing warning `local-admin-used` for 7 days.
The last `cloud-admin` rule (old clause 3.10.8) is removed, and sections 3.3, 6, 7, and 8 are reworked to match. ADR 0055 supersedes ADR 0050.
ARFC 0020 is not weakened and is unchanged, so the task is not blocked.

## Decisions

- The fixed policy is two parts: what `cloud-admin` allows, plus `iam:*` on every resource in every org. Reason: no ARFC says what `cloud-admin` allows inside an org, and F2 needs a caller that can detach a policy from any org under any deny. The task's scope names these actions.
- The local admin gets no access to the contents of an org's resources, as clause 3.3 says of cloud admins. Reason: recovery needs identity state only. It can reach tenant data only by granting a principal access inside the org, which that org's chain records.
- Local admin reads are audited, so they need quorum and are never stale. Reason: D-0020 says every action is audit-logged, and ARFC 0018 clause 3.3.1 records break-glass access.
- A call that touches an org is recorded in that org's chain as well as the cluster chain. Reason: this is what clause 3.3 requires of break-glass access, and it carries the I-02 argument.
- The standing warning is one per cluster, kind `local-admin-used`, lasts 7 days after the latest successful local admin write, and has no command that clears it. Reason: a stolen `cloud-admin` key or the root that used the socket could otherwise clear it. One record keeps the state bounded (I-21). Reads raise no warning.
- The last `cloud-admin` rule is removed, not kept as a guard. Reason: the local admin can always make one, and the rule promised only that such a user exists, not that anyone can use it (F1).
- The socket serves every native API method except `ExchangeLoginCode`. Reason: an exchange is authenticated by its login code, not by a principal.
- The ruling still does not rest on the cluster key. Reason: ARFC 0002 section 2 lists it as held by the control plane, and its custody across control nodes is open (ARFC 0002 section 9). Section 8 says that root holds it wherever a control node does.

## Issues

- `spec-issue`: ARFC 0019 clause 3.2.5 lists the standing warning kinds without `local-admin-used`, and requires a command that removes each warning, which this one does not have. Clause 3.1.14 still limits the local admin to three commands. T-0045 should cover both (`spec/arfc-0019-cli-and-console.md`).
- `spec-issue`: I-02 names only "a policy in that org" as the way across the org boundary. ARFC 0007 clause 3.3 has a second, the break-glass action recorded in the org's chain, which the local admin now uses. The invariant should name it (`agent/domain/invariants.md`).
- `spec-issue`: no ARFC names the `iam` methods that create, list, enable, and disable users, grant and remove roles, or attach and detach policies, nor what the cluster role `cloud-admin` allows. Clause 3.10.7 fixes the outcomes the local admin needs, and the methods need a spec task before any build task cites it (`spec/arfc-0007-tenancy-and-iam.md`, section 2.4).
- `spec-issue`: carried from T-0044: `cluster:UpdateNode` is not stated to refuse removing the `control` role from the last control node, which would remove every local admin (`spec/arfc-0002-identity-and-join.md`, section 3.9).
- `follow-up`: the `Decisions` lines of ARFC 0002 and ARFC 0019 still name ADR 0041. They should name ADR 0055 (`spec/arfc-0002-identity-and-join.md`, `spec/arfc-0019-cli-and-console.md`).
- `follow-up`: PB-0001 says `sudo alloy login --issue-code` prints a code for `admin`. It should mention the standing warning that follows, and that routine `sudo alloy token create` raises it too (`product/briefs/PB-0001.md`).
- `follow-up`: conformance cases in `tests/conformance/authn` for clauses 3.10.1 and 3.10.5 to 3.10.8: recovery under a deny on the org, recovery with no `cloud-admin` user left, removing the last `cloud-admin` succeeding, audit records in both chains for a read, a read refused without quorum, and the warning's start and its end after 7 days (`spec/arfc-0007-tenancy-and-iam.md`).

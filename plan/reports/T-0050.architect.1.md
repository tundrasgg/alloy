## Decisions

- The scenario is a control task, a `Send` future scheduled with the host tasks. It writes no `task-*` records, and its result, together with any host panic, observer panic, middlebox panic, or trace file error, decides `pass`, `fail`, or `liveness` (clause 3.2.8).
- The topology is a forest of networks, each joined to its parent by one router. Routing goes to the exact address, then a routable child prefix, then upward. The hop limit is 64. A `Middlebox` on a router is the plug-in that `alloy-natlab` implements (ADR 0054).
- Link properties apply per network crossing. Partitions are judged by origin host and destination host, so NAT translation does not affect them. A blocked datagram is dropped with reason 2 when it would be delivered.
- `mem` streams are a reliable segment model delayed by the route's latency. An end resets on a reset segment, or 60 s after a byte it sent fails to arrive. On drop, an end sends a reset instead of an end of stream when it holds unread bytes.
- A connection request blocked by a partition, a middlebox, a crash, or a full backlog gets no answer, and `connect` fails with `TimedOut` at 30 s. Requests are never held.
- Crash outcomes for unsynced data come from the crash fault's `Unsynced` mode: `Lost`, `Seeded`, or `Torn`. This makes the old sentence in clause 3.1.12, "loses everything it allows to be lost, using the seed", into a choice the scenario makes.
- A host's wall clock persists across crashes through a rate clock that runs from world time 0. Its `now` restarts at 0 on each start, as clause 3.1.4 already said.
- `Restart { rng_replay }` is the explicit repeat of clause 3.1.5, so a test can model a faulty generator.
- The simulator's own suite is `tests/conformance/sim/`, matching T-0010's `touches`. Section 5 used to name `tests/sim/`, which now holds whole-system scenarios only.
- Defaults: link latency 1 ms, reorder delay 10 ms, queue 1 MiB per sender, MTU 1,500, `icmp_too_big` true, file namespace capacity 1 GiB, budget 3,600 s, wall start 1,800,000,000 s.

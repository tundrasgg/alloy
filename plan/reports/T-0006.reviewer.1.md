## Findings

| id | severity | where | claim | evidence | change |
|---|---|---|---|---|---|
| F1 | block | `spec/arfc-0005-simulator-and-natlab.md:782` | `mem` streams have a buffer (`write` "waits for buffer space") whose size is stated nowhere: not in `StreamOptions` (lines 277-281), clause 3.1.9, or the section 7 table (lines 1134-1152). So the bound, and when `write` starts to wait, is left to the developer and cannot be tested. | I-21 ("Every queue, table, cache, and buffer has a stated bound and a defined behavior at the bound"); `agent/eng/rust.md` architecture rule 6; grep output above. | ARFC 0005 states the `mem` stream buffer bound in bytes, per direction and per connection, in clause 3.1.9 and section 7. If the bound is configurable, it states the default and the allowed range. |
| F2 | fix | `spec/arfc-0005-simulator-and-natlab.md:681-685` | Under a clock skew fault that speeds a host's clock up, "a task woken by `sleep_until(d)` reads `now() == d`" cannot hold for every `d`. World time has nanosecond resolution (clause 3.2.3), so host time advancing at a rate above 1 skips some integer nanosecond values, and no world instant gives `now() == d` for those. The clause excepts only CPU stall faults. | Clause 3.1.4 `mem` bullet; clause 3.2.3; trace kind `0021` gives the rate offset in parts per million (line 1057). Example: offset +500,000 ppm (rate 1.5). Host time at world ns 0,1,2,3 is 0,1,3,4 (floor) or 0,2,3,5 (ceil). Either way one value of `d` is never read. | Clause 3.1.4 defines how host time maps to world time under skew (rounding), and states the wake guarantee so that it holds under skew too, for example `now() >= d` and the smallest such value, or an explicit skew exception. |
| F3 | fix | `spec/arfc-0005-simulator-and-natlab.md:693-694` | "Bytes come from a stream fixed by the world seed and the host" does not say whether several `mem` `rng` instances on one host share one stream, or whether the stream continues across a host restart. Under the other reading, two instances, or one host before and after a crash, return identical bytes. Real `os` never does that, so the simulator would produce key and nonce repeats that production cannot have (I-07), or hide them. | ARFC 0001 clause 3.3 (several instances of one seam in one process); clause 3.1.6 states task ids continue across restarts but clause 3.1.5 says nothing for `rng`; `agent/eng/crypto.md` rule 4. | Clause 3.1.5 states how `mem` output relates across instances on one host and across restarts of a host, and that no two of them repeat a stream unless the scenario asks for it. |
| F4 | fix | `spec/arfc-0005-simulator-and-natlab.md:892-898` | The trace is a byte format checked by `tests/sim/` (line 1117), but which records are emitted is ambiguous in four places. (a) Is `stream-open`, `stream-data`, or `stream-close` written once per event or once per endpoint host? Connection numbers are per host and a record carries one `host`. (b) Is `stream-data` written per `write` call, per `read` call, or per delivery? (c) What is the `handle` of an `open` record: 0 as a path operation, or the new handle? (d) Is a short read's `length` the requested or the returned length? In addition, the `host` of a `packet-drop` at a link or NAT device is not stated. | Clause 3.2.4; section 4.1 kinds `0040`-`0042`, `0050`, `0032` (lines 1062-1065, 1060); disk operations paragraph (lines 1075-1080); the ARFC template requires formats to be "byte exact" (`agent/templates/arfc.md`). | Section 4.1 and clause 3.2.4 fix each of these choices, so that one sequence of simulator events has exactly one trace byte string. |
| F5 | fix | `spec/arfc-0001-runtime-seams.md:407-409` | Step 0 of the swap does not say when a swap future starts to count: when `swap` is called, or on its first poll. Two tests give different results depending on the reading. Create futures A and B and poll B first: B returns `Busy` (A counts once created) or runs (A counts only once polled). Drop A without polling it: the slot is `Poisoned` (clause 3.16 reads "dropped before it completes") although nothing ran. | Clauses 3.15 step 0 and 3.16 (lines 429-432); ARFC 0001 section 5 says the `tests/conformance/seam/` suite checks clauses 3.10 to 3.17. | Clauses 3.15 and 3.16 state the instant at which a swap future counts as running for `Busy`, and whether a future dropped before its first poll poisons the slot. |
| F6 | fix | `spec/arfc-0001-runtime-seams.md:391-398` | Clause 3.13 cites ARFC 0017 clause 3.3 for one release of skew, but `SeamConfig::to_value` can only write `VERSION`. A release that raises `VERSION` therefore writes the new format at once, while ARFC 0017 clause 3.3 says the new format is written only after finalization, so that rollback to N works. Meanwhile section 8 (line 516) says configuration values "cross only between instances in one process". Whether a `ConfigValue` is ever stored or sent to another node, which decides whether this matters, is not stated. | `spec/arfc-0017-*.md` clause 3.3 ("Release N+1 reads and writes the old format ... The new format is written only after the upgrade is finalized"); ARFC 0001 section 2 (bindings come from control plane state); I-18. | ARFC 0001 states whether serialized configuration values are persisted or cross nodes. If they are, it states how release N+1 keeps writing the previous version until finalization, and the `SeamConfig` interface can express that. |
| F7 | fix | `spec/arfc-0001-runtime-seams.md:124-128` | `SeamState` and `ConfigValue` (line 151) derive `Debug`, which prints their bytes. Live seams `key-provider` and `authn` (lines 463-464) move their state through `SeamState`, and `oidc`'s configuration goes through `ConfigValue`, so key material or client secrets reach debug output. `Binding` and `Slot` inherit the derived `Debug`.

Attack A: concurrency stress on the new hook check. For each seed 0..200, the control task adds three observers. Each observer calls `note`, `random_u64` and `observe` on its own world for every `note` record, and records any result other than `Busy`, 0 and `Busy`. Eight threads and the control task each make 200 `note` calls and 200 draws, so observers run on all nine threads. Every call outside an observer must return `Ok` and a nonzero draw. Each run must end within 20 s with `Pass` and 1,801 records.

Attack B: determinism and fault injection over 1,000 seeds, on one thread, through the changed `emit` and `finish`. The budget is `1 + seed % 300` ns. A re-entering observer, as in attack A, panics at record `1 + seed % 30` on one seed in three. On one seed in seven, the control task returns `Err`. The control task does up to 40 rounds of draw, note, and a sleep of `draw % 4` ns. Each seed runs twice. Both `RunSummary` values, both lines, both observer record lists and both draw lists must be equal. No call inside an observer may do anything, and no draw outside one may be 0.

Attack C: a world call from inside an observer on a different world. World B runs on its own thread and stays open. World A's observer calls `B.note` on each `note` record. Then A's control task writes one note.


The call returned `Ok`, and B's trace gained a `note` record.

Attack D: two worlds on two threads, each with an observer that calls the other world's `note` from `record`. A barrier makes the two observers call at the same time. Each run executes on a helper thread, and the test waits 10 s.

```
test attack_d_cross_world_lock_order ... ATTACK D: results = None (None = deadlock past 10 s)
ok
test result: ok. 4 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 16.10s
```

Cause, by reading. `Shared::in_hook` (`crates/alloy-sim/src/world.rs:123-125`) asks only this world's `Hook` (`crates/alloy-sim/src/trace.rs:42-57`). A thread inside an observer of A is not in B's hook, so `B.note` passes `check` and takes B's trace lock while it still holds A's. A's observer holds A's lock and waits for B's, and B's observer holds B's lock and waits for A's. Neither run can end.

The developer's evidence matches what I observed. The test counts are 28 unit tests and 22 in `tests/runs.rs`. The diff is 2,742 changed lines outside `plan/`. T-0010 has not merged: `tests/conformance/` holds only `rt` and `wire`.

Checks with nothing to report:

- Round 1 F1. Attack A covers both cases of its required outcome on nine threads. The new tests `world_calls_from_an_observer_off_the_run_thread_are_busy` and `an_observer_on_another_thread_leaves_calls_on_the_run_thread_alone` reproduce round 1 attacks 3 and 2.

## Issues

- `spec-issue`: clause 3.2.9 of `spec/arfc-0005-simulator-and-natlab.md` says "a world call made from inside `Observer::record`" without naming a world or a thread. It should say whether that covers a call on a world other than the one observed (finding F1). It should also cover a call made by a helper thread that the observer starts and waits for. The developer's round 2 decision treats that helper-thread call as outside the hook, so it waits on the trace lock. If the observer joins that thread, the run deadlocks.
- `spec-issue`: the round 1 question about clause 3.2.7 step 4 and `sleep_until` past 2^63 - 1 ns is still open.

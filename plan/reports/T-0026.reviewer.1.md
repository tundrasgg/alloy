Attack 2: tamper with the fields outside Noise. With a zero-length prologue (line 44) and lines 54 to 57 putting `type`, `version`, `reserved`, `sender_index`, `receiver_index`, `mac1` and `mac2` outside Noise, none of them enters `h`. `mac1` is keyed by a public value (line 80), so an on-path party can rewrite any of them and recompute `mac1`, and the handshake still completes. The consequence is denial of service only, which an on-path party has anyway. The protocol name binds `v1`, so a rewritten version byte breaks the handshake rather than downgrading it. The hybrid flag is inside the encrypted payload, so it is authenticated. This is F1, at `fix`.

Attack 3: recover past session keys after the handshake. `k1` and `k2` are a pure function of the chaining key (`split_raw` above). Section 3.3 requires only `k1`, `k2` and `prk` to be zeroized. `snow` 0.10.0 zeroizes nothing and implements no `Drop`. So the chaining key, and the ephemeral private key, stay in freed memory. This is F2, at `fix`.

Invariants checked: I-06 (pre-auth cost is unchanged, because psk2 adds no DH and the responder still does `es` and `ss` before the psk), I-07 (see attack 1), I-22 (no change). Banned list in `agent/core/4-evidence.md`: the change has no code, and no future-work text without a task id.

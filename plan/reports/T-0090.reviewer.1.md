Model of the probe replay window. It lives in scratch and is not committed, since only the report is mine to commit. `window.py` is about 80 lines and was written from the branch text and ARFC 0003 section 3.6. It applies the 5 rounds 200 ms apart (`:92-97`), one check per round (`:242-246`), missed and fails (`:251-257`), and the probe window of `spec/arfc-0003-mesh-wire-protocol.md:573-577`: one counter per session and direction, +1 per sealed probe message, and a message rejected once a counter 2,048 or more above it has been accepted. A sends N probe messages per round back to back, `tx` apart, with the check at index 0. The check's pair has a one-way delay of 20 ms. One other pair, at index j, reaches B with delay `d_f`, and the rest do not arrive. No packet on the working path is lost.

```
$ python -I window.py
4096 pairs, check first, fast pair last: checks rejected 5/5, E fails [12.4]
4096 pairs, check first, fast pair at 2048: checks rejected 5/5, E fails [12.4]
4096 pairs, fast pair 3 ms faster: checks rejected 5/5, E fails [12.4]
4096 pairs, fast pair 1 ms faster: checks rejected 0/5, E fails []
4096 pairs, fast pair at 2047: checks rejected 0/5, E fails []
2048 pairs, check first, fast pair last: checks rejected 0/5, E fails []
4096 pairs, check last: checks rejected 0/5, E fails []
2112 pairs (33x64), check first: checks rejected 5/5, E fails [12.4]
4096 pairs, 100 Mbit/s (116 B per 9.3 us): checks rejected 0/5, E fails []
```

`tx` is 1 us (a 116-byte datagram at about 1 Gbit/s) unless the row says otherwise. The probe set starts at 10 s. A single accepted probe 2,048 or more counters after the check, arriving first, rejects it. The pair only has to beat the working pair by more than the time A takes to send 2,048 probe messages. The ARFC fixes no send order inside a round (`:243-246`).

The echo direction has the same gap, and sending the check last does not close it. B answers the check, then its own signaled probe set (`:310-312`) seals more probe messages under the same counter. `echo_dir.py` applies the same window rule at A:

```
$ python -I echo_dir.py
B pairs 4096, fast pair index 4095, B round 0.5 ms after answer: echo rejected in every round: True
B pairs 4096, fast pair index 2047, B round 0.5 ms after answer: echo rejected in every round: True
B pairs 4096, fast pair index 2046, B round 0.5 ms after answer: echo rejected in every round: False
B pairs 2048, fast pair index 2047, B round 0.5 ms after answer: echo rejected in every round: True
B pairs 4096, fast pair index 4095, B round 15.0 ms after answer: echo rejected in every round: False
```

Both sides' rounds are 200 ms apart, so the offset is the same in every round of the two sets. A bad offset rejects all five echoes. The architect raised this window as a `spec-issue` and counted it under the goal's "overtaken". I do not. In section 8, overtaking means a copy of the same answer accepted first (`:492-495`). Here no copy exists and no packet is lost.

## Summary

Round 2 resolves all ten findings of `plan/reports/T-0088.reviewer.1.md`. The two `block` findings get new mechanisms. A host file in the data directory (ARFC 0017 section 4.2) records every host object Alloy creates, and uninstall and `leave` remove only objects that match it. Reserved names and the default data directory no longer overlap Grafana Alloy's. ARFC 0002 section 3.12 sets owner and access rules for the data directory, and `init`, `join`, and `alloyd` refuse a directory that breaks them.
The eight `fix` findings are resolved in ARFC 0017 clauses 3.13 to 3.17 and ARFC 0002 sections 3.5, 3.8, 3.9, and 3.11. `spec/README.md` is back to main. `cargo xtask ci` passes.

## Changes

- F1 (block), resolved:
  - Reserved units are now `alloyd.service` and `alloyd-*`. User and group names are no longer reserved, and the guest id range replaces them.
  - The Linux default data directory is `/var/lib/alloyd` (ARFC 0002 sections 3.1 and 3.3).
  - Clause 3.17 names the Grafana Alloy objects (`alloy.service`, user and group `alloy`, `/etc/alloy`, `/var/lib/alloy`) as not reserved and never touched. Clause 3.17.6 adds a host snapshot test with those objects present.
  - Clause 3.17.2: Alloy treats a reserved object as its own only while a host file line or a manifest line shows that it created it.
  - Uninstall (clause 3.16) removes only manifest entries, host file objects that still match (boot id on Linux, interface GUID on Windows), and an Alloy data directory. It prints every other object with a reserved name and leaves it in place.
- F2 (block), resolved:
  - New ARFC 0002 section 3.12 defines an Alloy data directory. On Linux: owned by uid 0, mode `0700`, no symbolic link, root-owned ancestors that group and others cannot write. On Windows: owned by `SYSTEM` or `Administrators`, a protected ACL granting only those two, and not a reparse point. On both, a valid host file.
  - On Windows, `init` and `join` never adopt an existing directory, and create the directory with its ACL in the call that creates it.
  - The new `data directory` check fails with exit 5. `alloyd` checks the rules at every start, before it reads any secret.
  - An `icacls` test against an unprivileged user's pre-created `%ProgramData%\Alloy` is stated.
- F3 (fix): clause 3.15 requires that a script runs nothing until it has been read to its end (last line a brace group, or an equivalent), and that a script cut at any byte changes nothing. The same rule binds `install.ps1` under `Invoke-Expression`.
- F4 (fix): clause 3.15 step 6 names each path's temporary names, `.alloy-new` and `.alloy-old`. These are the only unlisted paths the install writes, and every later install and every uninstall removes them (step 4, clause 3.16 step 7, section 6).
- F5 (fix): ARFC 0002 section 3.9: `leave` stops every process of ARFC 0000 section 2.3 and removes the objects in the host file, so `join` after `leave` passes `names`. Section 6 says the same for a failed join attempt.
- F6 (fix): clause 3.13 defines the preview rules:
  - an install refuses to change a joined node's release when either release is a preview (clause 3.15 step 4);
  - an `alloyd` that finds such a mismatch serves nothing and logs it every 60 seconds;
  - a preview cluster changes release only by being created again.
  
  Section 7 points to these rules.
- F7 (fix): ARFC 0002 section 3.5 adds catch-up renewal after sleep. It also adds renewal of an expired record through an anchor's join service, signed by the identity key over the AL-authenticated mesh key, with the single refusal `node_unknown`. It defines retries every 60 seconds, what `node list` and the log show, and recovery by `leave --force` and `join`. Section 3.11 adds a client node bullet.
- F8 (fix): new clause 3.17.7 defines the guest id range: uids and gids 1,900,000,000 to 1,900,065,535, with no `passwd` or `group` entries. The `names` check and every VMM start prove an id is free: no `getent` entry, no `/etc/subuid` or `/etc/subgid` overlap, no process using it.
- F9 (fix): the Wintun driver is a shared object that Alloy never removes (clause 3.17 table, clause 3.17.1, clause 3.16 step 6, the snapshot exception). ADR 0062's consequence now says the same.
- F10 (fix): `spec/README.md` is restored to main's content. The milestone column edits are dropped.

  - Install step 8 warns when another `alloy` executable is on the search path.

## Decisions

- Host object ownership is proven by a write-ahead host file, `<data-dir>/alloy-host` (ARFC 0017 section 4.2), not by name alone. It also holds the local join state and the started release in a format every release shares, so install and uninstall scripts can read them. This adds an on-disk format to an accepted ARFC. The task allocated no ADR for it, so whether it gets one is the lead's call.
- The Linux default data directory changes from `/var/lib/alloy` to `/var/lib/alloyd`, and reserved units from `alloy*` to `alloyd.service` and `alloyd-*`, so that no reserved name overlaps Grafana Alloy.
- VMM identities are numeric ids from a fixed range, 1,900,000,000 to 1,900,065,535, with no `passwd` or `group` entries, checked free at `init`, `join`, and every VMM start. No user or group names are reserved.
- A preview cluster never changes release in place. It is created again (clause 3.13).
- A joined node whose record expired renews through an anchor's join service with its identity and mesh keys. No token is needed, and a deleted node is refused.

T-0052 round 2 findings (`plan/reports/T-0052.reviewer.2.md`), checked against 42ec2d6:

- F1 (fix): partly resolved. "There is no third way" is gone, 3.3 limits its audited-access rule to the API, and the way through a node is stated with its records and the ruling against ARFC 0020. The replacement claims are again exhaustive ("one way ... outside the API") and miss control plane state (F1 here) and the case with no setup call (F2 here).
- F2 (note): resolved. Clause 3.10.7 now names 3.2's default deny for a target in another org, says a cluster role never lifts it, and says cluster-scope targets lie in no org. This follows 3.2's text ("a policy in the target's org") and 3.3. A residue on targets that are orgs is F5 here.

Attacks tried. This is a spec task with no code, so each attack is a scenario traced through the amended clauses.

1. **Tenant data on a control node, with no call.** Root on control node C, which is the local admin's party, reads C's replica of the control plane state: every resource of every org, including instance user data and SSH keys (ARFC 0006 lines 17, 27 to 28; ARFC 0011 lines 17, 134), and decrypts access key secrets with the node key (ARFC 0020 clause 3.7), which ARFC 0007 lines 607 to 612 already say gives C the power of every principal holding an access key, org owners included. No call is made, so no chain records anything and no warning is raised. C need not serve any guest or volume of the org. Lines 102 and 650 say the way through a node serving guests and volumes is the only way outside the API (F1).
2. **Node that already serves the data.** `alloy init` creates the first node with `control`, `compute`, and `storage` (ARFC 0002 line 88), and a single-node cluster is a full cluster (I-16). Root on that node reads every org's guests and volumes as the node serves them (ARFC 0020 clause 3.3), with no `cluster:UpdateNode`, no join token, and no placement call. Nothing is in the cluster chain and no warning is raised. Line 691 says other cloud admins can see that the way was prepared (F2).
3. **Recovered key on a target in another org.** `U` in `O` with `cloud-admin` calls on a project of org P: 3.2 refuses unless P allows `U`; on a node, pool, or org: 3.2 does not apply. The clause now says both. On org P itself, a deny attached to P is neither "the target's org" (P lies in no org by line 441) nor clearly "any other place" (F5).
4. **Storage data through a node.** A storage node serves chunks of objects and registry content as well as volumes (ARFC 0012 lines 10 to 11), and a cloud admin steers which disks hold a PG by disk and pool changes and by marking a disk out (ARFC 0012 clause 3.1.1, line 115). The new paragraph names guests and volumes and cites ARFC 0011 only (F4).

Invariants checked: I-02 (F1, F2), I-15 (no new unaudited API call), I-16 (attack 2), I-22 (no new response carries a secret). ARFC 0020 sections 2.2 and 8 support the ruling that the node ways lie outside the boundary. Banned list: not applicable, no code in the diff.

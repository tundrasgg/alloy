## Summary

Added `.gitattributes` (text as LF) and moved 17 of the 20 CRLF files to LF, in a commit that changes only line endings. Added the `check-repo` rule `line-endings`, with tests. `collect-licenses.sh` now takes reviewed upstream license texts from `packaging/licenses/`. It passes for both release targets, and so does `set-version.sh`.
Three CRLF files are under `tests/conformance/`. A developer may not change that path (`agent/core/4-evidence.md`), and the path lock would reject the change in the PR check and in the push commit check (D-0016). They are still CRLF, so the new rule fails `cargo xtask ci` on them and only on them.

## Changes

- `.gitattributes`: `* text=auto eol=lf`, plus common binary types marked `binary`.
- 17 files under `Cargo.toml`, `crates/`, and `adr/0070-*.md` (commit 8dc03d8 on the branch): line endings only. `git diff --ignore-cr-at-eol` of that commit is empty.
- `xtask/src/tree.rs`: `Tree::has_crlf`. It reads the git index class (`i/crlf`, `i/mixed`) from `git ls-files --eol`. Walked fixtures are judged by content. Unit tests added.
- `xtask/src/rules/line_endings.rs`, `xtask/src/rules/mod.rs`: the rule `line-endings`. A fixture `files` entry can now take a content kind (`crlf`, `mixed`, `binary`), so no CRLF fixture is ever committed.
- `xtask/tests/fixtures/line-endings/{pass,fail}/`: the fixture lists and the expected violations.
- `packaging/licenses/{openraft-0.10.0,openraft-rt-0.10.0,tonic-prost-0.14.9}/`: the upstream license texts, unmodified. Each directory's `SOURCES` gives the file, its git blob id, and its URL at tag `v0.10.0` or `tonic-prost-v0.14.9`. The tags point at the commits in the crates' `.cargo_vcs_info.json` (`git ls-remote`).
- `packaging/collect-licenses.sh`: when a crate has no license file, it copies the reviewed texts as `<crate>-<version>-<file>`. It stops when a text's blob id differs from the one recorded, or when a crate has neither a license file nor reviewed texts.
- `packaging/README.md`: a row for `licenses/`.

## Decisions

- Line endings in `adr/0070-*.md` changed, since the task lists it in `touches`. Its text is unchanged.
- The rule reads the index, not the working tree, so a Windows editor that writes CRLF into a file stored as LF is not a false failure.
- The reviewed texts are checked by git blob id, so anyone can compare them against the upstream tree listing.

## Changes

- F1 `crates/alloy-api/src/transport.rs`: `ConnLimits` gives each limit a number. `API_PORT` allows 1,024 connections, a 10 s handshake, and 60 s idle. `LOCAL_ADMIN` allows 64 connections and 60 s idle. `Slots` counts the open connections.
- F1 `crates/alloy-api/src/server.rs`: when a listener is at `max_connections`, `accept_loop` closes the new connection at once and sends nothing. `serve_h2` drops a connection once no call has been in progress for `idle`. A call counts as in progress from its headers until hyper has sent or dropped its whole response body (`CallBody`). `ApiPort::with_limits` sets the limits for the port, and `serve_local_admin` takes them as an argument.
- F3 `crates/alloy-api/src/service.rs`: `fit` refuses a `GetNode` or `ListNodes` response whose `encoded_len` is over 4 MiB, with `InvalidArgument` and the `alloy-error-bin` trailer. tonic's encode limit stays in place as a backstop.
- F4 `crates/alloy-api/src/server.rs`: `auto_date_header(false)`.
- F5 `crates/alloy-api/src/transport.rs`: `Transport::of(&RuntimeConfig)` returns clear when the `net` binding is `mem` and TLS for any other binding. Callers cannot build a `Transport` any other way. `sniff` reads the HTTP/2 preface (RFC 9113 section 3.4).
- F5 `crates/alloy-api/src/server.rs`, `client.rs`, `io.rs`: `ApiPort::new` and `connect` both take a `Transport`. In the clear, the bytes read to tell the API from `stream` are replayed to whichever one is chosen (`RtIo::with_unread`). `StreamConn` now holds either TLS or clear (`is_tls`).
- `crates/alloy-api/src/lib.rs`: the docs are updated. `ConnLimits` and `Transport` are exported, and `HANDSHAKE_TIMEOUT` is removed because `ConnLimits::handshake` replaces it.
- `crates/alloy-api/src/tests.rs`: new tests cover:
  - the connection bound and idle close;
  - a call in progress keeping its connection open;
  - a response over 4 MiB, for both get and list;
  - no `date` header;
  - in the clear, the API and `stream` told apart by the preface;
  - on TLS, the preface alone getting no API.

## Decisions

- The idle limit counts activity at the call level, not the byte level. A client that keeps sending calls with no credential stays connected. Rate limits (clause 3.9) are what bound that case.
- `stream` connections count toward the API port's `max_connections` from accept until the underlay returns, and the underlay owns their idle limit. The port has only one count for every protocol it serves.
- `Transport` is decided from the `net` binding name in `RuntimeConfig`, because `Runtime` does not record which implementation built it.

## Issues

- `spec-issue`: ARFC 0008 section 7 states no connection count, handshake time, or idle time for the API port or the local admin socket. The numbers in `ConnLimits` (`crates/alloy-api/src/transport.rs`) should be written into the spec, or replaced by numbers the spec chooses.
- `follow-up`: there is no per-source connection bound. One host can take all 1,024 slots by opening a new handshake about every 70 ms (`crates/alloy-api/src/server.rs`, `accept_loop`).
- `follow-up`: h2 0.4.20 calls `std::time::Instant::now` to expire streams the server reset (`src/proto/streams/stream.rs:585`, `recv.rs:1049`). hyper's server builder does not expose `reset_stream_duration`. This can change the server's frames only for a stream it reset less than 30 s earlier.
- `follow-up`: the `mem` `net` serves no stream yet, so the clear path is tested on `os` loopback. A simulator test belongs with T-0077 (`crates/alloy-sim/src/host.rs`).
- `follow-up`: `alloy-rt`'s `Runtime` could record its `net` binding, so that `Transport` cannot be given a configuration other than the one that built the runtime (`crates/alloy-rt/src/runtime.rs`).

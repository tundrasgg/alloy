## Summary

The task's premise is stale. Since D-0017 (T-0046), `check-repo` holds no `std::process` text pattern. Clippy carries the ban, and it already allows `std::process::ExitCode` everywhere: the fixture's `values()` in `crates/demo` lists it as reaching nothing.
So `alloyd` and `alloy` can already return an exit code from `main` (`fn main() -> ExitCode`, `ExitCode::from(u8)`), which is what ARFC 0002 and ARFC 0019 need.
The scope's file-scoped allowance ("`ExitCode` and `std::process::exit` only in the two `main.rs`") cannot be expressed in the current gate. Clippy has one configuration per crate and no per-file setting. The `clippy-forbid` step rejects every source attribute that would lower the lint (E0453).
Done, as the coherent part: Clippy fixtures show a binary's `main` returning `ExitCode` passing both steps, and `std::process::exit`, `abort`, and `id` still rejected in a non-binary crate.
Not done: banning `ExitCode` outside `main.rs`, and allowing `std::process::exit` in `main.rs`. Both need a choice of design (see Question).

## Question

How should the binary crates' exit path be allowed, given that Clippy cannot scope a disallowed path to one file and the `clippy-forbid` step rejects source attributes?

1. (Recommended) Keep the current gate. `ExitCode` stays allowed everywhere: it starts nothing and reads nothing, and it takes effect only as `main`'s return value. `std::process::exit` stays banned everywhere outside `alloy-rt` and `alloy-sim`, binaries included. Binaries return `ExitCode` from `main`, which meets ARFC 0002 and ARFC 0019, and destructors still run. This branch is then complete as it stands.
2. Bin-only packages with a derived config. `alloyd` and `alloy` hold only `src/main.rs`, and their logic moves into library crates (a `plan/workspace.md` change). `crates/alloyd/clippy.toml` and `crates/alloy/clippy.toml` would equal the root config minus `ExitCode` and `exit`. `check-repo` would verify that exact content, and that the package holds no other Rust source, `include!`, or `#[path]`. The root config would ban `ExitCode`. The fixture runner would need nested configs, since it sets `CLIPPY_CONF_DIR`. About 200 lines in `xtask/`, reviewed.
3. A separate Clippy pass over the two bin targets with a derived config. The strict steps exclude `alloyd` and `alloy`. New steps lint their non-bin targets strictly and their bin targets with the derived config. `check-repo` forbids out-of-line `mod`, `include!`, and `#[path]` in those `main.rs`. Packages may keep a `lib.rs`. 300 lines or more, including a rework of the gate steps and the fixture, reviewed.

## Summary

ARFC 0003 section 3.4 now defines a 9-byte transport header (`type`, `receiver_index`, low 32 bits of `counter`) and no inner header. Fixed overhead is 25 bytes: 53 with UDP over IPv4, 73 over IPv6.
A receiver index names the session, the VNI and the sending queue through blocks of 64 indexes per VNI per session. VNI 0's block comes from the handshake `sender_index`. Other VNIs are bound per session by two new control frames.
The full counter is reconstructed from the replay window and is still the whole counter in the nonce. The inner kind is the first nibble of the frame. Fragmentation (3.5), probes (3.6), handover (3.9), failure costs (6) and limits (7) are updated to match. ADR 0058 records the change.

## Changes

- `spec/arfc-0003-mesh-wire-protocol.md`: section 2 says transport packets carry no `version` byte. The 3.1 `Indices` rule makes each `sender_index` reserve a block of 64 values. 3.3 rekeys at 2^30 transport packets per queue instead of 2^48. 3.4 is rewritten: the header, reserved type values, the overhead, blocks and their bounds, counters and the 2^31 cap, the nonce, the reconstruction rule and reorder limit, receive checks, inner kinds by first nibble, the bind request and bind control frames, and session choice. 3.5 is rewritten: payload budget, a 7-byte fragment header, reassembly rules. 3.6 says a probe uses the VNI 0 block base. 3.9 hands over blocks and bindings and frees blocks of consumed sessions. Section 6 adds a transport row and section 7 adds index limits. ADR 0058 is added to `Decisions`.
- `adr/0058-al-transport-packets-carry-25-bytes-of-overhead.md`: new ADR (40 lines).
- `adr/README.md`: ADR 0058 indexed under Mesh.

## Decisions

- N: VNI bindings are per session and fixed for the session's life. The receiver allocates them and the sender learns them from a `bind` (control type 2) sent in answer to a `bind request` (control type 1) on VNI 0. A node binds only a VNI whose VPC has a port on it (ARFC 0009 section 3.3). Why: if a binding outlived its session, or an index were rebound, a stale sender could have its packets delivered into another VPC (I-01).
- N: an index is `base + q` within a block of 64, and the handshake `sender_index` is VNI 0's base. Why: the sender computes every queue's index from one 4-byte value, and the handshake layout does not change.
- N: limits are 1,024 blocks per session (65,536 indexes) and 4 sessions per peer, pending initiations included, for 262,144 indexes per peer. A sender holds up to 16 packets per VNI per peer for 1 second while it waits for a binding. Why: I-21 needs a bound, and rekeys and crossing handshakes need at most 3 sessions.
- N: rekey after 2^30 transport packets per queue (was 2^48), and never use a counter of 2^31 or more. Why: with the cap at 2^31, every packet the window can accept is reconstructed exactly, whatever is lost or reordered.
- N: transport session choice is the newest confirmed session that binds the VNI, and for VNI 0 the newest session when none is confirmed. An initiator seals a keepalive on every session it makes. Why: bindings need a defined session, and without the keepalive a responder may keep sealing under a session whose receive key the initiator drops 10 seconds later.
- N: the kinds are 0 keepalive (exactly `0x00`), 1 control (`0x10`), 2 fragment (`0x20`), 4 IPv4 and 6 IPv6. Keepalives and control frames are carried only on VNI 0. The low nibble of the first byte of kinds 0 to 2 must be zero. Kind 0 stays the keepalive, so ARFC 0004 section 3.4 and ADR 0045 still read correctly.
- N: first byte values 0 and 7 to 255 are reserved, and a later transport version takes a new type value from them.
- Ruling on T-0054's `spec-issue`: the developer's readings were right on all four points. Fragment `index` counts from 0 and is below `count`. A fragment carries IPv4, IPv6 or control, never a keepalive or a fragment, and control only on VNI 0. The fragment `reserved` byte no longer exists, and the first byte's low nibble must be zero. Queue ids run from 0 to `queues` - 1, now through the receiver index.

## Issues

- `follow-up`: `crates/alloy-wire` (T-0054) still encodes the old 16-byte header, the 4-byte inner header and `TRANSPORT_OVERHEAD = 36`, so it now contradicts ARFC 0003 section 3.4. Its build and verify tasks (T-0054, T-0055) need recutting for the new layout and for the control and fragment frames.
- `spec-issue`: `spec/arfc-0009-vpc-networking.md` section 3.5 says the VNI "is read from the authenticated inner frame". It is now the VNI bound to the authenticated `receiver_index` (ARFC 0003 section 3.4). `spec/arfc-0020-security-model.md` section 2.3 ("The VNI in the authenticated AL frame") is still loosely true but should say the same. Both are outside this task's `touches`.
- `follow-up`: under the old rules nothing guaranteed that an initiator uses a new session, so the responder could not confirm it. This change closes that gap with the initiator keepalive in 3.4. Conformance tests for 3.6 session choice should cover it.

## Goal

An anchor's `alloy-link` can accept a handshake from a joiner whose static key it does not know yet, within the rate limits ARFC 0002 states. The node channel can draw request ids from the handshake counter, as ARFC 0002 section 3.13 requires.

## Scope

- Read only ARFC 0002 sections 3.3 and 3.13 and ARFC 0003 sections 3.1 and 3.2, plus the two `follow-up` items about `alloy-link` in T-0111's report.
- An opt-in accept-unknown mode:
  - initiations from static keys that are not peers are accepted at most 10 per second per source and 100 per second in total, as section 3.3 states;
  - the peer is then reported to the caller to admit or drop.
  Everything else about the handshake is unchanged.
- A call that returns the next handshake counter value no initiation has used and marks it used, so request ids and initiations never share a value.
- Tests: unknown initiators accepted and rate-limited at both bounds; counter values never reused across initiations and draws, including across a restart if the counter persists.

## Out of scope

- The node channel itself (`alloyd`).
- Crossed rekeys (T-0116, which also holds `crates/alloy-link/**`; this task starts after T-0116 merges).

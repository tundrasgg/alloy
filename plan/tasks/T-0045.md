## Goal

The three `fix` findings in `plan/reports/T-0022.reviewer.2.md` are resolved in ARFC 0002 and ARFC 0019.

## Scope

- F1: a machine refused with `key_in_use` because of keys it kept itself has a stated command that lets it join, and the refusal names that command.
- F2: a join during the cluster key overlap succeeds when the anchor's current record is signed by either trusted cluster key and every other step 5 check passes.
- F3: every error returned through the local admin socket exits with the code clause 3.1.7 gives its kind.
- API CA key lifetime and rotation (`spec-issue` in `plan/reports/T-0041.architect.1.md`): ARFC 0002 states the API CA key's lifetime, its rotation procedure, and the validity of the certificates it issues, as `agent/eng/crypto.md` rule 7 requires.
- ARFC 0019: the CLI commands root on a control node uses for break-glass administration as ARFC 0007 specifies it after T-0052 (D-0020), next to `sudo alloy login --issue-code`.
- Note F3 in `plan/reports/T-0041.reviewer.1.md`: ARFC 0002 section 2 no longer says the API CA key is the one signing key that is not Ed25519, since API server certificate keys are P-256 too.
- From `plan/reports/T-0052.architect.1.md`: ARFC 0019 clause 3.2.5 lists the `local-admin-used` standing warning and says how it ends; clause 3.1.14 no longer limits the local admin to three commands; ARFC 0002 section 3.9 refuses removing the `control` role from the last control node; the `Decisions` lines of ARFC 0002 and ARFC 0019 name ADR 0055 instead of ADR 0041.
- ADR 0051 is allocated if a fix is a new decision. Clarifications need none.

## Out of scope

- Anything the review did not raise.

## Goal

The Proxmox VE part of the host snapshot drops the timestamps that Proxmox writes into its own status files, as ARFC 0017 clause 3.17.6 requires, so that rung 1 passes when Alloy changed nothing under `/etc/pve`.

## Scope

- Evidence: the rung 1 run of `v0.0.1-preview.2` passed 78 checks and failed 3. All three failures are the `/etc/pve` digest of `/etc/pve/nodes/<node>/lrm_status`, which differed between every pair of snapshots.
  - The lead read the file twice, 12 s apart, on the Proxmox VE 9.1 node. It is JSON, rewritten by Proxmox's HA local resource manager, with a `timestamp` field that advanced (1794559030 to 1794559045) and with its keys in a different order each time:
    `{"mode":"active","state":"wait_for_agent_lock","results":{},"timestamp":1794559030}`
- In the Proxmox section, hash such status files after normalizing them: parse the JSON, drop `timestamp`, and sort keys. Every other file under `/etc/pve` stays a raw SHA-256. Name the files normalized, at least `nodes/*/lrm_status` and `manager_status` if present, and say why in `tests/e2e/README.md`.
- Use only tools present on a stock Proxmox VE host, for example `python3` or `perl`, and fall back to a raw digest with a note when neither exists.

## Out of scope

- Anything outside `tests/e2e/`.

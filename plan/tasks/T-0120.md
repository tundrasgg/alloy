## Goal

`alloy-rt`'s `os` and `alloy-sim`'s `mem` `disk-io` implement the protection operations T-0117 added to ARFC 0005:
- `create_file` and `create_dir_protected` with `Protection`;
- `security`;
- `set_mode`.

`alloyd`, `alloy-id`, and `alloy-state` can then create keys and stores locked down on Linux and Windows.

## Scope

- Read only ARFC 0005 section 2.4, clauses 3.1.10 to 3.1.15, and section 4.1's trace operations 13 to 16.
- `os` on Linux, macOS, and Windows, exactly as clause 3.1.15 states, with each platform's tests.
- `mem` in `alloy-sim`, with trace records.
- Fold findings F7 and F8 of `plan/reports/T-0117.reviewer.2.md` where they bear on the implementation (`NotFound` during the data directory procedure, and `rt_path` under `mem`). If either needs spec text, list it as a `spec-issue` instead.

## Out of scope

- Using the operations in `alloy-id`, `alloy-state`, or `alloyd` (T-0121).

## Acceptance

```
cargo test -p alloy-rt -p alloy-sim --locked   # expected: passes
cargo xtask ci                                 # expected: exits 0
```

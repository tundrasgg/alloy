## Goal

`cargo xtask check-repo` closes the three gaps and the fixture concern in `plan/reports/T-0036.reviewer.1.md`.

## Scope

- F1: the path lock takes the task type from a source the judged branch cannot change, for example the task file as it is on the base ref.
- F2: only test attributes (`#[test]`, `#[cfg(test)]`, `#[<path>::test]`) mark test code. A call such as `checks::test(1)` does not.
- F3: `direct-io` also rejects `from_os_rng`, `ThreadRng`, `tokio::runtime` thread pools, `std::process`, and `tokio::process` outside `alloy-rt` and `alloy-sim`, with a fixture line each.
- F4: the failing `instruction-files` fixture no longer commits vendor instruction files or nested `AGENTS.md` files to the repository. Create them at test time in a temporary directory instead.

## Out of scope

- New rules.

## Acceptance

```
cargo test -p xtask   # expected: passes, with a failing case for each of F1, F2, and F3
git ls-files | grep -i -E "GEMINI.md|\.cursorrules|copilot-instructions|.+/AGENTS.md"   # expected: no output
cargo xtask ci        # expected: exits 0
```

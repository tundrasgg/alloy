## Goal

A user whose only credential was stolen can recover, even as the cluster's only `cloud-admin` and with the 1,000 kept key limit full, and every request that names a deleted access key has one defined outcome.

## Scope

- F2 (`plan/reports/T-0040.reviewer.1.md`): specify a path by which a user with no remaining credential revokes the stolen key's lineage or obtains a key at the limit. One option is a fourth local admin action that revokes a user's keys with `descendants: true`. Check the option against ARFC 0020. A new local admin action changes ADR 0041's decision of exactly three actions, so it needs ADR 0050 superseding ADR 0041; restate ADR 0041's other decisions unchanged in it. If no option keeps ARFC 0020 intact, report `blocked` with one question and its options.
- F1: one outcome for an exchange whose `replaces` names a key that is not kept, and which requests the `NotFound` rule of clause 3.9.11 covers, so that authenticating with a deleted key has one defined error.
- F3 (note): section 7 or 8 states that re-logins through `replaces` with a code issued by the replaced key, or a descendant, consume the limit, and how a user frees it.

## Out of scope

- ARFC 0002 and ARFC 0019, except as a `follow-up` in the report if the CLI needs a new command.

## Acceptance

```
grep -n -i "NotFound" spec/arfc-0007-tenancy-and-iam.md   # expected: one stated scope for the rule
```

The report states, for F1 to F3, the change made and why it resolves the finding.

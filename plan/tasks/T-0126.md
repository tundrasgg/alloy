## Goal

A developer can build M11 rung 2 without inventing anything:
- `alloy init` on a Linux node;
- `alloy join` on a Linux node and a Windows client node;
- `alloy node list` healthy on all three.

The specs say which steps of `init` and `join` rung 2 builds, which wait for a later rung, and how the local admin path learns who is calling.

## Scope

- Read only the named sections, plus T-0111's report Issues, which list the gaps.
- `init` step 3 creates an org, a project, the user `admin`, a pool, and a login code (ARFC 0007, 0012), and none has a store or crate. State which rung 2 creates and which come later. Keep only what `node list` from each machine and the rung 2 check need. If an object is deferred, say what `init` prints in its place, keeping the output true.
- Join tokens: give them a resource kind (ARFC 0006 section 2.6 has none), or state where they are stored.
- Join's reflection step (ARFC 0002 section 3.3 step 3, ARFC 0004 section 3.1.2): rung 2 runs on one LAN with an anchor every node reaches. State whether rung 2 skips it, and what replaces it until rung 3 builds `alloy-relay`.
- Local admin peer credentials (ADR 0055): add to ARFC 0005's `net` seam what the local admin socket needs:
  - Unix domain socket peer credentials on Linux;
  - the Windows equivalent, for example a named pipe's client token, or a stated reason the client node needs none;
  - their `mem` behavior.
  Keep the addition minimal.
- A write-through atomic replace for `disk-io` (rename over an existing file, durable when it returns), with `MoveFileExW` `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH` on Windows, which ARFC 0002 section 3.14 needs and T-0121's report says the seam lacks (T-0106 review F4).
- Record the rung 2 build profile in ADR 0068, so later rungs know what is deferred.

## Out of scope

- Building any of it. Rungs 3 and later beyond naming what they will add.

## Goal

The rules carry the pilot's lean direction (D-0028): larger code tasks behind frozen interfaces, review only where it protects something, and non-blocking findings batched instead of cut as new tasks.

## Scope

- `agent/core/6-pace.md` "Small tasks": a task targets 400 changed lines or fewer, except a `build` or `verify` task against an interface already merged on main, which targets 2,000 changed lines or fewer. One crate and one concern still hold.
- `agent/core/6-pace.md` "One review pass" and `agent/protocol/tasks.md`: one review is required for a `build` or `interface` task, and for a `spec` or `process` task that changes behavior in a security-relevant area (cryptography, authentication, authorization, tenant isolation, a wire or on-disk format). No review for a `spec` clarification, a `research` task, or a `build` task under 100 changed lines confined to `xtask/`, `.github/`, or `fuzz/` whose acceptance the lead has run.
- `agent/protocol/tasks.md` and `agent/roles/lead.md`: `fix` and `note` findings that are not `block` are recorded on the board and folded into the next task that touches the same files; the lead cuts a new task for them only when no such task is coming.
- `agent/protocol/tasks.md` Sizing: match the new targets.

## Out of scope

- Which milestones get spec work (a lead planning decision, D-0028).
- Anything else in `agent/`.

## Acceptance

```
grep -n "2,000" agent/core/6-pace.md agent/protocol/tasks.md   # expected: the larger target in both
grep -n -i "clarification" agent/core/6-pace.md agent/protocol/tasks.md   # expected: no review for a clarification
cargo xtask ci                                                  # expected: exits 0
```

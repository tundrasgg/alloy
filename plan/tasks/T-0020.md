## Goal

ARFC 0011 section 2 states a sandbox for each VMM process that the first `hypervisor` implementation, Cloud Hypervisor, can actually meet. Today it says the seccomp filter allows "only what that guest's devices need", while R-0002 finds Cloud Hypervisor's seccomp filter is built in and fixed, not generated per guest.

## Scope

- Decide how section 2 should read. Candidates include: Alloy applies its own outer per-guest seccomp filter around the VMM process; the requirement becomes a fixed per-VMM-implementation filter plus per-guest Landlock rules; or another option the sources support.
- Address the related gaps R-0002 raises for this section where they change the wording: Landlock rules must be known at start, so hot attach (section 3.1.4) needs pre-declared rules; Landlock does not cover AF_UNIX sockets.
- If the change alters behavior, write ADR 0038 and index it in `adr/README.md`. If it is a clarification only, write no ADR and say why in the report.
- Do not weaken the security model in `spec/arfc-0020-security-model.md`. If every option would, stop and report `blocked` with the question.

## Out of scope

- Implementing any filter.
- Other sections of ARFC 0011.

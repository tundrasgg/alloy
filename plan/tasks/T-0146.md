## Goal

The release workflow builds and publishes `v0.0.1-preview.3` from main, so the M11 rung 2 check can run on the real machines.

## Scope

The run for tag `v0.0.1-preview.3` failed in two places:
- **Linux:** `set-version.sh` reported that `Cargo.toml` has no version line in `[workspace.package]`. The file reached main with CRLF line endings, so the awk section match fails. Twenty tracked files have CRLF (`git ls-files --eol | grep i/crlf`).
  - Add a `.gitattributes` that stores text as LF (`* text=auto eol=lf`, with binary types kept binary), and renormalize every tracked file, in a commit that changes only line endings.
  - Add a `check-repo` rule that fails on any tracked text file with CRLF, with a test.
- **Windows:** `collect-licenses.sh` stopped, because these crates have no license file: `openraft` 0.10.0, `openraft-rt` 0.10.0 (MIT OR Apache-2.0), and `tonic-prost` 0.14.9 (MIT).
  - Give `collect-licenses.sh` a reviewed source for such crates: license texts checked in under `packaging/`, keyed by crate and version, taken unmodified from each crate's upstream repository at the matching tag, with the URL recorded beside each.
  - A crate with neither a license file nor such a text still stops the build.
  - Keep `make-archive.sh`'s listing correct.
- Run `sh packaging/set-version.sh 0.0.1-preview.3` and `sh packaging/collect-licenses.sh` for both targets locally where possible, and report what you could not run.

## Out of scope

- Anything else in the release workflow.

## Acceptance

git ls-files --eol | grep -c "i/crlf"   # expected: 0

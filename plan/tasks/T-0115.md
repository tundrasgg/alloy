## Goal

ARFC 0003 states which session each side sends on and how long each side keeps a previous receive key when two rekey handshakes cross, so that a crossed rekey never blackholes either direction. The stated key lifetimes must still hold.

## Scope

- Read only ARFC 0003 sections 2, 3.1, 3.3, and 3.4, and the review.
- Resolve the spec question behind findings F1 and F2 of `plan/reports/T-0104.reviewer.2.md`:
  - when both nodes start a rekey and both handshakes complete, which session each node sends on;
  - when each node may discard a previous session's receive key;
  - what proves the peer has moved on.

  The rule must hold for every order of arrival of the two responses and the first packets. It must keep the 10 s and 180 s lifetimes (or change them with the reason). WireGuard's rule (a responder does not send on a new session until it receives a packet on it) is one known answer; compare against it.
- A short table of the arrival orders, and the outcome of each under the rule.

## Out of scope

- Anything else in ARFC 0003.

## Goal

M11 rung 1 can be built from the specs: one command installs `alloyd` on a Linux node and the CLI and mesh client on Windows, and one command removes all of it. The specs also say what a Windows client is in the cluster, so rungs 2, 3, and 6 have a place to stand.

## Scope

- Install and uninstall (in ARFC 0017, or wherever the ARFCs hold packaging):
  - What `install.sh` and `install.ps1` do, step by step: platform detection, download from the ADR 0044 release URLs, integrity check, files placed and their paths, the service units (systemd on Linux, a Windows service for the mesh client), and what runs at the end.
  - Uninstall, as a flag of the same scripts or a CLI command: it removes every file, service, interface, route, firewall table, and user the install or the daemon created. It removes node state only when asked, and says so.
  - Re-running an install is safe.
  - Release integrity for preview prereleases (D-0035) must be workable now. If ARFC 0017 clause 3.8 needs a release signing key that does not exist yet, state what a preview release does instead (for example published SHA-256 sums and GitHub artifact attestations), and what the first stable release must add.
- Coexistence (milestone M11 rules), as testable requirements:
  - On a Proxmox VE host, Alloy never changes the host's bridges, firewall, storage, or guests.
  - On any host, Alloy changes only interfaces, routes, firewall tables, and address ranges it created, under names it owns, and never ones that overlap existing use. Running Docker (its nftables or iptables chains) and an existing Tailscale (100.64.0.0/10) are the named cases.
- Windows client node: a node with no roles, running `alloyd` (or a mesh client binary, your choice) as a Windows service, that joins with `alloy join` and appears in the node list. Linux and macOS client machines can be the same kind of node. Say what it may and may not do (no compute, no control, no anchor), how it gets mesh addresses, and how it routes to VPC addresses (the routing itself may be a later rung's spec; name the clause it will go in).
- ADR 0062 for the Wintun license exception (D-0036): the signed DLL, unmodified, in Windows client packages only.
- Keep every changed section consistent with ARFC 0020.

## Out of scope

- VPC routing details, VM networking, and console packaging.

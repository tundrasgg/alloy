## Goal

Two tasks that each add a crate can run in parallel. Today each must list the root `Cargo.toml`, `Cargo.lock`, and `deny.toml` in `touches` (D-0006), so no two crate-adding tasks are ever disjoint.

## Scope

- In `agent/protocol/tasks.md`, name the root `Cargo.toml` workspace member list, the root `deny.toml` allowlist, and `Cargo.lock` as shared files for tasks that add crates or dependencies: a task may add entries and may not remove or reorder existing ones.
- Exclude them from the disjointness check, as the shared index files are.
- Say how the lead resolves conflicts at merge: keep both sides' added entries in sorted order for `Cargo.toml` and `deny.toml`; regenerate `Cargo.lock` with cargo from the merged manifests, then run `cargo xtask ci`. Any other conflict goes back to the task's role.
- Check consistency with `agent/roles/lead.md` and `agent/core/5-delegation.md`; report a `process-issue` if either needs a change.

## Out of scope

- Other shared files.

## Acceptance

```
grep -n "Cargo.lock" agent/protocol/tasks.md   # expected: named as a shared file with its merge rule
cargo xtask ci                                 # expected: exits 0
```

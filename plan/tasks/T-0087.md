## Goal

`product/principles.md` states the pilot's design direction (D-0033) concretely enough that a product, architect, or developer task can check a CLI screen, a console page, or an API call against it.

## Scope

- Terminal UI: beautiful and utilitarian. Say what that means in checkable terms:
  - output layout and alignment;
  - color use, and its fallback when output is not a terminal or `NO_COLOR` is set;
  - progress display;
  - tables and machine-readable output;
  - error layout.
- Web console: beautiful and utilitarian, in the style of Linear, Notion, and Raycast. State the qualities: keyboard-first, a command palette, density, speed, restrained color, and typography. Copy no product's assets or trade dress.
- Native API: as ergonomic as possible. Cover consistent resource naming, verbs, pagination, filtering, errors, idempotency, long-running operations, and client generation.
- Compatibility APIs (S3, EC2 and others): behave exactly as AWS does, extending principle 8. Ergonomics never change compatible behavior.
- Measures for each, added to the measures table where a number fits.

## Out of scope

- Changing any ARFC: spec work for M2 and later is frozen (D-0028). List the spec changes these principles will need in the report's issues.

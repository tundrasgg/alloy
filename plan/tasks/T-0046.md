## Goal

Direct operating system access outside `alloy-rt` and `alloy-sim` is rejected by the compiler's view of resolved paths, so grouped imports, renamed imports, and macro-generated calls cannot slip past, and only test attributes mark test code.

## Scope

- D-0017: a workspace `clippy.toml` with `disallowed-methods` and `disallowed-types` covering every item the `direct-io` rule lists today (time, sockets, filesystem, threads, randomness including `from_os_rng` and `try_from_os_rng`, `tokio::runtime` builders, `std::process` and `tokio::process`). `alloy-rt` and `alloy-sim` opt out with a crate-level `allow` and a comment stating why. `cargo xtask ci`'s clippy step denies these lints.
- Show by fixture or test that a grouped `use std::{process::Command}` call and a `#[tokio::main]` function are rejected outside the two crates. If Clippy cannot see a macro-generated call, keep a narrow text check for `#[tokio::main]` and `#[tokio::test(flavor = "multi_thread")]` and say so.
- Remove the text patterns from `direct-io` that Clippy now covers; keep any it cannot.
- Review F1 in `plan/reports/T-0042.reviewer.1.md`: a test attribute on an item with no body, such as a field or match arm, does not mark the next unrelated body as test code.

- Review F1 in `plan/reports/T-0018.reviewer.1.md`: a `Key:value` trailer with no space after the colon is parsed as a trailer, as git does, so the `trailers` and `task-id` rules see it. Note F2: trailing whitespace on a subject does not hide a trailing period.

## Out of scope

- Other `check-repo` rules.

## Acceptance

```
cargo test -p xtask   # expected: passes, with failing cases for a grouped import, #[tokio::main], try_from_os_rng, and the F1 attribute case
cargo xtask ci        # expected: exits 0
```

## Goal

The binary crates `alloyd` and `alloy` can return an exit code from `main`, as ARFC 0002 and ARFC 0019 require, without weakening the ban on starting processes or reading the environment outside `alloy-rt` and `alloy-sim`.

## Scope

- `check-repo` and the Clippy configuration allow `std::process::ExitCode` (the type and its `From<u8>`), and `std::process::exit`, only in `crates/alloyd/src/main.rs` and `crates/alloy/src/main.rs`. Everything else in `std::process` stays banned everywhere outside `alloy-rt` and `alloy-sim`.
- Fixtures show the allowance, and show a ban still holding in a non-binary crate.

## Out of scope

- Creating the binary crates.

## Acceptance

```
cargo test -p xtask --locked   # expected: passes, including the new fixtures
cargo xtask ci                 # expected: exits 0
```

Board note from T-0042: `check-repo` rejects all of `std::process` outside `alloy-rt` and `alloy-sim`, and the first binary crate needs a narrower pattern. Under 100 changed lines in `xtask/` with lead-run acceptance, no review (T-0073).

## Goal

ARFC 0007 says whether and how a user holds access keys created by `alloy login` with a login code, and whether root on a control node may act as a built-in local admin through the local `alloyd`. Each answer is checked against ARFC 0020 and recorded in ADR 0041.

## Scope

- User access keys: one per computer, named after it, revocable like any access key, created only by exchanging a login code. Specify issuance, naming, revocation, and audit in ARFC 0007 sections 2.2 and 2.3.
- Local admin path: PB-0001 asks that root on a control node act as admin through the local `alloyd`, audit-logged as `root@<node>`, used by `sudo alloy login --issue-code`, `sudo alloy token create`, and `sudo alloy node update`. Decide against ARFC 0020 whether this adds a trusted party. PB-0001 argues root there already holds the cluster key, which ARFC 0020 section 2.2 trusts.
- If either change would weaken the security model in ARFC 0020, do not make it. Report `blocked` with one question and its options, because weakening the security model is pivotal.
- Write ADR 0041 and index it.

## Out of scope

- The login code format itself (T-0022 puts it in ARFC 0002).
- Changes to ARFC 0020.

## Goal

Answer: which `rustls` crypto provider should Alloy use, and which library produces ECDSA P-256 keys and signatures that meet ARFC 0002 section 2 (RFC 6979 deterministic nonces, key generation from the `alloy-rt` randomness trait), for TLS handshakes, the API CA, and ACME CSRs?

## Scope

- For `ring`, `aws-lc-rs`, RustCrypto (`p256`, `ecdsa`, `rustls-rustcrypto` or equivalent), and any other maintained candidate: license, C or assembly build needs, maintenance, audits, RFC 6979 support, whether key generation and signing accept an injected random source, and whether it can sign through a `rustls` `SigningKey` or `CryptoProvider`.
- Whether a split is workable: one provider for TLS record and handshake crypto, another library for P-256 signing behind a custom `SigningKey`.
- Which crate builds and signs X.509 certificates and PKCS#10 CSRs with such a key (for example `rcgen`), and whether it accepts an external signer.
- Cite source lines for every claim about nonce generation or randomness, as the T-0041 review did.

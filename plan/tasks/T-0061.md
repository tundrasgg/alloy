## Goal

Every public decoder in `alloy-wire` has a fuzz target, as `agent/eng/testing.md` requires, and each runs clean.

## Scope

- One target each for `Message::decode`, `InnerFrame::decode`, `InitiationPayload::decode`, and `ResponsePayload::decode`, under `fuzz/`, checking that decoding never panics and that a successful decode re-encodes to the same bytes.
- Use the fuzzing tool `agent/eng/testing.md` names; add it to `deny.toml` if needed, with the license check `agent/eng/deps.md` requires.
- Seed corpora from the valid messages in the crate's tests.

## Out of scope

- Running fuzzers in CI (M1 exit criterion 3 runs them for 10 minutes each; wiring that is a later task).

## Acceptance

```
cargo xtask ci   # expected: exits 0
```

The report quotes a run of each target for at least 60 seconds with no finding, and the command used.

## Notes

Fuzzing needs a Linux or nightly toolchain environment the Windows workspace may lack; if it cannot run here, report `blocked` and the lead runs the targets on the lab machine.

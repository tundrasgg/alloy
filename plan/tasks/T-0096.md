## Goal

The process records and the reading every agent does shrink to what protects an invariant or is read again, following D-0044. Measured by the pilot: today `plan/reports/` holds 171 files and 17,684 lines for about 95 tasks, and most tokens an agent spends go to rereading large files.

## Scope

- Report template and rules (`agent/templates/report.md`, `agent/protocol/messages.md`):
  - A report targets 60 lines or fewer, a reviewer's 100 or fewer.
  - Evidence quotes only the lines that show the result (the final summary line of a test run, the failing line), never whole logs.
  - Changes lists files, not narration.
  - Decisions and Issues are one line each.
- Report lifetime (`agent/protocol/tasks.md`, `agent/roles/lead.md`):
  - When the lead marks a task `done`, it removes that task's reports from the tree in the same commit, unless a task that is not `done` lists one of them in its `reads`. Each such report is removed when the last task reading it is done.
  - Git history keeps every removed report. A task that needs an old report names it as `git show <commit>:<path>` in its notes.
  - Task files stay.
- Reads (`agent/protocol/tasks.md`, `agent/roles/lead.md`, the role files):
  - A `reads` entry for a long file names its sections (`spec/arfc-0005-simulator-and-natlab.md#3.1`).
  - The role reads those sections, plus anything it finds it needs, rather than the whole file.
  - The session start procedure in `agent/ROOT.md` keeps the core files and drops anything a role does not use.
- Research notes for dependencies (`agent/eng/deps.md`, `agent/roles/architect.md`): a new dependency needs its license, maintenance, and tree recorded in the report of the task that adds it, not a separate research note, unless the choice is between alternatives. Also name the ADR 0062 exception next to the ADR 0060 one (T-0088 follow-up).
- Fold the recorded process notes this touches: `agent/protocol/spec-change.md`'s behavior-change row against the lean review rule, and the reviewer role naming interface, spec, and process tasks as review inputs (T-0073 notes on the board), if they fit within `touches`. Otherwise list them as `process-issue`.
- Remove any other rule in the touched files that costs time without protecting an invariant, each named in the report with the reason.

## Out of scope

- `agent/core/` files other than `6-pace.md`, the specs, and the review rules for security-relevant work.

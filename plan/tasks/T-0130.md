## Goal

`alloy-state` stores what rung 2's `init` creates and its API calls read: the `JoinToken` kind, `Organization` and `User` (only the fields ARFC 0002 section 3.15 needs), and the login code records of section 3.7. All go through T-0107's resource API with their checks.

## Scope

- Read only ARFC 0006 sections 2.6 to 2.9, ARFC 0007 sections 2.3 and 2.5, and ARFC 0002 sections 3.2, 3.7, and 3.15.
- The kinds and their field checks. A login code issue records its hash, issuer, and expiry, and an exchange consumes it exactly once (section 3.7). The access key or session it yields is stored as section 3.7 says.
- Fold T-0121 review F2 (a test for the re-read that drops a heartbeat entry when a removal overtook it) and F3 (the unelevated Windows `native` tests return after checking the refusal; make each say so, as T-0128's harness does).
- Tests: create, get, and list for each kind; a login code exchanged once, refused the second time and after expiry; an exchange racing a second exchange.

## Out of scope

- The API methods (T-0131) and `alloyd`.

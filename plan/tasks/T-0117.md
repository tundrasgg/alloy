## Goal

The `disk-io` seam can read and set what ARFC 0002 section 3.12's data directory rules and ARFC 0006's store files need, so that `alloyd` can create its data directory, keys, and stores locked down on Linux and Windows. That covers an entry's owner and mode on Linux, and its owner and access control list on Windows, set at creation.

## Scope

- Read only ARFC 0005 sections 2.4, 3.1.10 to 3.1.13, and 4.2, ARFC 0002 section 3.12, ARFC 0006 section 4.2, and the two reports. Both reports state the gap:
  - T-0106 Issues: the seam cannot read an owner, mode, or ACL, or set one at creation;
  - T-0107 review F4: `redb` files are created with the umask.
- Add the smallest set of `disk-io` operations and `RtPath` metadata that the rules need:
  - for example, `create` options carrying a mode and an owner-only ACL, and a `metadata` result with owner, mode, and reparse or symlink facts;
  - their behavior under `os` on Linux, Windows, and macOS, and under `mem`.
- How a library that opens its own files, as `redb` does, gets the same protection. For example: create the file through the seam first, then let `redb` open it; or create the parent directory with an owner-only mode.
- Keep it an interface change in section 2.4 with clauses in 3.1. The build of `os` and `mem` comes after.

## Out of scope

- Anything not needed by ARFC 0002 section 3.12 or ARFC 0006's store files.

## Acceptance


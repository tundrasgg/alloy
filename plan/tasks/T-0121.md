## Goal

Every secret and store file Alloy writes is created with the protection its spec requires, on Linux and Windows.

## Scope

- Read only ARFC 0002 sections 3.12 and 3.14, ARFC 0006 clause 5.2 and section 4.2, and ARFC 0005 clause 3.1.15.
- `alloy-id`, using T-0120's `disk-io` operations:
  - `DataDir` creates the data directory and every stored file with `Private` or `PrivateRoot` protection;
  - atomic replacement uses the clause 3.1.15 write-through path on Windows.
  This resolves T-0106 review F3 and F4.
- `alloy-state` `native` creates `log.redb` and `state.redb` through `disk-io` with `Private` protection before `redb` opens them (D-0055). This resolves T-0107 review F4.
- Tests that check the resulting mode on Linux and the descriptor on Windows.

## Out of scope

- Anything else in either crate.

## Acceptance

```
cargo test -p alloy-id -p alloy-state --locked   # expected: passes
cargo xtask ci                                   # expected: exits 0
```

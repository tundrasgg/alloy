## Goal

ARFC 0007 makes the local admin (root on a control node, through the root-only local socket) a full break-glass administrator, as the pilot decided (D-0020), so that a cluster whose only admin credential is stolen can always be recovered, and ADR 0055 records it.

## Scope

- The local admin may perform every action a cloud admin may, through the root-only socket, with no deny binding it. Specify how it acts: what it may name and list, how it restores a working administrator (for example create or re-enable a user, grant `cloud-admin`, detach or delete policies, revoke keys, issue a login code), and that every action is audit-logged as `root@<node>` (ARFC 0018).
- A standing warning (ARFC 0019 clause 3.2.5 form) for some stated period after any local admin write, so other administrators see that break-glass was used.
- Rework what the break-glass power makes unnecessary or wrong in ARFC 0007 sections 3.9, 3.10, and 8, including the clause that keeps one enabled `cloud-admin` (clause 3.10.8) and the review findings in `plan/reports/T-0044.reviewer.2.md` (F1 to F4), each resolved or made moot with a stated reason.
- Check against ARFC 0020: state why this adds no trusted party (root on a control node already holds the cluster key), and how it is consistent with I-02 (tenant isolation) given that the local admin belongs to no org.
- Write ADR 0055 superseding ADR 0050, restating ADR 0050's decisions that still hold. Set ADR 0041's and ADR 0050's status lines to `superseded by 0050` and `superseded by 0055` respectively, and mark both rows in `adr/README.md`. This task holds `adr/README.md` exclusively for those row edits.
- If this cannot be done without weakening ARFC 0020, report `blocked` with one question and its options.

## Out of scope

- CLI commands for break-glass (T-0045 adds them after this task).
- ARFC 0020 edits.

## Goal

`alloy-api` reaches TLS only through `alloy-crypto`, as crypto rule 1 requires, and a client with no credential cannot hold API port connections or lock other clients out.

## Scope

- From `plan/reports/T-0109.reviewer.1.md` F2 (D-0052): `rustls`, `tokio-rustls`, and `rustls-webpki` become dependencies of `alloy-crypto` only. `alloy-crypto` exposes the server and client TLS configuration and connection types `alloy-api` needs.
- From `plan/reports/T-0109.reviewer.2.md` F1 (D-0054): rejected calls do not count as activity, an unauthenticated connection is closed after a bounded time and a bounded number of rejected calls, and the connection bound reserves capacity so authenticated clients and the `stream` underlay are not locked out. State each bound and its behavior at the bound (I-21).
- Fold the T-0109 review 1 F6 note: the dependency record per crate.
- Tests: an attack test with many unauthenticated clients repeating rejected calls, while an authenticated client still gets served.

## Out of scope

- New API methods.

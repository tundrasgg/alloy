## Goal

Every commit on `main` follows Conventional Commits 1.0.0. `agent/eng/git.md` states the format exactly, and `agent/protocol/tasks.md` agrees with it.

## Scope

- Replace the "Commits on main" format in `agent/eng/git.md` with Conventional Commits 1.0.0: `<type>(<scope>): <description>`, a body of two to five lines, and footers.
- Fix the allowed types (at least `feat`, `fix`, `docs`, `test`, `refactor`, `perf`, `build`, `ci`, `chore`, `spec`) and say how the scope is chosen (crate name, or the top-level area such as `plan`, `agent`, `adr`, `spec`, `xtask`, `ci`).
- Task ids move from the subject to a `Task: T-NNNN` footer. A paired build and verify squash lists both ids: `Task: T-0042, T-0043`. The `Spec:` footer stays.
- Breaking changes to a frozen interface or format use `!` and a `BREAKING CHANGE:` footer.
- Keep the existing rules: subject 72 characters or fewer, imperative, no trailing period, no tool, vendor, or co-author trailers.
- Update the paired-squash sentence in `agent/protocol/tasks.md` (and anywhere else in the touched files) to the new form.

## Out of scope

- Enforcing the format in `cargo xtask check-repo` or in CI. File a `follow-up` issue in the report if enforcement is worth a task.
- Rewriting existing history on `main`.
- Commits on task branches, which stay free-form.

## Acceptance

```
grep -n "Conventional Commits" agent/eng/git.md     # expected: at least one line
grep -n "Task: T-" agent/eng/git.md                 # expected: at least one line
grep -rn "T-NNNN: <task title>" agent agent/protocol  # expected: no output
```

## Goal

`alloy-crypto` exists as the only crate that depends on cryptographic crates, and offers BLAKE3 content hashing so `alloy-sim` can compute the trace hash ARFC 0005 clause 3.2.5 requires.

## Scope

- New crate `crates/alloy-crypto` with `#![forbid(unsafe_code)]`, depending on `blake3` with the features `agent/eng/crypto.md` and `agent/eng/deps.md` allow (pure Rust if a feature selects it, so the build needs no C or assembly unless the deps rules permit it; say which in the report).
- A minimal hashing interface: a one-shot `hash(&[u8]) -> [u8; 32]`, and an incremental `Hasher` with `update` and `finalize`. Document both. Nothing else; later crypto lands by its own tasks.
- Add `blake3` and its tree to the `deny.toml` allowlist after the license and advisory check (`blake3` is dual or triple licensed; record which license applies).
- Unit tests against the official BLAKE3 test vectors, and a test that the one-shot and incremental forms agree.

## Out of scope

- AEAD, signatures, key exchange.

## Acceptance

```
cargo test -p alloy-crypto   # expected: passes, including official test vectors
cargo deny check             # expected: exits 0
cargo xtask ci               # expected: exits 0
```

## Notes

D-0029: the hashing interface is defined here as a class N decision because no ARFC specifies `alloy-crypto`'s API; ARFC 0005 clause 3.2.5 only requires that the trace hash go through it.

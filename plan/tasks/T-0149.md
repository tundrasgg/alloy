## Goal

On Linux, `alloyd` with `control` creates `/run/alloy` and serves the local admin socket at `/run/alloy/admin.sock`, so `alloy init` reaches its ready step and `alloy login --issue-code` works as root with no context.

## Problem

`admin_dir_ready` in `crates/alloyd/src/lib.rs` calls `RtPath::new("run/alloy")`. An `RtPath` starts with `/`, so that returns `InvalidPath`, and the function returns `false` without a log line. `alloyd` then opens no local admin socket and still logs "serving the API, the local admin socket, and the join service".

On the first rung 2 hardware run (preview.4, Proxmox VE 9 host), `alloy init` exited 6 after 20 seconds: "alloyd started, but node ... was not active with its API answering at 10.0.10.51:443 within 20 seconds." During that window the API answered TLS on 443, `/run/alloy` did not exist, `alloyd` held no Unix listener, and `alloy login --issue-code` as root printed "Not logged in".

## Scope

- Use `/run/alloy` as the `RtPath`.
- Log every path in `admin_dir_ready` that returns `false` on Unix, at warn.
- The start log line names the local admin socket only when it is served.
- A test in `crates/alloyd` that runs the admin directory check against the `mem` `disk-io` rooted at `/` and shows that `/run/alloy` is created `Private` and `admin.sock` may be bound. It must fail on the current code.
- Look in `crates/alloyd/src/` for any other `RtPath::new` literal that lacks its leading `/`, and fix those the same way.

## Out of scope

- The CLI's mapping of every local admin failure to "Not logged in". That's a later task.

## Acceptance

```
cargo test -p alloyd     # expected: the new test passes; it fails with the old literal
cargo xtask ci           # expected: exits 0
```

The lead then reruns `tests/e2e/rung2.ps1` on the hardware.

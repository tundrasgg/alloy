## Goal

`alloyd` can bring up `al0`, the host interface that M11 rung 3's overlay traffic uses, from the specs. On Linux that is a TUN device; on Windows, a Wintun adapter (ADR 0062). Every node and client node can then send IPv6 packets to another node's infrastructure address over the mesh.

## Scope

- Read only ARFC 0005 sections 2.3 and 3.1, ARFC 0002 section 3.4, ARFC 0017 clause 3.17, ARFC 0009 section 2, and ARFC 0003 section 3.4.
- A seam, or an addition to `alloy-rt`'s `net` seam, for a layer 3 virtual interface, with `os` on Linux (TUN) and Windows (Wintun), and `mem`:
  - create it under a reserved name (`al0`);
  - set its MTU;
  - assign the infrastructure address with prefix length 64;
  - add and remove routes through it within ARFC 0017 clause 3.17.3's rules;
  - read and write packets;
  - remove it.
- What `alloyd` does with it in rung 3:
  - which packets enter the mesh, which session and VNI 0 they ride;
  - the MTU from ARFC 0003's overhead;
  - what happens when a peer has no session.
  Name the clause later rungs extend for VPC prefixes on client nodes (ARFC 0009 clause 3.13).
- ADR 0069 records the interface choice.

## Out of scope

- VPC switching, and the path manager (T-0138).

## Goal

Two host snapshots of an idle machine taken seconds apart are equal, as ARFC 0017 clause 3.17.6 requires by removing counters, statistics, and timestamps.

## Scope

- Evidence: on the Proxmox VE node, two snapshots taken 20 s apart differed in one line of `ip -d link show` for the bridge `vmbr0`: `fdb_n_learned 12` became `fdb_n_learned 13`. That is the number of MAC addresses the bridge has learned, and it changes whenever a guest or LAN host sends traffic.
- Drop every value in `ip -d link show` output that the kernel changes during normal operation: at least `fdb_n_learned`, and the timer values (`hello_timer`, `tcn_timer`, `topology_change_timer`, `gc_timer`) when they carry numbers. Keep the configuration attributes.
- Audit every other command of the snapshot for values of the same kind, and list in `tests/e2e/README.md` each value dropped and why.
- Add a self-check mode or a documented command that takes two snapshots a few seconds apart and diffs them, so a stability problem shows before a rung run.

## Out of scope

- Anything outside `tests/e2e/`.

## Acceptance

```
for f in tests/e2e/*.sh; do sh -n "$f" || exit 1; done   # expected: exits 0

```

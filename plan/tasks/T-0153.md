## Goal

`alloyd` on Linux adds the line `run <boot id> /run/alloy` to the host file before it creates `/run/alloy`, as ARFC 0017 section 4.2 says. That way `uninstall.sh --purge` finds the directory and removes it (clause 3.16).

## Problem

Since T-0149, `alloyd` creates `/run/alloy` for the local admin socket. It writes no host file line for it. On the third rung 2 hardware run (preview.5), `uninstall.sh --purge --force` exited 0 on both Linux nodes, but `/run/alloy` remained. `uninstall.sh` removes a `/run` directory only when a `run` line matches it.

## Scope

- Read the boot id, the 36 characters of `/proc/sys/kernel/random/boot_id` without the line feed, through the `disk-io` seam. Add the `run` line through the host file's whole-file replace, before `create_dir_protected`. When the directory exists already with a matching line, add nothing.
- When the creation fails, remove the line, as section 4.2 says.
- Tests on the `mem` seams: the line is written before the directory exists, with the boot id read; a second start adds no second line; a failed creation leaves no line.

## Out of scope

- `link`, `netns`, and `nft` lines. Nothing creates those yet.
- Removing `/run/alloy` when `alloyd` stops. The directory stays until uninstall or reboot.

## Goal

From the `alloy` CLI:
- `alloy init` on a Linux node creates a cluster;
- `alloy join <token>` joins a Linux node or, from an elevated Windows prompt, a client node;
- `alloy login <code>` and, as root on the control node, `alloy login --issue-code` (ARFC 0002 section 3.15);
- `alloy node list` works on all three machines, laid out as ARFC 0019 and `product/principles.md` require.

## Scope

- Read only the named sections, and PB-0001's transcript for wording.
- `init`, `join`, and `login` as ARFC 0002 and 0019 state, through the local `alloyd` interfaces that T-0132 and T-0133 name in their reports. Build only the commands ARFC 0002 section 3.15 lists for rung 2. That covers:
  - the flags and their defaults;
  - the machine checks' output;
  - enabling and starting the service;
  - the printed next step, for example the join token after `init`.
- Contexts and the pinned API CA fingerprint (ARFC 0019 section 2), however rung 2 reaches the API on each machine.
- `node list` through the generated client:
  - the columns and order of ARFC 0019 clause 3.1.15;
  - `--output json`;
  - color and `NO_COLOR` per T12;
  - exit codes per clause 3.1.7.
- Fold T-0091 review findings F2 (a `Try:` line runs as printed) and F3 (control characters in usage errors are escaped).
- Tests: argument parsing for each command, output layout against fixed data, and exit codes.

## Out of scope

- Other nouns and verbs, and the console.

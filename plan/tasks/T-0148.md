## Goal

The command in the header of `rung1.ps1` and `rung2.ps1`, and in `tests/e2e/README.md`, works as written from `cmd.exe`, Windows PowerShell 5.1 and PowerShell 7.

## Problem

Both drivers document `powershell -File tests\e2e\rungN.ps1 ... -LinuxNode a, b`. With `-File`, PowerShell binds each argument as a string and does not parse arrays. `-LinuxNode` gets `a,` and `b` binds by position to `-TimeoutSeconds`, so the run stops with an Int32 conversion error. That happened on the first rung 2 hardware run.

## Scope

- `[CmdletBinding(PositionalBinding = $false)]` on both drivers, so an extra word is a usage error.
- Split every `-LinuxNode` and `-ProxmoxNode` element on commas, trim it, and drop empty pieces before validation. Then `-LinuxNode a,b`, `-LinuxNode a, b` under `-Command`, and `@('a','b')` in-process all give `a` and `b`.
- Change the documented command to `-LinuxNode root@<node-a>,root@<node-b>` (no space), in both headers and the README.

## Out of scope

- Any other behavior of the drivers.

## Acceptance

From Windows PowerShell 5.1, with no machine contacted (a usage error or a parse dump is enough):

```
powershell -NoProfile -File tests\e2e\rung2.ps1 -Version 0 -LinuxNode 'bad host' ; echo $LASTEXITCODE   # expected: 2, usage error
powershell -NoProfile -File tests\e2e\rung2.ps1 -Version 0 -LinuxNode a, b ; echo $LASTEXITCODE        # expected: 2, usage error naming the extra word, not an Int32 error
cargo xtask ci                                                                                          # expected: exits 0
```

The report shows that `-LinuxNode a,b` under `-File` binds two nodes: a script-level debug line or a `-WhatIf`-style dry check is fine.

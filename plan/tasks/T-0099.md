## Goal

`tests/e2e/rung1.ps1` runs its Linux scripts on real nodes from Windows PowerShell 5.1 and PowerShell 7. The first real run failed on both Linux nodes before any install.

## Scope

- `Invoke-RemoteScript` passes each script's text in the SSH command line as base64 inside single quotes. On the first real run, from an elevated Windows PowerShell 5.1 with the Windows OpenSSH client, both nodes failed at the probe with:
  - `bash: -c: line 1: unexpected EOF while looking for matching '''`
  - `bash: -c: line 2: syntax error: unexpected end of file`

  The command line is mangled or truncated on the way. Send the script text on standard input to `sh -s -- <args>` instead, or by another means that does not depend on Windows command-line quoting or length. Still copy nothing to the node.
- Check it locally against any SSH server you can reach, and against `ssh.exe` argument handling on Windows PowerShell 5.1 and PowerShell 7. If you can reach no SSH server, test the quoting with a local stand-in for `ssh` that runs the command through `sh -c`, and say so.
- Make the acceptance forms correct, as T-0093's report noted: a `sh -n` loop over every file, and the PowerShell parse with initialized variables.

- Snapshot noise found by the lead on the Ubuntu node, in a manual install and uninstall of `v0.0.1-preview.1`. The before and after snapshots differ only in:
  - `systemctl list-unit-files` rows `session-143.scope` becoming `session-147.scope` (transient, created by each SSH login);
  - a `home-<user>.mount` row (generated).

  Neither is Alloy's. Drop units whose state is `transient` or `generated` from the snapshot, or from the comparison, and list in the README every other class of state the comparison ignores and why.

## Out of scope

- The install and uninstall scripts (T-0098).

## Acceptance

```
for f in tests/e2e/*.sh; do sh -n "$f" || exit 1; done   # expected: exits 0
cargo xtask ci                                           # expected: exits 0
```

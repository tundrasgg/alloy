## Goal

`alloy-id` holds everything a node needs to have an identity in a cluster. That covers the cluster key, a node's identity and mesh keys, node records, join tokens, the API CA and the API server certificate, infrastructure addresses, and the data directory with its stored files. `alloyd`'s `init` and `join` and the node channel then use it without touching cryptography or the file layout themselves.

## Scope

- Read only these sections:
  - ARFC 0002 sections 2, 3.1, 3.2, 3.4, 3.5, 3.12, and 3.14;
  - ARFC 0008 clause 3.8;
  - `agent/eng/crypto.md`.
- In `alloy-crypto`, the primitives this needs, behind its API:
  - Ed25519 signing and verification;
  - P-256 with RFC 6979 signing, certificate and CSR generation with `rcgen` (ADR 0053);
  - BLAKE3, already present;
  - keys generated from bytes the caller draws from the `alloy-rt` randomness trait.
  Add the crates from the crypto table and their trees to `deny.toml`, and give each license in the report. Fold the T-0085 review notes on the board: take HMAC and HKDF from the `hmac` and `hkdf` crates, or record why not; erase moved-from key copies, or state the limit.
- In `alloy-id`:
  - `cluster_id`, keys, and node records with their signatures and encoding, plus validity;
  - join tokens: encode, decode, the `alyt_` form, and the preset roles;
  - the infrastructure address derivation (section 3.4);
  - the data directory checks and the stored data layout of sections 3.12 and 3.14, including the at-rest key, atomic replacement, and Windows ACLs;
  - the API CA and the API server certificate.
  All file I/O goes through the `alloy-rt` `disk-io` seam.
- The public interface is a class N decision of this task. Document it, and list it in the report.
- Tests: encode and decode round trips; fixed vectors where a standard has them (RFC 8032, RFC 6979); signature checks failing on a single flipped bit; token rejection rules; data directory checks against bad permissions, on Linux and on Windows.

## Out of scope

- The node channel messages (T-0105 and a later build), the CLI, and the API server.

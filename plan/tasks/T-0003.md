## Goal

Answer: should `alloy-sim` build on an existing deterministic runtime or be written in-house, given ARFC 0005's requirements?

## Scope

- Survey the existing Rust options for deterministic simulation of async code (at least `turmoil`, `madsim`, and `shuttle`), with license, maintenance, and how each controls time, scheduling, network, and disk.
- For each, state which requirements of ARFC 0005 sections 3.2 and 3.3 it meets, fails, or cannot be made to meet.
- State what running production `tokio` code under each requires.
- Estimate the surface of an in-house executor that meets the ARFC.

## Out of scope

- Designing `alloy-rt`.
- Simulation in other languages beyond one paragraph of context.

## Goal

`alloy-path` runs the path manager of ARFC 0004 for direct paths as a sans-I/O state machine:
- candidates;
- probe sets;
- checks with verify-before-move (ADR 0063);
- keeping a path, and path MTU.

M11 rung 3 can then report each pair's path as `direct`, and later rungs add relays.

## Scope

- Read only ARFC 0004 sections 2, 3.1, 3.2, 3.4, 3.5, 7, and 8, and ARFC 0003 section 3.6 (probe messages).
- Probe messages (ARFC 0003 section 3.6), sealed and opened with the probe keys `alloy-crypto` already derives. Put them in `alloy-link`, beside the transport it owns, or in `alloy-path` if the spec places them there; say which.
- The direct path rules of sections 3.1 to 3.5 and every section 7 bound, each with a test at the bound (I-21). Relays (`alloy-relay`) and section 3.3's traversal beyond what direct paths on one network need are out.
- Time and randomness come in as inputs, as in `alloy-link`. The public interface is a class N decision of this task; document it for `alloyd`.
- Tests:
  - two path managers driven against each other on a simulated network reach a direct path and report it;
  - loss, reordering, and a moved endpoint behave as section 3.4 says;
  - every check rule of ADR 0063 is exercised.

## Out of scope

- Relays and anchors' relay service, `al0` (T-0137), and `alloyd` wiring.

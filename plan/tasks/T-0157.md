## Goal

The ports check of `alloy init` and `alloy join` (ARFC 0002 section 3.8, as T-0155 amended it) asks the `host` seam's port holders call (built by T-0156) who holds each port. It opens no socket, and a taken port's message names each holder as the section says.

## Problem

`busy_ports` in `crates/alloy/src/setup/probe.rs` binds UDP 7476 on `0.0.0.0` and `[::]`, and for `anchor` or `control` it listens on the API port. On the Windows client the wildcard bind made Windows Firewall write a `Query User` rule for `alloy.exe`. That broke both Windows snapshot checks of the third rung 2 hardware run (T-0154's report has the evidence).

## Scope

- Replace the binds and listens with the port holders call, exactly as section 3.8 now says, including the message for each holder and the limit it states.
- Tests on the `mem` `host`: a free port passes; a held port fails with the section's message and exit code, for one holder and for two; the check makes no `bind_udp` and no `listen` through the `mem` `net`.
- Remove any test in `crates/alloy` that binds a wildcard address on Windows only to drive the ports check.

## Out of scope

- The seam itself (T-0156).

## Acceptance

```
cargo test -p alloy    # expected: the new tests pass
cargo xtask ci         # expected: exits 0
```

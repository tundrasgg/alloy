## Goal

Clause 3.17.6 says which Windows firewall rules the host snapshot leaves out, so a snapshot of a machine that Alloy did not change stays equal while the machine's user answers Windows Firewall prompts for other programs.

## Problem

On the second rung 2 hardware run, the Windows snapshot after uninstall differed from the one before install in 12 rules of `Get-NetFirewallRule`. Each was named `TCP Query User{<guid}<path>` or `UDP Query User{<guid>}<path>`, and each was for a test build of a developer workspace, not an Alloy program. During the run they changed from `Action=Block` to `Action=Allow` with `EdgeTraversalPolicy=DeferToUser`, which is what Windows writes when a user answers its prompt to allow a program. The clause removes only counters, statistics, and timestamps, so it counts that as a difference. The script also already leaves out `Get-Service` `Status`, which the clause doesn't name.

## Scope

- Amend 3.17.6 so the Windows snapshot leaves out every firewall rule that Windows created from a user's answer to its prompt for a program outside the Alloy install directory. Say how a script tells them apart, by the rule's program from `Get-NetFirewallApplicationFilter` and its name form, and why.
- Name the `Get-Service` `Status` exclusion and why, as `host-snapshot.ps1` describes it.
- Keep every equality rule of 3.17.6 as it is.

- The script. T-0151 changes it.

## Goal

Pushing a tag `v0.0.PATCH-preview.N` publishes a GitHub pre-release with every asset ARFC 0017 clause 3.13 lists, and its `install.sh` and `install.ps1` install and uninstall Alloy exactly as clauses 3.14 to 3.17 and section 4.1 state.

## Scope

- `packaging/`: `install.sh` (POSIX `sh`), `install.ps1` (PowerShell 5.1), `uninstall.sh`, `uninstall.ps1`, the systemd unit `alloyd.service`, and the archive layout of clause 3.13. Every step, flag, exit code, path, and message of clauses 3.15 and 3.16, and the manifest of section 4.1. The digests are written into the scripts at release time, so the scripts hold a placeholder that the workflow replaces. A script with an unreplaced placeholder refuses to run.
- `.github/workflows/release.yml`, triggered by a tag push matching `v*`:
  - Build `alloy` and `alloyd` for `linux-x86_64` and `windows-x86_64` at least. The Linux build must run on Ubuntu 22.04 and later and on Debian 13 (a static `musl` build is one way).
  - Fetch the signed Wintun DLL for the archive's architecture and its license from the Wintun project, checked against a SHA-256 pinned in the workflow (ADR 0062).
  - Assemble the archives, write the digests into the scripts, write `SHA256SUMS`, and attest every asset with GitHub artifact attestations.
  - Publish the release as a pre-release when the version is a preview.
  - Set the binaries' version to the tag's version.
  - Pin every action to a commit SHA, as `ci.yml` does, and give the workflow only the permissions it needs.
- Shell and PowerShell checks that run anywhere: `sh -n` and `shellcheck` where available for the `sh` scripts, and the PowerShell parser for the `.ps1` scripts. Put them in a script under `packaging/` and quote their output in the report.
- A dry run of the install and uninstall scripts against locally built archives. Make it possible to point the scripts at a local directory instead of the release URL, through an environment variable that is documented as test-only, and quote a run on this host.

## Out of scope

- Publishing a release (the lead pushes the tag), macOS archives, and the release key of clause 3.14.

## Acceptance

```
actionlint .github/workflows/release.yml   # expected: exits 0 (official rhysd/actionlint; if it cannot run, report it and the lead runs it)
sh packaging/check.sh                      # expected: every script parses and passes its checks
cargo xtask ci                             # expected: exits 0
```

## Notes

The install scripts are the first thing a user runs as root, so this task gets a review. The lead tags the first preview and runs the rung 1 check on real machines.

## Goal

The `host` seam (ARFC 0005 clause 3.1.18) has a read-only call that returns the holders of a local TCP or UDP port. With it, the ports check of ARFC 0002 section 3.8 opens no socket, and it names the process and pid holding a port, as its table row already requires.

## Problem

The ports check binds UDP 7476 on `0.0.0.0` and `[::]`, and for `anchor` or `control` it listens on the API port. On Windows, the wildcard bind from the interactive, elevated `alloy.exe` makes Windows Firewall raise its prompt and write a `Query User` rule for `alloy.exe`. That rule broke both Windows snapshot checks of rung 2 (ARFC 0017 clause 3.17.6), and ARFC 0017 clause 3.17 lets Alloy make no Windows Firewall rule. T-0154's report shows that the current seams have no correct way to check without a wildcard bind: a loopback bind succeeds while the same account holds the wildcard. The check also never names the holder, which section 3.8 asks for.

## Scope

- Specify a `host` call, for example `port_holders(protocol, port)`. It returns the local holders of that port on every address and family, each with its local address and, where the platform reports them, its pid and process name. Specify its errors in the seam's error set, how `mem` answers it, and its `os` sources: Linux `/proc/net/{tcp,tcp6,udp,udp6}` with inodes mapped to `/proc/<pid>/fd` and `/proc/<pid>/comm`; Windows `GetExtendedTcpTable` and `GetExtendedUdpTable` with owner pids, and the image name where it can be read. TCP counts only listening sockets.
- Change the ports check of section 3.8 to use that call on every platform, with no bind and no listen, and say how the message names a holder.
- Keep the seam count, and keep `host` out of `Runtime` (clause 3.1.18).

## Out of scope

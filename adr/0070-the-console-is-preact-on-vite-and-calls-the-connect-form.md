# ADR 0070: The console is Preact on Vite and calls the Connect form

- Status: accepted
- Subject: api
- Specs: arfc-0019, arfc-0008, arfc-0007

## Context

ADR 0002 fixed TypeScript for the console. D-0066 picked Vite and Preact and a hand-written design system, so T-0140 could start. ARFC 0019 section 7 bounds the initial load at 300 KiB compressed, and ARFC 0008 had no form a browser can call. R-0007 found that native gRPC cannot be called from `fetch`, that protobuf-es with Connect-ES is the only maintained client with server streaming and typed error details, and left the server's browser protocol to this task: Connect (option A) or gRPC-Web (option B). Nothing checks npm packages: `cargo deny` sees only Cargo.

## Decision

- The console is TypeScript in strict mode, built by Vite, rendered by Preact, under `ui/console/`. It has no CSS framework, no component library, no font file, and no icon font. Its styles are one hand-written set of tokens with a light and a dark theme.
- Its runtime dependencies are exactly `preact`, `@bufbuild/protobuf`, `@connectrpc/connect`, and `@connectrpc/connect-web`. Another needs a new ADR. Build and test tools are dev dependencies and pass `agent/eng/deps.md`, npm packages.
- Its API client is generated by `protoc-gen-es` from `proto/` and calls the Connect form of ARFC 0008 clause 3.14 through `createConnectTransport`. The Connect form is also the JSON over HTTP form, so one form serves the browser and `curl` (rule A20).
- The server keeps `tonic` over `prost` for gRPC (ARFC 0008 clause 3.10). `alloy-api` serves the Connect form over the same `prost` messages. Which crate supplies the JSON mapping is a dependency choice for the task that builds it.
- `cargo xtask console` runs, in order, and fails on the first failure: `npm ci --ignore-scripts` from the committed `package-lock.json`; the npm rules of `agent/eng/deps.md` over every package in the lockfile; regeneration of the client, failing on any difference from the committed one; `tsc --noEmit`; the tests; `vite build` into `ui/console/dist/`; and the size check, which gzips at level 9 the index document and every script and stylesheet it loads before the first screen renders, and fails when they sum to more than 307,200 bytes (300 KiB). It prints that sum.
- The console's speed rules are ARFC 0019 clause 3.2.13: a loaded screen renders in under 100 ms, the palette takes the first keystroke with no request, and later screens load as separate chunks that the size check does not count.
- `cargo xtask ci` runs `cargo xtask console` from the task that embeds `ui/console/dist/` in `alloyd` (ARFC 0019 clause 3.2.6), and from then on.
- The console's page script never holds a session token. At a public name the token is the `HttpOnly` cookie of ARFC 0008 clause 3.14.6. Through the bridge the bridge holds the token, and the browser holds a bridge credential that is sent as a header, not a cookie, since cookies are not separated by port. Its launch secret reaches the browser through a launch file readable only by the user, never a process argument (ARFC 0019 clause 3.1.16).
- Session tokens form sessions that are refreshed and revoked through the API (ARFC 0007 section 3.12). A refresh reads committed revocation state, a revoked session record lives as long as any token of its session can, and a user or a local admin ends every session of a user at once (ARFC 0007 clause 3.12.6). The console's live state comes from Watch streams that resume on any control node (ARFC 0008 clause 3.15).

## Consequences

- Every change to `ui/console/` or `proto/` needs Node.js and npm on the build machine.
- An npm package with a required install script cannot be used without an ADR, since the install runs with no scripts.
- The Connect form is written in `alloy-api` against a public protocol, not taken from `connect-rust`, so `prost` stays the one Protocol Buffers stack on the Rust side.

## Alternatives rejected

- gRPC-Web through `tonic-web` (R-0007 option B): a second JSON form would still be needed for rule A20, and gRPC-Web has no GET for reads.
- `connect-rust` on the server (R-0007 option A as written): pre-1.0, and built on `buffa`, a second Protocol Buffers stack beside the standing `prost`.
- React: D-0066 chose Preact over it to keep the initial load small.
- A bridge cookie: two bridges on `127.0.0.1` would overwrite each other's, and every server on another port of `127.0.0.1` would receive it (RFC 6265 section 8.5).
- A CSS framework or component library: more bytes, and a look traceable to others (product principles, Web console).
